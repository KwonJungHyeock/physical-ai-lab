## 1. 연결 방식: Wi-Fi 유지 + LAN · 시리얼 (작은 것부터, 끝내 태블릿까지)

배경: 교육 현장에서는 LAN 포트 연결이나 시리얼 통신을 쓰고, 태블릿도 Wi-Fi 보다 시리얼을 씀.

1. **LAN 직결 모드**: 연결 창에 [유선(LAN) 직결] (주소 `192.168.127.10:8080` 미리 채움),
   PC · 태블릿 고정 IP(192.168.127.x) 설정 매뉴얼. 공유기 경유 유선은 이미 됨 (서버가 0.0.0.0:8080). 실물 1회 확인.
2. **USB 케이블 연결**: 로봇 보드 USB-C 를 "USB 네트워크"로 쓸 수 있는지 실물 확인 →
   되면 PC · 태블릿(갤럭시 탭)이 지금 웹 화면 그대로 케이블 한 줄로 연결.
3. **진짜 시리얼**: PC 는 브라우저 시리얼 (코드 `web-typescript/src/engine/serial/` 은 280 AR 용, 화면 미연결).
   280 RDK X5 에서 팔 명령을 받는 단자 실물 확인 필요 (팔 제어기는 보드 안쪽 `/dev/ttyS1`).
   태블릿은 웹으로 불가(안드로이드 크롬 USB 시리얼 없음, 아이패드 USB 막힘) → 지금 화면을 감싼 안드로이드 앱 + USB 시리얼.

## 2. 앞선 작업에서 남은 것

- 카드 모드(AIDT)를 바이오 ②③ · 다른 현장으로 넓히기 (바이오 ① 시범 완료: `2a38ea3` · `c208ca6`).
- 비교 카드 표의 "처음" 칸 실패 문장이 길어 세 줄로 꺾임 → 표에서는 짧게 (예: "쏟아짐 (31.1°)").
- `release` 브랜치 테스트 파일(시뮬레이터 zip · USB 키트) 다시 만들기 — 카드 모드 · 태블릿 대응 반영.

## 3. 레인보우 RB 식 티칭 기능 (조사 · 보완해서 우리 툴에 맞게)

출처: 레인보우로보틱스 Rainbow-RB 실습 교육에서 본 기능. 만들기 전에 RB 매뉴얼(Make · Play 메뉴, MoveJ/MoveL,
포인트 티칭, 프로젝트 저장)과 myCobot 280 RDK X5 에서 되는 것(pymycobot `send_angles` = J, `send_coords` mode 0/1 = 각도 보간/직선)을 조사해 맞춘다.

1. **J 이동 · L 이동 모드**: 곡선 · 자율 이동은 J(관절 보간), 용접 · 특수 목적은 L(직선 보간).
   모드별로 작업할 수 있게 (조그 · 포인트 이동 · 프로그램 줄마다 J/L 선택, 3D 에 두 경로 모양 비교).
2. **BEGIN–END 공정 짜기 창**: [포인트] · [MOVE] 를 눌러 줄을 추가 → 그 줄에서 로봇팔을 움직이고 [좌표 저장] →
   순서를 만든 뒤 [실행] (시뮬레이션 → 실물). 말 그대로 공정 짜보기.
   만든 공정을 **프리셋**으로, **프로젝트 파일**로 저장 · 불러오기.
   (지금 있는 것과 겹침 확인: 자세 저장 · 불러오기, 블록 코딩의 자세 블록, 프로그램 자동 저장)
3. **Smooth 방식 · Tick 방식 (일반 자율 제어)**: 이름은 로봇 제어에서 흔히 쓰는 말로 맞춘다.
   조사해서 정할 것 — 지금 짐작하는 뜻 두 가지:
   - 경로 실행: Smooth = 포인트 사이를 멈추지 않고 이어 가는 연속 경로(블렌딩 · 블렌드 반경, ABB zone / KUKA 근사 위치 결정),
     Tick = 포인트마다 정확히 멈추고 가는 방식(정지점 · fine) 또는 한 줄씩 실행(스텝 실행).
   - 조그: Smooth = 누르는 동안 연속 이동(지금 있음), Tick = 한 번 누를 때 정해진 칸만큼(인칭 · 증분 조그, 지금 0.5 · 1 · 5 · 10° 있음).
   RB 에서 이 두 이름이 어디에(공정 실행 · 조그) 쓰이는지 확인 후 J/L 모드 · BEGIN–END 창과 함께 설계.

## 4. 플랫폼 방향: 스마트팩토리 교육과정 (제조 AI · 다크팩토리)

피드백: 3D 가상환경에서 여러 스마트팩토리 환경(식품공장 · 제지공장 등)을 시뮬레이션해 교육과정으로 만든다.
전북 피지컬 AI 의 핵심 주제는 **제조 AI** — 기존 공장에 AI · 로봇을 적용해 **다크팩토리**(무인 공장)로 바꾸는 것.
이 관점으로 커리큘럼을 짠다.

1. **지금 만든 것 백업**: 바꾸기 전에 git 태그(예: `backup-before-factory`) + release 브랜치에 그대로 남김.
2. **잠금 정리**: 스마트팩토리만 열고 나머지 현장(물류 · 바이오 · 스마트팜 · 카페 · AI 연구소 · 시티 등)은
   "준비 중"으로 잠가 개발 여지를 남김 (지운 게 아니라 잠금: 교사 [모든 현장 열기]로는 볼 수 있게 할지 결정).
3. **스마트팩토리 공정 실습**: 다양한 현장 묘사(식품공장 · 제지공장 등)로 공정 실습. 기존 공장에 로봇 · AI 를 하나씩
   들여 사람 손을 줄여 가는 흐름(수작업 → 로봇 1대 → 비전 · AI → 다크팩토리).
   §3 의 J/L 이동 · BEGIN–END 공정 짜기 · Smooth/Tick 을 이 실습의 도구로 쓰면 맞물림.
   - **먼저 자료조사 → 카테고리화 → 묘사 순서 정하기 → 차례로 제작**: 실제 피지컬 AI 대상 현장
     (전북 피지컬 AI 사업 대상 업종 · 기업 포함)과 스마트팩토리 현장(식품 · 제지 · 자동차 부품 · 금속 가공 ·
     화학 · 전자 조립 등)을 조사해 공정 유형(이송 · 조립 · 검사 · 포장 · 팔레타이징 · 용접 등)과 업종으로 나누고,
     교육 효과 · 제작 난이도 · 지역 연관성으로 묘사 순서를 정한다. 조사 결과는 `docs/reports/research/` 보고서로.
   - **기존 모델링 백업**: 지금까지 만든 3D 모델 · 현장 장면(산업단지 맵, 현장 7곳 셀, 소품 GLB 등)은 지우지 않고
     따로 모아(예: `web-typescript/public/education/archive/` + 쓰던 코드 위치 목록) 나중에 꺼내 쓰게 한다.
