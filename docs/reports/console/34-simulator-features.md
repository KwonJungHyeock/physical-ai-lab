# 보고 #34 — 시뮬레이터 기능 정리 · 공정 짜기(간소화) 추가

시뮬레이터 화면(`/console`)에 지금 있는 기능을 한곳에 모았습니다.
같은 일을 하는 버튼이 여러 곳에 있는지, 숨겨 둔 기능이 무엇인지도 함께 적었습니다.
이번에 다섯 번째 탭 **공정 짜기**를 더했습니다. PLC 연동은 하지 않은 간소화 버전입니다.

## 1. 화면 구성

| 자리 | 들어 있는 것 |
| --- | --- |
| 위 막대 | 화면 탭 **교육 · 시뮬레이터 · 라이브러리 · 자료실**, 지금 과제 칩(공정 짜기 탭에서는 공정 이름 · 줄 수), 로봇 연결, 도움말, 설정(⚙), 로봇 정지(실물 연결 때) |
| 3D 화면 | 로봇 · 실습 환경, 모니터(관절 · 손끝 · 그래프 · 부하), 알림 카드, 실행 뒤 결과 카드 · 다시 보기 막대, 시점 도구(보기 큐브 · 확대 · 화면 저장 · 카메라) |

### 오른쪽 패널 탭

탭은 두 묶음으로 나뉩니다. **공정 · 티칭**(수동 제어 · 공정 짜기)은 팔을 움직이고 점을 찍는 쪽, **코딩**(블록 · Python · ROS 2)은 프로그램을 쓰는 쪽입니다.
공정 쪽 버튼은 [공정 예제] · [공정 파일 열기 · 저장] · [새 공정], 코딩 쪽은 [예제 코드 처음으로] 처럼 이름으로 구별합니다.

| 탭 | 단계 | 하는 일 |
| --- | --- | --- |
| 수동 제어 | 조그 | **좌표 조그(기본)**: 위치 X·Y·Z + 회전 RX·RY·RZ, 관절 조그 J1~J6, 도구 · 액세서리, 자세 저장 · 불러오기, 기본 자세 · 일자로 펴기 · 정지 |
| **공정 짜기** (새로) | 티칭 | BEGIN–END 줄 목록으로 공정을 만들고 실행. 아래 3장 |
| 블록 코딩 | 초급 | 블록 ↔ 파이썬 한 프로그램. 실습 과제 카드 |
| Python | 중급 | pymycobot 파이썬(브라우저 안 Pyodide) |
| ROS 2 | 고급 | rclpy 노드 · 토픽 그래프 |

블록 · Python · ROS 2 아래의 실행 막대(▶ 시뮬레이션 · 배속 · 로봇 실행/코드 받기 · ■)는 공정 짜기에서도 같습니다.
**시뮬레이션을 통과해야 로봇 실행이 열리는** 규칙도 그대로입니다.

## 2. 세 언어와 공정 짜기의 관계

| | 블록 코딩 | Python · ROS 2 | 공정 짜기 |
| --- | --- | --- | --- |
| 만드는 법 | 블록 쌓기(= 정해진 파이썬 문장) | 코드 직접 쓰기 | 팔을 움직이고 [좌표 저장] |
| 이동 종류 | 자동(내려가기 · 올라가기만 직선) | `send_angles` · `send_coords`(관절 이동) | 줄마다 **MOVE J** / **MOVE L** 직접 고름 |
| 점 사이 | 매번 멈춤 | 명령 시각대로 | **Tick**(점마다 멈춤) / **Smooth**(이어서 지나감) |
| 저장 | 자동 저장(브라우저) | 자동 저장(브라우저) | 자동 저장 + **공정 파일(.pal)** |
| 실물 실행 | 시뮬레이션이 계산한 관절 각도를 보냄 | 같은 시각에 다시 보냄 | 시뮬레이션이 계산한 각도를 순서대로(Smooth 는 지나가는 점) |
| 코드 받기 | pymycobot 파이썬 | 그 코드 그대로 | pymycobot 파이썬(줄마다 공정 줄을 주석으로) |

## 3. 공정 짜기 (간소화 버전)

레인보우로보틱스 RB 펜던트에서 하는 BEGIN–END 프로그램 짜기를 우리 툴에 맞게 줄였습니다.

- **줄 추가**: [＋ MOVE J] · [＋ MOVE L] 을 누르면 **지금 팔 자세가 점(P1, P2…)** 이 됩니다. 그리퍼(그리퍼를 끼웠을 때) · 대기 줄도 넣습니다.
- **줄 고르기**: 줄을 누르면 [좌표 저장](지금 자세로 다시) · [가 보기] · [J/L 로 바꾸기] · [▶ 이 줄](한 줄만 실행) · ↑ ↓ · ✕ 가 나옵니다.
- **MOVE J**: 모든 관절이 같이 돌아 손끝이 곡선으로 갑니다(빠름, 일반 이동).
- **MOVE L**: 손끝이 직선으로 가고, 도구 방향은 두 점 사이에서 고르게 돌아갑니다(용접 · 끼우기). 가는 길에 팔 자세가 뒤집히면 그 줄에서 멈추고 "MOVE J 로 바꾸거나 점을 하나 더" 라고 알려 줍니다.
- **Tick / Smooth**: Tick 은 점마다 멈춥니다(정지점). Smooth 는 이어진 MOVE 줄의 점을 멈추지 않고 둥글게 지나갑니다(블렌딩: 점 앞뒤 관절 12° 구간을 둥글게). 실물에는 지나가는 점을 "가까이 오면 다음으로" 신호(`via`)로 보냅니다.
- **실행 전 점검**: 좌표가 없는 점, 관절 범위 밖 점, 그리퍼 없이 그리퍼 줄, 대기 0초를 **실행 전에** 줄 번호와 함께 막습니다. 자기 충돌 · 책상 충돌은 다른 탭과 같은 사전 점검을 거칩니다.
- **공정 예제**: 집어서 옮기기(J 로 위까지, L 로 내려가기), 네모 그리기(L 네 변, Smooth 로 보면 차이가 잘 보임).
- **공정 파일 `.pal`**: [공정 파일 저장] · [공정 파일 열기]. JSON 한 파일(이름 · Tick/Smooth · 속도 · 줄). 다른 PC · 태블릿에서 그대로 열립니다. 모양이 틀린 파일은 반만 읽지 않고 이유와 함께 거절합니다.

### PLC 없이 줄인 것 (다음에 필요하면)

| --- | --- |
| PLC · 센서 입출력(신호 기다리기, 신호 내보내기) | 없음. 나중에 `신호 대기` · `신호 켜기` 줄로 더할 자리만 둠 |
| 조건 · 반복 · 변수 | 없음(블록 코딩에 반복이 있음) |

| 사용자 좌표계 · 도구 좌표계 바꾸기 | 로봇 바닥 기준 하나, 도구 길이는 끼운 도구로 자동 |

### 좌표 조그: 위치 + 회전 (기본)

산업용 펜던트(UR · 두산 · 레인보우 RB 등)는 **베이스(또는 툴) 좌표**에서 손끝을 **X · Y · Z 로 옮기고 RX · RY · RZ 로 돌리는** 조그가 기본이고, 관절 조그는 따로 고릅니다.
공정을 짤 때 점을 맞추기도 이쪽이 쉬워 기본으로 바꿨습니다.

- 위치 X · Y · Z: 도구 방향은 그대로 손끝을 곧게(한 번에 1 · 5 · 10 · 20 mm).
- 회전 RX · RY · RZ: 손끝 자리는 그대로 도구만 베이스 축 둘레로(같은 칩에 1 · 2 · 5 · 10°). 시험: 10° 돌려도 손끝 0.5 mm 안.
- 실물: 로봇 자체 좌표 조그(pymycobot `jog_coord` 4~6)를 씀. 로봇 서버가 rx · ry · rz 를 받도록 고침. 실물 확인은 아직.
- 용어: "작업반경"은 팔이 닿는 범위를 말하므로, 이 조그 이름은 **위치 / 회전**으로 씁니다.

## 5. 확인한 것

- `npm run check:process`: MOVE L 은 직선에서 0.5 mm 안, 같은 두 점의 MOVE J 는 약 23 mm 휘어짐. Smooth 는 네모 그리기 10.4 초로 점에서 멈추지 않음, Tick 은 16.8 초에 점마다 멈춤. 예제 2개 실행, 실행 전 점검, 불가능한 MOVE L 거절, 파일 저장 · 불러오기 · 거절.
- 브라우저: 공정 짜기 탭, 공정 예제 열기, 시뮬레이션 통과 후 [코드 받기] 열림, 3D 궤적(모서리가 둥근 네모), 그리퍼 없을 때 줄 표시와 안내.
- 실물 로봇 실행은 아직 해 보지 않았습니다(시뮬레이션이 계산한 각도를 보내는 방식은 다른 탭과 같음).
