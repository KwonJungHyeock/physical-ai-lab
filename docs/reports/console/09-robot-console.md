[보고 #9] 로봇 연결 콘솔 — 검수항목 7종 실습, 테마 2개, 제어판, 실제 카메라

■ 요약
 - 로봇(RDK X5) 안에서 서버를 켜고, PC 브라우저로 콘솔을 열어 실제 로봇을 움직이는 구성 완성
   (robot-python/server, manuals/robot-arm/robot-console.md)
 - 로봇 화면에서 콘솔을 열면 느린 문제 → 로봇은 서버만, 3D·시뮬레이션·영상처리는 PC 가 계산
 - 제안서 "검수 대응 — 규격서 검수항목 7종" 을 AI 키트 테마의 실습 7개로 구성
 - 테마 2개: AI 키트 / 로봇팔 단독 (키트 없이 책상 위 작업 매트)
 - 제어판: 관절 ±, 도구 끝 X·Y·Z ±, 기본 자세·0° 자세, 손으로 움직이기, 영점 맞추기
 - 실제 키트 카메라: 영상·영상처리 화면, 실제 블록 위치를 시뮬레이터로 가져오기,
   로봇 안에서 색 인식 실행(검수 6)
 - 자동 검사 추가: 모든 실습의 예제 프로그램이 시뮬레이터에서 목표 달성 (npm run check:practice)

■ 로봇 화면에서 느렸던 이유와 구성
 - 콘솔은 3D 렌더링, 매 프레임 충돌 검사, 카메라 화면 생성·영상처리를 브라우저에서 계산.
   RDK X5 의 화면·브라우저로는 수업이 안 될 만큼 느림
 - 구성: 로봇 = server.py (화면 파일 제공 + 로봇 제어 + 카메라), PC = 브라우저 (계산 전부)
   주소 http://<로봇 IP>:8080/console. 학생 PC 사양만 맞으면 로봇 수와 관계없이 같은 속도
 - 추가로 카메라 화면은 장면이 바뀔 때만 다시 그리게 바꿔 PC 부담도 줄임 (전에는 0.2초마다)
 - 파이어폭스에서 로봇 모델이 안 뜨던 문제: 공식 URDF 첫 줄의 XML 1.1 선언을 파이어폭스가 거부
   → 읽기 전에 선언을 빼고 1.0 으로 읽음 (내용은 1.0 범위)

■ "연결됐는지 모르겠고, 실행해도 안 움직임" 대응
 - 맨 위 주황 줄: 실제/데모, 연결 여부(마지막으로 각도를 읽은 지 2초 이내), J1~J6 실제 각도,
   실행 단계, 마지막 오류
 - [연결 확인]: 6번 관절 15° 왕복 → 실제로 움직이면 연결 확실
 - 서버 터미널: 시작할 때 각도 읽기 결과, 명령마다 한 줄 기록 (send_angles 응답 포함)
 - 흡착 펌프가 들어간 프로그램은 전에는 거절만 했음 (당시 스크린샷의 프로그램이 이 경우)
   → 이제 "펌프 동작은 빼고 움직임만 실행할까요?" 로 묻고 실행

 - 자유 실습도 남겨 둠 (도구별 기존 미션)

■ 로봇팔 단독 테마
 - 키트 없이 책상 위 작업 매트: 10mm 격자, 블록 시작 칸 4개, 놓을 자리 1~4
 - 카메라가 없으므로 블록은 이름으로: robot.move_above("빨강 블록"), robot.move_down("자리 1")
 - 실습: 전 축 구동, 반복 위치제어, 드래그 티칭(자세 3개 기록 → go_pose), 블록 옮기기(4개),
   엔드이펙터 교체, 펜 드로잉, 실린더
 - 규칙 검사: 분류함·키트 카메라는 AI 키트에만, 자리 1~4 는 로봇팔 단독에만 → 틀리면 줄 번호와 함께 알려 줌

■ 제어판 ([직접 움직이기])
 - 관절: 슬라이더 + −/+ (1°·5°·10°). 도구 끝: X·Y·Z (5·10·20mm, 도구는 아래 방향 유지)
 - 기본 자세로 / 0° 자세로: 틀어진 자세를 한 번에 바로잡기
 - 모든 이동을 먼저 시뮬레이터로 검사(책상·보정판·분류함·카메라 거치대·블록) → 닿으면 거절
 - 로봇 모드에서는 같은 버튼이 실제 로봇을 속도 20 으로 움직임. 관절이 25° 넘게 도는
   도구 끝 이동은 먼저 확인
 - 영점 맞추기(실제 로봇): 서보 풀기 → 표시 맞추기 → 저장(set_servo_calibration 1~6) → 0° 확인.
   서버도 "서보가 풀려 있을 때만" 허용

■ 실제 카메라 · 로봇 안 영상처리
 - server.py --camera auto: /dev/video0~9 중 영상이 나오는 장치를 찾아 씀 (RDK X5 는 USB 카메라가
   0번이 아닌 경우가 많음). OpenCV 가 없으면 카메라 기능만 꺼짐
 - 콘솔 [실제 카메라]: 로봇 카메라 영상에 브라우저의 공식 방식 영상처리를 그대로 적용
 - [실제 블록 위치 가져오기]: 실제 카메라가 찾은 블록 좌표로 시뮬레이터 블록을 옮김
   → 그 배치로 시뮬레이션 통과 → 로봇에서 실행 (시뮬레이터 = 실물 배치)
 - 같은 영상으로 비교: 로봇 쪽 OpenCV(camera.py)와 브라우저 쪽(color.ts) 결과가 0.5mm 안에서 일치,
   마커 비율 0.5008 mm/px 로 같음. 처리 시간 12~20ms (개발 PC 기준)
 - 이 비교에서 찾은 문제: 시뮬레이터의 블록 시작 위치가 ArUco 마커 2와 2mm 붙어 있어
   OpenCV 가 마커 2를 못 읽음 (브라우저 해독기는 읽었음). 실물에서도 같은 일이 생김
   → 시작 위치를 안쪽으로 5mm 옮겨 여백 7mm 확보 (135/185, ±25)

■ 제안서와 시뮬레이터가 다른 점 (실물 사진으로 확정 필요)
 - 제안서의 키트 카메라: Full HD 1920×1080, 시야각 110°
 - 시뮬레이터: 공식 키트 사진(구형 키트, 640×480)에서 잰 위치·배율로 시야각 48°, 높이 360mm(추정)
 - 시야각 110° 카메라라면 훨씬 낮게 달리거나 넓게 보임 → 실제 카메라 [사진 찍기] 한 장이면
   높이·위치·시야각을 맞출 수 있음. 영상처리는 마커 2개로 보정하므로 카메라 사양이 달라도 좌표는 동작

■ 확인 방법
 - npm run check:practice — 두 테마의 모든 실습 예제가 충돌 없이 목표 달성, 테마 규칙
 - npm run check:console — 기존 공식 키트 대조 전부 통과 (블록 시작 위치 변경 후)
 - 데모 서버 + 브라우저: 검수 1·2 실제 실행(데모 팔), 반복 정밀도 표시, 검수 4·6·7, 제어판 조그,
   0° 자세, 영점 마법사, 로봇팔 단독 블록 옮기기 4/4, 실제 카메라(그림 파일)·가져오기·로봇 영상처리

■ 남은 것
 - 실물에서: 검수 1·2 실행, 반복 정밀도 값, 영점 표시 위치 확인, 키트 카메라 사진
 - 흡착 펌프 핀 (RDK X5) → 확인되면 펌프·펜·실린더도 로봇에서 실행
 - 검수 6 의 YOLO 등 공식 AI 샘플 시연 절차
