■ 2. 현장 세팅을 짧게
 지금까지: 로봇(RDK OS)에 접속 → 압축 풀기 → server.py 실행 → 윈도우로 돌아와 브라우저에 주소 입력
 바뀐 방법
 1) 로봇 — 처음 한 번만: 압축을 풀고 `sudo python3 autostart.py`
    → systemd 서비스로 등록. 이후엔 로봇 전원만 켜면 서버가 켜짐 (끄기 `--off`, 상태 `--status`)
 2) PC — 교실 PC 마다 한 번만: 콘솔 오른쪽 위 [바로가기] → 받은 .url 파일을 바탕화면에 → 이후 더블클릭
 3) 주소가 바뀌지 않게: 공유기에서 로봇에 DHCP 예약(고정 IP), 또는 유선·USB 직결.
    서버가 mDNS(avahi)를 찾으면 `http://<로봇이름>.local:8080/console` 도 함께 알려 줌
 수업 당일 절차: 로봇 전원 켜기 → (20초) → PC 바탕화면 아이콘 더블클릭
 실물에서 확인할 것
 - 자동 시작 서비스가 부팅 후 로봇 포트(/dev/ttyS1)와 카메라를 제대로 잡는지 (서비스는 3초 기다린 뒤 시작)
 - 흡착 펌프(Hobot.GPIO)가 서비스 사용자 권한으로도 켜지는지
 - RDK OS 에 avahi 가 있는지, USB-C 직결 시 고정 주소가 무엇인지

■ 3. 모델 확장 설계
 - 앱 구조: 시작 화면 → 모델 선택 → 시뮬레이터. 모델 목록은 web-typescript/src/engine/robot/catalog.ts 한 곳
   (이름, 제어보드, 연결 방식, 상태). 로봇 주소로 열면 그 로봇의 모델로 바로 시작
 - 연결 방식은 두 가지로 정리됨
   · 로봇 안 서버(onboard): 로봇에 리눅스 보드가 있는 모델 — 280 RDK X5, 280 Pi, myAGV.
     지금의 robot-python/server/server.py 를 모델별 설정(포트·통신 속도·관절 한계·펌프 핀)만 바꿔 씀
   · USB 직결(usb): 보드가 없는 모델 — 280 Arduino. 크롬의 Web Serial 로 브라우저가 로봇과 직접 통신
     (보고 #01 Web Serial 시험에서 가능성 확인). 로봇 쪽 설치가 전혀 없음
 - 모델마다 필요한 것
   · 3D·기구학: 공식 URDF 와 메시(Elephant Robotics mycobot_ros / mycobot_ros2 의 description 패키지) → 변환·경량화
     (지금 280 RDK X5 와 같은 도구 robot-python/tools/convert_meshes.py)
   · 관절 한계·기본 자세·속도 한계·도구(TCP) 치수
   · 서버 설정 또는 Web Serial 통신
   · 실습 목록: 모델마다 가능한 실습만 (예: 4축 팔은 손목 회전 실습 제외)
 - 공통으로 손볼 곳 (모델 2개째부터 필요)
   · "로봇 프로필" 한 덩어리로 묶기: URDF 경로, 관절 수·한계, 기본 자세, TCP, 연결 방식
   · 블록 편집기·조그 패널이 관절 수(4·6축)를 프로필에서 읽게
   · 역기구학: 6축은 지금 방식, 4축(myPalletizer)은 전용 풀이

■ 4. 작업 순서
 ① myCobot 280 RDK X5 — 마무리 (지금)
    남은 것: 실물에서 자동 시작·실시간 조그 확인, 중급 카메라 실습(파이썬 사진·색 인식), 교육 자료
 ② myCobot 280 Pi
    같은 팔(기구 동일) → 3D 는 280 계열 공통 메시 재사용, 보드 부분만 다름.
    서버: pymycobot MyCobot280, 포트·통신 속도·펌프 핀은 공식 Pi 자료로 확인 후 설정 (확인 필요)
 ③ myCobot 280 Arduino
    같은 팔. 로봇 서버 없이 브라우저 Web Serial 로 직접 연결 → "USB 로 연결" 버튼, 포트 고르기, 같은 안전 검사(한계·속도·정지)
 ④ myAGV (이동 로봇) — 1차 구현 완료 (주행 제어 + 카메라, 4-6)
    새 시뮬레이션: 교실 바닥, 메카넘 바퀴 이동, 라이다·카메라, 장애물. 실습: 원격 조종 → 경로 따라가기 → 지도·자율 주행(ROS 2)
    모델링: 공식 myagv_ros2(2023) · myagv_plus_ros2(Plus) 메시(BSD-3). 연결: 로봇 안 서버(onboard) → 조사 결과는 보고 #12
 ⑤ 다른 로봇팔 — myCobot 320, mechArm 270, myPalletizer 260(4축) 순
    프로필 구조가 갖춰지면 모델마다 URDF·한계·실습 목록 추가

■ 4-1. 가독성·사용성 정리 (피드백 반영)
 - 글꼴: 화면 전체를 Pretendard(OFL, 한글 화면 가독성 글꼴)로 통일, 앱에 포함(오프라인 가능). 코드 편집기만 고정폭 글꼴
 - 상단 줄 글자 크게(단계·환경 14.5px, 번호 원 20px), 세 패널 머리줄은 진한 남색 띠 + 흰 글자로 구분
 - 제어 패널: 칸마다 흰 카드(회색 바탕 위), 칸 제목 띠, 버튼 높이 36~56px, 표시등·버튼 글자를 우리말로
   (시뮬레이션·서보 켜짐·대기·정상, 연결 확인·손으로 움직이기·영점 맞추기), 조그 키 사용법 한 줄 안내
 - 이름 바꿈: [예제 다시] → [예제 코드 처음으로], [바로가기] → [바탕화면 아이콘 만들기](로봇 상태 칸으로 이동),
   JOINT/BASE → 관절/좌표
 - ③ 로봇 실행 버튼이 잠겨 있으면 이유를 버튼 안에 표시: "시뮬레이션 통과 후" / "로봇 연결 필요"
 - 연결이 끊기면 안내 창: 서버가 끊김(전원·공유기·서버 확인, 화면이 계속 다시 시도) / 팔이 대답 안 함(서버가 로봇 포트를
   새로 여는 [다시 연결] = /api/reconnect)
 - [도구 없음] 추가: 끝 플랜지만 달린 상태. 도구 명령은 "지금 로봇에 도구가 없어요" 로 알려 줌
 - 내 자세: [지금 자세 저장] → 목록에서 [가기]·[지우기], 이 PC 에 저장되어 다음 수업에도 남음

■ 4-2. 전체화면 3D 와 떠 있는 패널, 부드러운 조작
 - 목업 확인 후 적용: 3D 가 창 전체, 상단 줄·제어 패널·편집기·실습 제목·실행 막대·기록이 그 위에 떠 있음.
   제어 패널과 편집기는 접으면 창 가장자리 세로 탭이 되고, 상태는 이 PC 에 기억
 - 상단 줄의 단계·작업 환경·실습 버튼이 남는 가로 공간을 나눠 가짐
 - 3D 자동 맞춤은 떠 있는 창이 가리지 않는 부분을 기준으로 (패널을 접고 펼 때도 다시 맞춤)
 - 실제 로봇 관절 조그 = 로봇 자체 연속 조그(jog_angle, /api/jog): 목표를 끊어 보내던 방식의 가감속 반복(덜컥거림)을 없앰.
   0.2초마다 유지 신호, 끊기면 0.8초 안에 정지, 한계 3° 앞 정지, 화면이 8° 앞을 미리 충돌 검사
 - 시뮬레이터 조그는 0.25초 부드러운 가속, 실제 로봇 표시는 0.1초마다 읽고 60ms 로 따라가 지연을 줄임
 - 자체 동작 검수(자동): 시뮬레이터 21항목(한 칸·계속·HOME·자세 저장/가기/지우기·좌표 Z·도구 없음·시뮬레이션→목표→코드,
   접기/표시 기억, 검수 1~7, 단계 전환) + 로봇(데모 팔) 15항목(HOME·한 칸·연속 조그와 정지·자세 가기·손으로/고정·영점 창·
   로봇 실행 끝까지·정지) + 연결 끊김/복구 — 모두 통과

■ 4-3. 로봇 연결 단계와 수업 편의 (피드백 반영)
 - 로봇 연결: 처음 시작 = 모델 선택 → 로봇 연결(로봇 ID 입력) 또는 시뮬레이션만. 언제든 오른쪽 위 [로봇 연결].
   로봇 ID = 로봇 IP 의 마지막 숫자(서버가 켜질 때 "★ 로봇 ID: 252"), 교실 네트워크 앞부분은 한 번 정하면 기억,
   최근 연결 목록. 연결하면 그 로봇의 콘솔(같은 앱)로 이동하고 상단·창 제목에 "로봇 252" 표시 → 여러 명이 각자 자기 로봇
 - 원인 정리: robot_console.zip 은 로봇용. PC 에서 풀어 열면 로봇 서버가 없어 시뮬레이션만 됨 → 매뉴얼 첫머리에 명시
 - 연결 확인 동작 빠르게(속도 15 → 35)
 - 블록: [N초 동안 관절을 X°로](time=, 0.3~20초, 속도를 시간에 맞춰 계산) · [⏸ N초 동안 멈추기]
 - 시뮬레이션 배속 ×1 ×2 ×4 (실제 로봇은 늘 제 속도)
 - 도구: 모양 아이콘 + 가운데 정렬, [도구 없음] 을 맨 앞으로 / 자세: [기본 자세] [일자로 펴기] [지금 자세 저장하기] [이 자세로]
 - 자체 동작 검수: 시뮬레이터 27항목, 로봇(데모) 17항목, 연결 끊김/복구, 단위 검사 67항목 모두 통과

■ 4-4. 전체 구조 검수와 최적화 (피드백: 끊김·가림·잘림)
 - 원인 1 — 조그 끊김: 카메라 작은 화면을 그릴 때 그래픽 카드를 기다리는 읽기(readPixels)가 페이지 전체를 최대 2~3초 멈춤
   → 로봇의 유지 신호가 끊겨 로봇이 스스로 멈춤("목표가 끊겨 멈춥니다"). 카메라 화면을 기다리지 않는 읽기로 바꾸고,
   작은 화면은 240×180 으로만 그림 → 누르는 동안 신호 간격 0.2초로 일정, 끊김 0회
 - 원인 2 — 좌표 조그: 도구가 아래를 향하지 않은 자세(기본 자세 등)에서는 풀이가 실패, 한 프레임 이동(약 0.5mm)이 풀이
   허용 오차와 같아 가다 서다 함 → 도구를 지금 방향 그대로 두고 곧게 옮기는 풀이(5mm 씩 나눠 따라감, 오차 0.05mm)
 - 로봇 상태 읽기는 한 번에 하나씩(느린 응답 뒤로 요청이 쌓이지 않음), 로봇 서버가 없는 PC 시뮬레이터는 3초에 한 번만 확인
 - 화면이 초당 10번 바뀌는 값(각도·로봇 상태)은 표시 칸만 다시 그림 → 조그 3초 동안 전체 화면 다시 그리기 0번
 - 기록 창은 누를 때만 열림, 카메라를 열어도 기록 창이 따라 열리지 않음, 카메라 창은 작게 3D 옆에
 - 실행 중 패널 자동 접기(표시 › 실행할 때 패널 접기), 끝나면 바로 다시 펼침
 - 노트북 화면(1180~1440): 상단은 로고만·모델 짧은 이름, 실행 막대는 ■ 정지·배속 한 버튼(×1→×2→×4),
   좁으면 목표 칸이 아랫줄로, 카메라 창은 한 장씩(300px)
 - 자동 화면 검수: 창 크기 1920·1536·1366·1280·1180 × 실습/검수 × 카메라 창, 시뮬레이터와 로봇 모드 모두.
   가려진 버튼·창 밖·잘린 글자(…)·단어 중간 줄바꿈·빈 카메라 화면을 찾음 — 모두 통과
 - 자체 동작 검수: 시뮬레이터 29항목, 로봇(데모) 24항목(유지 신호 끊김 0회 포함), 연결 끊김/복구, 단위 검사 모두 통과

■ 4-5. 조작감 · 화질 (myAGV 목업에서 좋았던 것을 로봇팔에도)
 - 입체 버튼: 조그 키 · 로봇 버튼 · 자세 · 도구 버튼이 도드라져 있고, 누르면 눌려 들어감(보라). 끼운 도구는 파랗게 눌린 상태
 - 둥근 손잡이: 관절 막대(보라) · 속도 막대(주황), 움푹한 홈
 - 슬라이드 조그(좌표 X·Y·Z): 손잡이를 끄는 만큼 빠르게, 놓으면 제자리로 돌아오며 정지. 로봇에서는 연속 조그 속도만 바뀜(3→24 확인)
 - 관절 한계 가까이에서도 좌표 조그가 막히지 않게: 미리 보기를 25mm → 8mm → 위치만 순으로 풀고, 충돌 검사는 그대로
 - 고화질: 흐린 가장자리의 부드러운 그림자(분산 그림자). 보통 화질은 가벼운 그림자 그대로(느린 PC 보호)
 - 도구 궤적 선의 셰이더를 불러올 때 미리 준비 → 처음 움직일 때 화면이 멈추던 것(느린 그래픽에서 최대 5초) 제거
 - 카메라 작은 화면에 렌즈 가장자리 어두움(보기만, 영상 처리에는 영향 없음)

■ 4-6. 교실 Wi-Fi · myAGV 주행 콘솔
 - 교실 Wi-Fi: 전용 공유기(예: EDUINO-LAB) 권장. 로봇은 한 번만 교실 Wi-Fi 로 옮기면(화면 [로봇 Wi-Fi] 또는
   sudo python3 wifi.py) 켤 때마다 교실 공유기에 먼저 붙고, 없으면 자기 핫스팟으로.
   학생은 [로봇 찾기] 로 같은 Wi-Fi 의 로봇 목록(ID·모델·상태)을 보고 [움직여 확인] 으로 내 로봇을 고른 뒤 연결
 - 서버의 Wi-Fi 변경 권한: 자동 시작 서버(일반 사용자)는 로봇 OS 설정에 따라 화면에서 Wi-Fi 를 못 바꿀 수 있음 →
   그때는 로봇 터미널에서 sudo python3 wifi.py (권한을 넓히는 설정은 넣지 않음, 필요하면 결정 후 추가)
 - myAGV 주행 콘솔(/agv, 로봇에서는 /console): 조이스틱·키보드·게임패드, 앞 카메라(실물 영상 / 시뮬레이션 찾기),
   라이다(시뮬레이션), 직진 보정(실물: 1m 테이프에서 옆 cm 한 번 재기 → 보정값 저장, 시뮬: 자동 측정),
   불빛, 모델 2023 Pi · 2023 JN · Plus
 - 로봇 서버 agv_server.py: pymycobot MyAgv 이동 명령을 0.1초마다 보내고, 화면의 유지 신호가 0.5초 끊기면 정지,
   속도 제한 0.5 m/s · 1.5 rad/s, 보정값은 로봇에 저장. 명령 단위(0.01)보다 작은 보정은 다음 명령으로 넘겨 평균이 정확하게
 - 유지 신호는 화면과 따로 도는 작업자(Web Worker)가 보냄: 3D 준비 등으로 화면이 0.5~0.7초 멈춰도 주행이 끊기지 않음
   (화면이 1초 넘게 멈추면 작업자도 멈춤). [멈춤] 은 작업자의 명령부터 지우고 보내, 멈춘 뒤 옛 명령이 다시 가지 않음
 - 자체 검수: 시뮬레이터 28항목, 로봇(데모) 25항목 × 5회 연속 통과, 단위 검사(바퀴·충돌·라이다·입력·직진 보정),
   창 크기 5종 화면 검수 통과. 로봇팔 쪽 회귀 검사(시뮬 32 · 로봇 26 · Wi-Fi 16 · 화면)도 통과
 - 실물 확인 남은 것: 배터리 전압 값, 젯슨 나노 포트 이름, 속도 값과 실제 m/s

■ 4-7. USB 키트 — 수업 장소마다 Wi-Fi 이름·비밀번호만 적어 꽂기
 - 문제: 출강 때마다 랜선 연결 → 터미널 → Wi-Fi 입력 → 확인. 로봇 수만큼 반복
 - 처음 한 번(로봇마다): USB 의 eduino/install.py 를 sudo 로 한 줄 실행 → 콘솔 풀기, 자동 시작(로봇팔 / myAGV 자동 판별),
   eduino-usb 서비스 설치, 이 USB 의 wifi.txt 로 바로 연결
 - 그 뒤: PC 에서 wifi.txt(이름=, 비밀번호=) 저장 → 로봇에 꽂기 → 연결되면 로봇이 살짝 움직이고
   USB 에 result-<로봇이름>.txt(성공/실패·이유·로봇 ID·주소) 가 생김. USB 하나로 여러 대 차례로 가능
 - 같은 wifi.txt 는 로봇마다 한 번만 적용(결과 파일의 확인값), 실패하면 다시 꽂을 때 재시도, 꽂은 채 켜도 반복 안 함
 - 로봇 화면에 아무도 로그인하지 않아 USB 가 열리지 않은 경우 서비스가 직접 열었다(nosuid·noexec) 닫음
 - 안전: USB 에서 읽는 것은 Wi-Fi 이름·비밀번호뿐, 프로그램 자동 실행 없음. USB 밖을 가리키는 링크 거부
 - 자체 검수: 설정 읽기(메모장 UTF-8·BOM·ANSI(cp949)·CRLF), 가짜 RDK X5 에서 연결·비밀번호 틀림·핫스팟 복귀,
   꽂기·빼기·다시 꽂기·늦은 자동 마운트 시간표, 설치 파일 모의 설치 — 37항목 통과. 실물 확인 남음 (USB 자동 마운트, 실제 공유기)
 - 매뉴얼: manuals/setup/usb-kit.md

■ 4-8. 화면 개편 — 작업 패널 하나(오른쪽) + 넓은 3D
 - 조작과 코딩을 오른쪽 패널 하나로 합침. 탭 4개: [직접 제어](처음 화면) · [블록 코딩] 초급 · [Python] 중급 · [ROS 2] 고급.
   탭마다 자기 프로그램을 기억해 오가도 지워지지 않음(단계 바꿀 때 묻던 창 없앰)
 - 오른쪽을 기본으로: 엔트리·스크래치와 같은 배치(실행 화면 왼쪽, 코딩 오른쪽), 눈이 먼저 3D 로봇에, 조작은 오른손 마우스 쪽.
   [··· 설정] 에서 왼쪽으로 바꿀 수 있음
 - 윗줄(늘 보임): 로고·Physical AI 학습 프로그램, 모델, 지금 과제(누르면 과제 카드 창 — 실습 / 검수 시연, 언어·작업대 골라 보기),
   목표 진행, 검수 번호 1~7, 작업대 메뉴(섞기·처음 상태, 비중이 작아 메뉴 안으로), 설정, 연결, ■ 정지
 - 실행 막대: 아이콘 한 줄 — ▶ 시뮬레이션 · 빠르기 버튼 하나(세모 둘: 한 번 = 세모 하나·2배, 두 번 = 세모 둘·4배, 세 번 = 보통) · 로봇 모양 ▶ 로봇 실행 · ■
 - 윗줄 로고 옆은 두 줄 'Physical AI / 학습 프로그램', 윗줄 버튼은 모두 같은 높이(44px)·한 줄 가운데 정렬. 과제 카드는 과제마다 큰 아이콘
 - 뺀 것: 관절 각도 표(조그 목록에 같은 값), 3D 아래 도구 끝 위치 중복(3D 왼쪽 위 한 곳), 편집기 머리줄의 예제 목록(과제 카드 창과 같음)
 - 기능 지도: 기존 버튼·목록 160여 개를 48묶음으로 모두 새 위치에 옮김, 처음 화면에서 2번 안에 닿음

■ 4-9. PC 프로그램 (Physical AI Tool) — 주소 외우지 않고 로봇 열기
 - 지금: [··· 설정] → [PC 프로그램 받기] 또는 USB 키트의 eduino/Physical AI Tool.html 을 바탕화면에 → 더블클릭
   → 내 로봇(연결 가능 표시) [열기] / 같은 Wi-Fi 에서 찾기 / 로봇 ID 로 열기. 설치 없음, 파일 하나(HTML)
 - 바로가기(.url) 는 로봇의 http 주소에서 받을 때 크롬이 위험 파일로 막아(".download" 로 남음) 이 방식으로 바꿈
 - 검토 — "USB 로 로봇에만 압축 파일, 나머지는 모두 PC 프로그램에서" (터미널 없는 현장):
   1) 지금 남은 터미널 일: 로봇마다 처음 한 번 sudo install.py (자동 시작·USB 서비스 설치에 관리자 권한 필요),
      콘솔 새 판으로 바꿀 때 다시 설치, 펌프 점검 등 문제 해결
   2) 다음 단계(권장, 작음): 콘솔 안에서 업데이트 — [설정] → [새 판 올리기] 로 robot_console.zip 을 PC 에서 올리면 로봇 서버가
      풀고 다시 켬(파일이 로봇 사용자 소유라 관리자 권한 불필요). 처음 설치 뒤로는 터미널이 필요 없어짐
   3) 그다음(큼): 설치형 PC 프로그램(Windows) — 로봇 핫스팟·랜선으로 SSH 접속해 처음 설치까지 대신 실행(로봇 비밀번호 한 번 입력).
      USB 없이도 됨. 필요한 것: 윈도 설치 파일 서명(학교 PC 경고 방지, 연 단위 비용), 로봇 기본 계정·SSH 가 켜져 있어야 함
   4) 보안상 하지 않는 것: 로봇이 USB 의 프로그램을 저절로 실행하게 하기, 서버를 관리자 권한으로 상시 실행(펌프 권한은 결정 필요)

■ 4-10. 색 따라가기 (손 카메라)
 - 지금: 카메라 플랜지를 달면 카메라 창에 [색 따라가기] — 색을 고르고 [▶ 따라가기] → 팔이 그 색을 손 카메라 화면 가운데에
   두도록 따라 움직임(높이·도구 방향 유지). 시뮬레이션은 3D 손 카메라, 로봇 연결 시 실제 카메라로 같은 동작
 - 방법: 처음에 팔을 x·y 로 2cm 씩 움직였다 돌아오며 화면 속 물체의 이동을 재서 "화면 ↔ 팔" 방향(2×2 영상 야코비안)을 구함
   → 카메라 모듈을 플랜지에 어느 방향으로 끼웠든, 공식 손-눈 보정 없이도 맞음. 이후 초당 수 회 가운데 쪽으로 비례 이동
   (한 걸음 최대 10mm, 가운데 14px 안이면 정지, 매 걸음 충돌 검사, 멀어지기만 하면 스스로 멈춤)
 - 시험: web-typescript/tests/robot/track-check.mts — 카메라를 0~270° 돌려 끼운 6가지 모두 가운데로 수렴, 천천히 움직이는 블록 추종
 - 함께 고침: 3D 손 카메라가 카메라 플랜지 몸체 안쪽을 비추던 문제(가까운 면 5mm → 30mm), [카메라 자세](공식 RDK X5 비전 키트 촬영 자세)
 - 실기 확인 필요: 실제 카메라 지연(초당 처리 횟수)에 따른 따라가는 속도, 조명에 따른 색 인식
