■ 화면 구성

     + 카메라 플랜지 켜기/끄기, 블록 섞기, 처음 상태로

■ 로봇팔 모델
 - 출처: elephantrobotics/mycobot_ros2 (humble) 의 mycobot_280_rdkx5 메시 7개 + URDF
 - 관절 위치·축은 URDF 원본 그대로, 화면과 계산이 같은 URDF 를 씀
 - 메시 단위가 파일마다 달라(mm/m) 변환 시 부품마다 크기를 검사하고, 1개(joint5) 는 다른
   리더로 읽어 좌표를 맞춤 → robot-python/tools/convert_meshes.py
 - 용량: 17개 부품(몸체 + 공식 액세서리) 합쳐 332KB

 - 공식 메시가 있는 것(어댑티브·흡착·카메라 플랜지)은 공식 장착 위치 그대로.
   나머지 4종은 공식 3D 파일이 없어 제품 사진 크기로 만든 단순 모형
 - 카메라 플랜지 두께 16.9mm 는 공식 URDF 두 개(펌프 / 카메라 플랜지+펌프)의 차이에서 계산
 - 그리퍼 종류 번호(1·3·4)는 pymycobot MyCobot280RDKX5.set_gripper_state 설명 그대로
 - 흡착 펌프·펜·실린더의 실제 제어 핀은 키트 배선에 따라 달라 추정하지 않음.
   로봇 코드에서는 해당 줄에서 멈추고 "핀 번호 확인" 안내를 띄움

■ 동작 — "오차 없이 부드럽게"
 - 5차 곡선 s(τ)=10τ³−15τ⁴+6τ⁵: 시작·끝에서 속도와 가속도가 모두 0 → 덜컥임 없음
   (목업은 2차 곡선이라 가속도가 끝에서 튀었음)
 - 모든 관절이 같은 곡선 → 동시에 출발, 동시에 도착 (send_angles 와 같은 방식)
 - 속도 1~100 → 관절 최고 속도 2°/s × 값 (수업 상한 50 = 100°/s)
 - 도구가 아래를 향한 상태에서는 도구 끝이 "직선"으로 이동 (4mm 마다 역기구학 계산)
   → 블록 위에서 수직으로 내려가 집음. 중간에 팔 자세가 뒤집히면 움직이지 않고 오류로 알림
 - 위치 오차: 역기구학 허용 0.5mm (로봇 반복 정밀도 ±0.5mm 와 같게), 방향 0.5°
 - 작업판의 모든 블록·칸·버튼 × 도구 7종 × 카메라 플랜지 유무 = 364점 모두 도달 확인,
   최대 오차 0.50mm
 - 움직이는 매 프레임마다 검사하고, 걸리면 그 줄에서 멈추고 고칠 방법을 표시
     관절이 책상에 닿음 / 도구가 판에 닿음 / 닫힌 그리퍼가 블록에 부딪힘 /
     잡은 블록이 판·다른 블록에 부딪힘 / 너무 높은 곳에서 놓아 떨어짐(주의)

■ 카메라 2화면 (영상 처리 알고리즘 적용 화면 포함)
 - 카메라 화면: 시뮬레이션 속 카메라가 실제로 찍은 영상 (320×240)
 - 영상 처리 화면: ① RGB→HSV ② 색 범위로 마스크 ③ 붙은 픽셀 묶기(연결 요소)
   ④ 크기·꽉 참 조건으로 블록만 남김 → 번호·중심점 표시, 아래에 픽셀 좌표와 작업판 좌표(mm)
   → 공식 비전 키트의 OpenCV 순서(cvtColor → inRange → connectedComponents)와 같음
 - 픽셀 → 로봇 좌표: 카메라 위치·방향으로 광선을 쏘아 블록 윗면 높이 평면과 만나는 점
   (손-눈 보정이 하는 일을 눈으로 보여 줌)
 - 색 칸의 테두리는 "꽉 참" 조건에서, 회색 로봇·흰 판은 채도 조건에서 걸러짐.
   버튼은 주황색이라 빨강·노랑 범위 사이에 들어가 블록으로 오인되지 않음
 - 고정 카메라: 작업판 위 520mm, 로봇이 화면 아래쪽에 보이게 (학생이 로봇 뒤에서 보는 방향)
 - 손 카메라: 카메라 플랜지 끝(플랜지 중심에서 50mm), 도구 방향을 봄. 그리퍼가 화면 아래에
   걸려 보이는 것도 실물과 같음
 - 프로그램: block = camera.find("빨강") / hand_camera.find(...) 로 찾고
   robot.move_above(block), robot.move_down(block) 으로 이동
 - 측정: 위 카메라로 찾은 위치 오차 약 2mm (블록 옆면이 보이는 원근 효과, 방향은 항상 카메라 쪽).
   집기 허용 범위(9mm) 안이라 미션은 성공. 수업에서 "왜 2mm 틀릴까?" 를 다루기 좋음

■ 로봇에서 실행
 - 시뮬레이션에 성공해야 버튼이 열림 (목업의 규칙 그대로)
 - 누르면 로봇용 파이썬 코드 창: 복사 / 파일로 받기 / 실행 방법 3단계
 - 코드는 시뮬레이션이 계산하고 충돌 검사를 마친 관절 각도를 그대로 보냄
   (MyCobot280RDKX5("/dev/ttyS1", 1000000), sync_send_angles). 직선 이동은 15mm 간격 관절 목표로
 - 카메라로 찾은 위치는 시뮬레이션에서 찾은 값으로 고정됨 (코드 머리말에 표시).
   실제 카메라로 찾는 것은 다음 단계 (로봇 안 서버)
 - 작업판을 시뮬레이션과 같은 자리(로봇 앞 x 110~280mm, y −140~140mm)에 두어야 함

■ 정정 — 기구학 회전 순서 오류 (보고 #2 수치에 영향)
 - URDF 의 rpy 는 Rz·Ry·Rx 순서로 곱해야 하는데 Rx·Ry·Rz 로 곱하고 있었음
 - 두 각이 0 이 아닌 관절(J3, J6)에서만 차이가 나서, 자기 자신과 비교하는 기존 검사
   (자코비안·IK 수렴)는 모두 통과했음
 - 발견 계기: 0° 자세에서 실제 로봇은 팔이 곧게 서는데 계산상 누워 있었음
 - 수정 후: 0° 자세 플랜지 높이 411mm (곧게 섬). 재발 방지 검사 2개 추가
   (0° 자세가 서 있는지, rpy 곱셈 순서)
 - 영향: 플랜지 도달거리 332.5 → 302mm 로 정정. 손목 기준 287mm(데이터시트 280mm 근거)는 그대로.
   목업의 이름 붙은 자세(물건 위 등)도 이 오류 위에서 확인한 값이라 폐기하고,
   작업판 좌표로 가는 명령(move_above / move_down)으로 대체
