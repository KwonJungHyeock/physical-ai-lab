### E. 삭제 · 축소

| 위치 | 이유 | 대신할 것 |

| 8-1 · 문항 객관식 응용 8 (102행, 강화학습 이름) | "이름만 다룬다"는 개념을 응용 문항으로 묻는다. 응용 칸이 아깝다. | 응용 문항을 "이 화면의 정책은 움직이는 동안 블록을 다시 보는가? (아니다, 처음에 한 번 보고 궤적을 정한다)" 같은 폐루프 · 개루프 문항으로 바꾼다. 강화학습은 기본 문항이나 새 용어로만. |
| 7-3 · 자세히 2 · 활동 2 · 3 왜 · 정리 답의 "π/2 ≈ 1.57" 근거 | 고등 본문에서 π/2 는 유도 없이 외우는 숫자다. 게다가 이 화면의 실제 한계(약 7.2)와 맞지 않는다. | 고등 본문은 "이 화면에서 `K` 가 약 7 을 넘으면 흔들림이 커진다"로 줄이고, π/2 · 지연 미분방정식은 대학 수식과 이론서로 옮긴다. |
| 7-1 · 수식 5 의 "AX = XB 꼴의 식을 풀어 구한다" | 시뮬레이터는 손-눈 변환을 주어진 값으로 쓰므로 보정 과정을 보여 줄 수 없다. 실물 키트도 공장 값(EyesInHand)을 쓴다. | "손-눈 변환은 여러 자세에서 같은 마커를 찍어 구한다(손-눈 보정)" 한 문장만 남기고 AX = XB 풀이는 이론서로. |

### F. 확인 필요

| 항목 | 내용 |
| --- | --- |
| 실물 키트 위 카메라의 시야각 | `board.ts` 는 86.1°(640 px)를 판매 사양에서 추정했다고 적는다(공개 안 됨). 그 값이면 판 위 1 px ≈ 1.07 mm. 시차(100 mm 에서 약 7.3 mm)는 높이 비율만으로 정해져 시야각과 상관없다. |
| 캡스톤 실물 실행의 흡착 컵 TCP | 화면은 맨 플랜지 펌프 89 mm 로 관절 각을 계산한다. 손 카메라용 카메라 플랜지를 단 채면 펌프 헤드는 106.2 mm(+16.9 mm)라서 컵이 약 17 mm 더 내려가 블록 · 책상을 누를 수 있다. 실물 수업에서 어떤 플랜지를 쓰는지 확인 필요(안전). (`effectors.ts` CAMERA_FLANGE_SPACER_MM) |
| 시뮬과 실물의 위 카메라 사진 방향 | 7-1 · 8-2 시뮬 카메라는 사진 위 = +x(로봇 바깥)이다. 실물 키트 공식 식(x = (v − c_v)·ratio + …)은 사진 위 = 로봇 쪽이다. 180° 돌아 보이는지 실물 화면으로 확인 필요. |
| 실물 빨강 블록의 색상 | 키트 위 카메라의 공식 빨강 범위는 OpenCV H 0~8 하나뿐이다(170~179 없음). 시뮬 블록(약 −2° = OpenCV 179)이라면 놓친다. 실물 블록의 색상 값 확인 필요. |
| 리더–팔로워 · 직접 교시 기록 빈도 | myCobot 280 의 get_angles 를 시리얼로 1 초에 몇 번 읽을 수 있는지(8-1 의 20 Hz 기록과 맞는지) 확인 필요. LeRobot 이 myCobot 280 을 공식 지원하는지도 확인 필요(공식 목록은 SO-100/101, Koch 등으로 알고 있음). |
| 7-2 앱 카메라 탭의 YOLO | 원고는 "이 앱의 카메라 탭에도 YOLO 검출이 들어 있다"고 한다. 로봇에 연결하지 않은 시뮬(Windows exe)에서도 되는지 확인하지 않았다(실물 콘솔의 `camera.py` Yolo 는 확인). |
| 이론서 PDF(7 · 8단원) | `theoryPages.gen.ts` 의 깊은 이론은 이번에 보지 않았다. B 의 7-3 한계 · 정책 표기를 고치면 이론서도 맞춰야 한다. |
