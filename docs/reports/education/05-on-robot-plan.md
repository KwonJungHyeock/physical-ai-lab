■ 로봇 OS 접속 — 세 가지 방법
 1) 모니터·키보드·마우스 직결 (HDMI) — 가장 쉬움. 로봇이 곧 컴퓨터
 2) 원격 화면 (VNC) — 같은 Wi-Fi 의 PC 에서 로봇 바탕화면
 3) 원격 터미널 (SSH)
 계정: 공식 문서의 비밀번호 "Elephant"(사용자 er)는 라즈베리파이 버전 기준이고,
       RDK 보드 기본값은 sunrise/sunrise 로 알려져 있음.
       RDK X5 출고 이미지가 어느 쪽인지는 설명서 또는 실기에서 확인 필요.

■ 추천 구조 — "수업 콘솔을 로봇 안에"
 - 로봇이 켜지면 수업 콘솔이 자동 실행
 - 학생·교사는 같은 Wi-Fi 의 PC/태블릿 브라우저로 http://로봇IP:포트 접속
   → 학교 PC 에 설치할 것이 없음 (관리 PC 제약 회피)
   → https(Vercel) 페이지가 로봇에 직접 못 붙는 문제도 사라짐
 - 로봇 모니터에 직접 띄워도 됨
 - 로봇 안 구성: 파이썬 서버 1개 (공식 SDK pymycobot 사용)
     웹 화면 제공 + 학생 코드 실행기 + 안전 계층(속도 상한·관절 한계·바닥·비상정지)
 - 웹 화면(목업을 실제로 만든 것)은 정적 파일로 빌드해 복사 → 로봇에 Node.js 불필요
 - 공식 것은 건드리지 않음: 공식 이미지·myStudio·myBlockly·ROS2 패키지 그대로.
   우리 것은 폴더 1개 + 서비스 1개. 끄면 공장 상태로 돌아감.

■ 공식 자료를 크게 벗어나지 않는 방법
 - 로봇 제어는 공식 SDK(pymycobot) 그대로. 우리 파이썬 명령은 그 위의 얇은 층
 - 파이썬 화면에 "공식 코드로 보기": 같은 동작을 공식 튜토리얼 코드로 함께 표시
     robot.move_joints([...])   ↔  mc.send_angles([...], 40)
     robot.gripper.open()       ↔  mc.set_gripper_state(0, 50)   (공식은 0=열기. 초보자가 헷갈리는 지점)
   → 학생이 공식 튜토리얼로 자연스럽게 넘어감
 - 커리큘럼 순서를 공식 문서 목차에 맞춤 (아래)
 - URDF·관절 한계도 공식 값 기반 (보고 #2)

■ 공식 자료에서 확인한 문제
 1) GitHub 공개 RDK X5 문서 원본(elephantrobotics/mycobot_docs, x5pi 브랜치, 2025-02-21)이
    라즈베리파이 버전 문서의 복사본: 포트 /dev/ttyAMA0, 클래스 MyCobot280, "Raspberry Pi 핫스팟".
    RDK X5 실제 공식 코드는 /dev/ttyS1, 1,000,000 baud, MyCobot280RDKX5.
    → 문서대로 따라 하면 RDK X5 에서 실패할 수 있음
    (docs.elephantrobotics.com 최신본은 이 환경에서 접속이 막혀 확인하지 못함. 거기선 고쳐져 있을 수 있음)
 2) MoveIt2 설정은 가짜 하드웨어(mock), 실기 연동은 간이 노드 (보고 #3)
 3) Gazebo 시뮬은 M5 전용 + 지원 종료된 Gazebo Classic (보고 #3)
 4) 중국어 비중이 높고, 터미널·ROS 를 안다고 전제
 → 우리 커리큘럼은 이 부분을 "실기로 검증한 한국어 버전"으로 대체
