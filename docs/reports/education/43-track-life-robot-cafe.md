# 보고 #43 — 입문 트랙 ① 생활 로봇: 로봇 카페 시뮬레이터 설계와 근거

> 상태: 설계안 (만들기 전 확정용) · 2026-11-03 · 브랜치 `track/life` · 주소 `/track/life`
> 이 문서는 시뮬레이터의 단계(차시)마다 **무엇을 실제처럼 만들었는지, 그 근거와 참고 자료가 무엇인지**를 적는다.
> 숫자 옆의 [n]은 맨 아래 참고 자료 번호. '확인 필요'는 2차 자료만 있어 공식 자료로 다시 봐야 하는 값.

## 1. 목적

- 입문(초5~중2) 학생이 **실제 로봇 카페가 일하는 방식**을 블록 코딩으로 따라 만들어 보게 한다.
- 결과가 장면으로 보여야 한다: 순서가 틀리면 커피가 흐르고, 컵이 없으면 머신이 추출하지 않고, 손님 손이 있으면 문이 안 열린다.
- 배우는 개념은 실제 로봇 카페를 만드는 엔지니어가 쓰는 말 그대로 쓴다: 레시피(순서), 위치 가르치기(티칭), 신호 기다리기(인터록), 사이클 타임, 안전문.

### 2-2. 공통 구조 (여러 사례에서 반복되는 것)

1. **주문 → 대기열**: 주문이 쌓이고 순서대로 만든다(PIN · 알림) [1][3].
2. **스테이션을 차례로 도는 팔**: 컵 디스펜서 → 제빙기 → 커피 머신(→ 시럽) → 픽업대. 팔이 컵을 들고 스테이션 사이를 옮긴다 [1][6][10].
3. **장비와 신호를 주고받는다**: 커피 머신은 컵이 감지될 때만 추출하고, 추출 중 컵이 사라지면 멈춘다(컵 감지 센서 + 상태 기계) [11]. 컵 공급 장치도 광센서로 컵이 있는지 본다 [12].
4. **레시피 = 순서 + 양**: 아이스 아메리카노는 얼음 → 에스프레소 2샷(샷당 약 30 ml) → 물 [13]. 에스프레소 한 샷은 보통 25~30초 추출(확인 필요: SCA 기준 번호) [14].
5. **픽업과 안전**: 협동로봇(사람 곁에서 일하도록 인증) 또는 안전문 · 펜스로 손님과 팔을 나눈다. 음료가 정해진 자리에 놓이면 안전문이 열리는 방식 사례가 있다 [5][6].
6. **사이클 타임과 처리량**: 한 잔 40초~1분, 시간당 90~120잔이 경쟁 지표다 [1][2][4][6].
7. **원격 관리와 오류 대응**: 재료 잔량, 결제 오류, 미수령 음료 폐기 [3][5].

## 3. 우리 시뮬레이터로 옮기는 원칙

| 실제 | 우리 모델 | 이유 |
|---|---|---|
| 팔 도달 거리 850 mm 급 협동로봇(RB5-850) | myCobot 280을 **1/3 축척**으로 그 역할에 둔다. 화면의 길이 · 컵 크기는 실제 매장 값(mm)으로 보여 준다 | 실습 셀이 1/5 축척으로 큰 산업 로봇을 대신하는 것과 같은 방식(engine/simulator/cell/cells.ts) |
| 컵 디스펜서 · 제빙기 · 커피 머신 · 픽업대(문) | 4개 스테이션 + 주문 화면, 각 장비는 **상태 기계**(대기 → 동작 → 완료)와 **센서 · 신호**를 가진다 | 2-2의 3 · 5 |
| 추출 25~30초, 얼음 · 물 양 | 추출 28초(실제 시간, 시뮬레이션 배속 ×2 · ×4 가능), 컵에 차는 양을 장면으로 | 2-2의 4. 숫자는 모두 계산식이 만든다 |
| 손님 · 안전문 | 픽업대에 문과 '손 감지' 센서. 손이 있으면 팔이 들어가지 않는다 | 2-2의 5 |
| 오류 | 컵 없이 추출(흘림) · 얼음 넘침 · 컵 떨어뜨림 · 문 인터록 위반을 기록 | 학생이 '왜 실패했는지'를 장면에서 보게 |

**단순화하는 것(입문이라서)**: 포터필터 장착 · 탬핑(전자동 머신으로 대신), 결제, 우유 스팀, 뚜껑 실링. 고급 트랙에서 다룰 수 있다.

## 4. 장비 모델 (상태와 신호)

| 장비 | 상태 | 로봇이 보는 신호 | 로봇이 보내는 명령 | 실패 |
|---|---|---|---|---|
| 컵 디스펜서 | 대기 → 컵 내림 → 컵 준비 | `컵 준비됨` | `컵 주세요` | 컵을 안 집고 다시 요청하면 쌓임 |
| 제빙기 | 대기 → 얼음 나옴(약 3초) | `얼음 끝` | `얼음` | 컵 없이 누르면 바닥에 떨어짐 |
| 커피 머신 | 대기 → 컵 확인 → 추출 28초 → 완료 | `컵 있음` · `추출 중` · `추출 끝` | `추출 시작` | 컵 없이 시작: 흘림(실제 머신은 거부, 입문에서는 결과를 보이려고 흘림으로 표시 — 아래 '확인 필요') |
| 픽업대 + 안전문 | 닫힘 → (음료 놓임) → 열림 → 손님이 가져감 → 닫힘 | `손 감지` · `문 열림` | `문 열기` | 문이 열려 있거나 손이 있을 때 팔이 들어가면 정지 |

## 5. 단계(차시) 구성과 각 단계의 근거

각 단계는 시뮬레이터의 한 과제(미션)이고, 지금 할 일 → 관찰 → 개념 → 적용 순서로 진행한다.

| 단계 | 미션 | 배우는 것 | 실제 근거 |
|---|---|---|---|
| 1 둘러보기 | 완성된 프로그램으로 아이스 아메리카노 한 잔이 만들어지는 걸 보고, 장비 4개의 순서를 맞힌다 | 공정 = 스테이션을 도는 순서 | 2-2의 2, [1][6] |
| 2 컵 옮기기 | 컵 디스펜서의 컵을 머신 아래로. 위치를 직접 가르친다(접근점 → 내려가기 → 집기) | 위치 가르치기(티칭), 접근점 | 산업 로봇 티칭 방식, 실습 셀 A와 같음 |
| 3 신호 기다리기 | `추출 끝`을 기다린 뒤 컵을 꺼낸다. 기다리지 않으면 덜 찬 컵 · 흘림 | 인터록 · 핸드셰이크 | 컵 감지 + 상태 기계 [11][12] |
| 4 레시피 | 얼음 → 2샷 → 물 순서와 양. 순서를 바꾸면 결과가 달라진다(얼음 넘침 등) | 레시피 = 순서 + 양 | [13][14] |
| 5 픽업과 안전 | 음료를 픽업대에 놓고 문을 연다. 손님 손이 있으면 기다린다 | 안전문 · 손 감지 · 협동로봇 | [5][6], ISO 10218 · ISO/TS 15066(협동 작업의 힘 · 속도 제한) [15] |
| 6 주문 3잔 | 반복으로 3잔. 추출을 기다리는 동안 다음 컵을 준비하면 빨라진다 | 반복, 사이클 타임, 처리량 | 한 잔 40초~1분 · 시간당 90~120잔 [1][2][4][6] |

## 6. 확인 필요 (만들면서 공식 자료로 다시 볼 것)

- 에스프레소 25~30초 · 1:2 비율의 SCA 공식 문서 번호 [14].
- 비트 처리량 90잔 vs 120잔(자료마다 다름) [1][2].
- 상용 커피 머신이 '컵 없음'일 때 추출을 거부하는지(제품마다 다름). 입문 화면은 결과를 보이려고 흘림으로 표시하고, 개념 카드에 '실제 머신은 컵 센서로 막는다'고 적는다.
- 안전문 방식은 HD현대 사례 보도 기준. 레인보우 제품의 안전 구성은 공개 자료에서 확인 못 함.
