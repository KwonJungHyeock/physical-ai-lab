## 2. 한 로봇 한 PC

**로봇 서버 (조작권)** — `robot-python/server/server.py`

- 화면은 로봇에 보내는 요청마다 이름표를 붙입니다: 탭마다 하나인 번호(`X-Console-Id`)와 이름(`X-Console-Name`, 예: "3번 학생" · "선생님 kim").
- 움직이는 요청(실행 · 관절 이동 · 조그 · 도구 · 영점 · 서보 풀기/고정)을 보낸 PC 가 로봇을 쥡니다. 실행 중일 때와, 마지막 요청 · 실행이 끝난 뒤 15초 동안입니다.
- 그동안 다른 PC 의 움직이는 요청은 거절됩니다: "다른 PC(3번 학생)가 이 로봇을 움직이는 중이에요."
- **정지는 누구든 언제나** 받습니다.
- `/api/state` 에 지금 쥔 PC(`owner`)가 나오고, 다른 PC 화면에는 위쪽에 노란 안내 띠가 뜹니다.
- 이름표가 없는 요청(스크립트 · 옛 화면)은 주소로 구분합니다.
- 이 규칙을 모르는 옛 로봇 서버에는 이름표를 보내지 않습니다. 브라우저의 교차 출처 확인에서 거절되지 않게 하려는 것입니다.

**학급 서버 (조마다 로봇 담당 한 명)** — `desktop-go/classroom/lead.go`

- 같은 조에 두 번째 로봇 담당이 들어오면 거절합니다: "1번이 이미 1조의 로봇 담당이에요. [화면으로 따라오기] 로 들어와요." 이 문장은 참여 창에 그대로 나옵니다.
- 수업에서 나가면 그 자리가 비어, 다른 학생이 로봇 담당을 맡을 수 있습니다.

## 3. 실물 결과를 학급 관리로

로봇 실습 7 에서 실물 단계를 끝내면, 학생 화면은 "실물 결과" 하나를 학급 서버로 보냅니다(로그인한 학생일 때).
결과에는 화면에 보인 문장과 잰 값이 함께 들어갑니다.

| 단원 | 보내는 값 | 학급 관리 표에 보이는 말 |
| --- | --- | --- |
| 7-1 전 축 구동 | 명령과 잰 각도 차이 최대(°), 그 관절 | 차이 최대 0.4° (J3) |
| 7-2 반복 위치제어 | 도착 횟수, 흩어진 폭(mm) | 5번 · 폭 0.6 mm |
| 7-3 영상 취득 | 카메라 수, 사진 크기 | 카메라 2대 |
| 7-4 비전-로봇 연계 | 옮긴 블록 수, 색 | 블록 4개 옮김 |
| 7-5 엔드이펙터 교체 | 그리퍼 · 펌프 | 그리퍼 · 펌프 |
| 7-6 AI 샘플 로컬 실행 | 처리 시간(ms), 찾은 물체 수, 첫 물체 | 412 ms · 3개 |
| 7-7 ROS 2 · API 실행 | 실행한 명령 줄 수 | 12줄 실행 |

- 선생님 화면: 선생님 계정 메뉴 → [학급 관리] → 학급 → [실시간 현황].
  - 학생 카드에 마지막 실물 결과가 한 줄로 나옵니다 (초록).
  - 아래 "로봇 실습 7 · 실물 결과" 표에는 번호 × 7-1 ~ 7-7 이 모입니다. 칸 위에 마우스를 올리면 문장과 시각이 보이고, 머리줄에는 단원마다 한 사람 수가 나옵니다.
- 데모 로봇 서버(연습용 가짜 팔)로 한 결과는 회색 "데모" 로 표시하고, 사람 수에 세지 않습니다.
- 내보내기(CSV)의 "답" 칸에 문장이 들어갑니다. JSON 내보내기에는 잰 값까지 모두 들어갑니다.
- 클라우드 동기화에는 숫자만 가고, 한국어 문장은 빠집니다. 가명 처리 규칙 그대로입니다.
- 학급 서버는 바꾸지 않았습니다. 이미 받던 기록 형식(`operated` + 결과 · 값)을 그대로 씁니다.

## 6. 시연 GIF 다시 찍기

수업 레일의 [▶ 시연] 을 누르면 나오는 GIF 84개(28차시 × 활동 A · B · C)를 지금 화면으로 다시 찍었습니다.

- 찍는 범위: 왼쪽 **수업 레일**(예상 · 해 보기 · 결과)과 오른쪽 **3D 화면**을 함께. 학생이 보는 화면과 같습니다.
- 찍는 방법: 앱을 자동으로 조작해 원고대로 활동을 하고(`web-typescript/tools/check/learn-sim.mjs --clips`), 그동안의 화면을 GIF(폭 800 px, 초당 10장)로 만듭니다.
- 8-2(블록 집어 옮기기, 물리 계산이 무거운 차시)는 처음 방법으로는 찍히지 않았습니다. 장면을 한 장 찍을 때마다 몇 초씩 걸려 물리 계산이 멈췄기 때문입니다. 브라우저가 화면을 그리는 대로 받아 오는 방식으로 바꾸고, GIF 를 두 번에 나눠 만들어 긴 활동(활동 2 는 약 6분)도 메모리가 넘치지 않게 했습니다. 만들다 실패해도 기존 GIF 는 그대로 남습니다.
- 찍으면서 활동마다 결과 숫자를 원고와 대조합니다. 84개 모두 통과했고, 결과가 원고와 다른 활동은 없었습니다.
- GIF 마지막 장면은 결과 칸이 채워진 화면입니다(몇 개를 열어 확인).
- 84개 합계 약 17 MB. 프로그램(exe)과 로봇 USB 키트에 함께 들어갑니다.
