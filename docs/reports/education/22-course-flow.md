# 보고 #22 — 교육 전개 점검과 수정 1~5단계: 이론과 현장을 번갈아, 스스로 생각하게, 실물과 함께

> 교육 과정 전체(이론 28차시, 현장 실습 7곳 21문제, 마무리 평가)를 이론 · 현장 · 흐름 세 갈래로 점검했습니다.
> 그중 **가장 영향이 큰 전개(순서) 문제**부터 고쳤습니다. 기준은 "처음 배우는 사람이 왜 그런지 납득할 수 있는가"입니다.
> 이어서 정확성(2단계), 현장 실습에서 스스로 생각하기(3단계), 대학 Python 과제 · 반 결과(4단계), 실물 연동(5단계)까지 마쳤습니다 — 6장.

**1) 문제마다 "먼저 배울 차시"** — 각 현장 문제에 그 문제를 이해하는 데 꼭 필요한 차시를 정했습니다(원고의 이론 연결에서 골라 최소한으로).

- **지도의 [다음 할 일]** 이 이론과 현장을 번갈아 안내합니다: 차시를 배우면, 그 차시로 열린 현장 문제를 바로 다음에 풀게 합니다(같은 현장은 ① → ② → ③ 순서).

- 로봇 아카데미 카드는 **지금 배우는 단원의 차시**를 보여 주고, 28차시 중 몇 차시를 마쳤는지 표시합니다.
- **고등 경로의 4단원(동역학) 선택 표시를 없앴습니다.** 5단원이 4단원을 전제로 하고, 현장 문제 4개(물류 ②, 시티 ③, 팜 ③, 자원순환 ②)가 4-2 · 4-3을 씁니다.
- 교사의 **[모든 현장 열기]** 는 그대로 — 켜면 모든 현장 · 문제가 열립니다(수업 순서를 교사가 정할 때).

- **잠긴 문제는 숨기지 않고 보여 줍니다.** 학생이 미리 눌러 보면 "무엇을 먼저 배워야 하는지"가 나와, 다음 차시의 동기가 됩니다.
- **로봇이 한 대뿐이면** 현장 문제는 시뮬레이터로 풀고, `실물 확인 · 보충` 시간에 교사가 시연합니다(학생은 결과를 관제센터에 기록).

## 6. 2~5단계에서 바꾼 것

### 2단계 — 정확성

| 1-4 작업 반경 280 mm | 기준점이 원고 · 코드에서 다름 | 손목 중심(J6 축)까지 잰 값으로 통일 |
| 1-3 활동 2 | 1-2의 "롤 = 손끝 축 비틀기"와 정답이 반대로 읽힘 | 두 회전이 바닥에 고정된 축 둘레임을 밝히고 1-2와의 관계 설명 |
| 5-4 토크 제한 | 3 N·m (4-1의 J2 1.57 N·m와 충돌) | 관절 1개 모델 값임을 밝히고 실제 J2 한계 약 1.57 N·m 함께 |

### 3단계 — 현장 실습에서 스스로 생각하게

- **잰 값의 '문제 값' 빨간 표시는 원인을 맞힌 뒤에.** 그 전에는 작업 기준과 직접 견줘 고르게 합니다(안내 문구 있음).
- **계산 칸의 식을 먼저 숨김.** 칸 이름만 보이고, 막히면 칸마다 **[식 보기]** — 본 식과 다시 계산한 횟수가 실습 기록지와 별점에 남습니다.
- **별점**: 힌트 2개 이상(또는 식을 모두 봄), 다시 가동 3번 이상, 원인 · 계산을 3번 이상 틀림 — 각각 별 하나씩. 해결 화면에 "원인 N번째에 찾음 · 계산 다시 N번 · 식 보기 N번 · 힌트 N번 · 다시 가동 N번".
- **마무리 평가**
  - 7문항(⑦ 에너지·자원순환 "캔이 더 무거워졌다" 추가) — 합계 70점, 100점 환산.
  - 힌트는 첫째 −1점, 둘째(거의 답) −2점 — 버튼에 미리 표시.
  - 고치기 조작반은 **계산을 맞혀야** 열림. 막히면 [계산 건너뛰고 고치기](계산 0점). 결과지에 원인 시도 횟수 · 계산 건너뜀 · 힌트를 남김.
  - 이제 현장 7곳을 모두 마치면 열림. 50~70분(2차시).

### 4단계 — 대학 Python 과제 · 반 결과 모으기

- **현장 문제 21개마다 자동 채점 Python 과제.** 대학 과정의 해결 화면에 코드 칸과 [실행·채점]. 함수 하나를 짜면 그 현장의 상황과 숫자를 바꾼 3가지로 채점합니다(예: 팩토리 ③ `catch_plan(belt, wait_y, down_s)`, 시티 ③ `min_turn_time(dq, inertia, tau_max)`, 자원순환 ③ `pick_order(kinds, areas)`).
  - 기댓값은 모두 시뮬레이터 엔진이 계산 — 화면과 어긋날 수 없음.
  - 현장 자신의 상황만 기댓값을 보여 주고, 바꾼 숫자의 기댓값은 맞힐 때까지 숨김(숫자 베끼기로는 통과 못 함).
  - 학생 코드는 시뮬레이터의 Python과 같은 격리 실행기(시간 제한)에서만 돌고, 오류는 줄 번호와 쉬운 설명으로.
- **반 결과 모으기** (서버 없이 파일로)
  - 학생: 지도 오른쪽 카드 아래 **[선생님께 내 결과 내기]** — 이름 · 번호를 적고 내보내면 `<이름>-로봇시티-결과.json`.
  - 교사: 관제센터 **[반 결과]** 탭에서 여러 파일을 한 번에 골라(끌어 놓기도) 반 표로. 번호 · 이름 · 이론 n/28 · 현장 n/21 · 별 · 힌트 · 다시 가동 · 마무리 평가 · 실물 실행 수. **살펴볼 학생**(한 문제를 6번 넘게 실패, 힌트 8개 이상, 평가 60점 미만)을 표시하고, **[CSV로 저장]**(엑셀에서 바로 열림).
  - 파일은 어디로도 보내지 않습니다. 가져온 파일은 모양 · 크기를 엄격히 검사하고, 못 읽은 파일은 이유와 함께 보여 줍니다.
  - 한계: 학생 파일은 서명이 없어 학생이 숫자를 고칠 수 있습니다(서툰 수정만 걸러짐). 성적 근거로는 교사 PC의 마무리 평가 결과지를 함께 보세요.

### 5단계 — 실물 연동 모드

- 로봇이 연결되면 교육 화면 아래에 **[실물 연동]** 스위치. 켜면 **화면의 팔을 실물이 따라** 움직입니다.
  - **이론 차시**: 늘 따라 움직임.
  - **현장 실습**: 값을 고친 뒤 **[다시 가동 · 비교]** 에서 고친 프로그램이 돌 때만(실패하는 처음 프로그램은 실물로 돌리지 않음).
  - **쓰지 않는 곳**: AI 연구소(실물 키트 배치가 화면과 다름), 돌봄 ③(실물에서는 팔이 myAGV 위).
- 안전
  - 측정 각도보다 12° 넘게 앞서지 않는 목표만 보냄 (로봇 서버는 15° 넘으면 거절). 화면이 빨라도 실물은 뒤따라오고, 차이를 "화면과 차이 N°"로 보여 줌.
  - 속도 50 이하(교실 상한), 처음 멀리 있으면 25. 관절 한계 안.
  - 한 걸음마다 책상 · 자기 충돌 검사. 막히거나, 로봇이 거절하거나, 각도를 못 읽으면 즉시 멈추고 이유를 보여 줌.
  - 큰 **[■ 실물 멈춤]** 버튼과 Esc. 화면을 떠나거나 탭이 가려지면 목표가 끊겨 로봇 서버가 1초 안에 멈춤.
  - 펌프 · 그리퍼도 화면을 따라 켜고 끔.
- 한계: 실제 로봇으로는 아직 해 보지 않았습니다(아래 확인 범위 참고).

### 남은 일

1. **실물 연동 · 대학 과제를 실제 로봇 · 수업에서 확인** — 특히 실물 연동은 실제 팔에서 반응 지연과 멈춤을 확인해야 합니다.
2. 교사 가이드(매뉴얼)에 현장 · 관제센터 · 평가 · 주차별 계획 · 반 결과 · 실물 연동을 넣는 일은 피드백이 끝난 뒤.
3. 검토할 것: 반 결과에서 이름 + 번호가 같으면 같은 학생으로 봄(반이 여럿이면 '반' 칸 추가 필요), 마무리 평가의 자체 반 결과표와 관제센터 [반 결과]가 일부 겹침.
