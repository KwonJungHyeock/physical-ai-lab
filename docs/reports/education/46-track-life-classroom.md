# 보고 #46 — 입문 로봇 카페, 교실 수업형으로 바꾸기

2026-11-09. 입문 트랙 ① 생활 로봇의 로봇 카페를 혼자 하는 게임형에서 **교사가 교안으로 이끄는 교실 수업형**으로 바꿨다.
결과는 모두 시뮬레이션 기준이고, 실제 교실에서는 아직 시험하지 않았다.

## 1. 왜

| 피드백 | 그전 상태 |
| --- | --- |
| 집에서 혼자 하기에 맞춰져 있고, 다수 수업에 맞지 않음 | 앞 퀘스트를 통과해야 다음이 열려 반 속도를 맞출 수 없었다. 교사용 기능이 없었다 |
| 무엇을 배우는지가 분명해야 함 | 퀘스트 2~8에 학습 목표 · 개념이 없었다 |
| 교안과 앱의 관계가 쪽마다 정리돼야 함 | 카페 교안 PDF가 없었고, md 지도안은 화면과 맞지 않았다 |
| LMS · 수행평가 · 내려받기가 보여야 함 | 통과 여부만 브라우저에 남았다 |

## 2. 한 원본

`web-typescript/src/engine/simulator/cell/lessons.ts` 하나에 퀘스트마다 학습 목표 · 개념 · 교안 쪽 · 확인 문제 3개, 차시 구성 4 · 6 · 8을 둔다.
앱과 교안 PDF(`tools/build/cafe-lesson.mts`)가 이 파일을 함께 읽어서, 앱의 '교안 6–7쪽' 표시와 교안 쪽 번호가 늘 같다.

| 차시 구성 | 퀘스트 묶음 |
| --- | --- |
| 4차시 | 1 · 2 / 3 · 4 / 5 · 6 / 7 · 8 |
| 6차시 | 1 / 2 · 3 / 4 / 5 · 6 / 7 / 8 |
| 8차시 | 퀘스트 하나씩 |

## 3. 앱 (입문 트랙만, 본 화면 · /console 그대로)

- **차시 판**(▶ 아래): 오늘 배울 것, 교안 쪽, 확인 문제 3개(차시 퀘스트를 다 통과하면 열림), 학습 기록.
- **통과 카드**: 퀘스트 2~8에도 개념 · 실제 현장 · 교안 쪽.
- **학습 기록**(위쪽에 늘 보임): 번호 · 이름, 퀘스트별 통과 · 시도 · 걸린 시간, 확인 문제, 3단계 기준(잘함 · 보통 · 노력), 기록지 인쇄(PDF), 제출 파일.
- **교사 열쇠**(⚙): 차시 구성 · 지금 열 차시 · 모두 열기 · 수업 링크(`/track/life?plan=6&lesson=2`) · 수업 화면(프로젝터) · 반 결과 모으기(표 · CSV) · 이 PC 기록 지우기 · 교안 · 학습지 PDF.
- **장면 정리**: 도구는 처음 시점 하나, 뷰큐브 숨김, 알림은 패널 옆 한 자리, ▶ 옆 ×1 · ×4, 퀘스트 8(14분)은 ×4로 시작, 메뉴 판 '핫' 잘림 고침.

## 4. 기록 모으기 — 서버 없음

학급 서버는 보고 #42에서 지웠다(학교망에서 학생 PC가 교사 PC에 붙지 못하는 경우가 많음). 그래서 본 과정의 반 결과처럼 **파일**로 모은다.
학생이 낸 파일은 믿지 않는다: 크기 · 글자 수 제한, 아는 퀘스트 · 문항만, 확인 문제는 열 때 다시 채점, 같은 학생 둘이면 나중 것, CSV 칸은 수식으로 읽히지 않게 막는다
(`lessonRecord.ts`, 점검 `tests/simulator/lesson-check.mts`). 한계: 실시간으로 반 전체를 보지는 못한다.
