# 보고 #23 — 학급 계정과 학습 기록: 교실 학급 서버 + 클라우드 (하이브리드)

> 결정 사항(대표): 역할이 있는 계정을 둔다. 수업은 **교실 LAN 의 학급 서버**(교사 PC)에서 돌리고, **가명 처리한 학습 기록만** 회사 클라우드로 보낸다.
> 공유기는 회사가 공급하므로 교실 LAN 과 인터넷은 안정적이라고 본다.
> 이 문서는 설계와 1차 구현(엔진 · 학급 서버 · 클라우드 수신기)을 정리한다. 로그인 화면 · 교사 대시보드 · 역할별 화면 가리기는 화면 쪽에서 붙인다(10장).

---

## 1. 구성

```
 학생 PC (크롬·엣지)                    교사 PC = 학급 서버                         회사 클라우드 (선택)
 ┌──────────────────────┐   LAN     ┌──────────────────────────────┐  HTTPS   ┌──────────────────────┐
 │ 앱 (교육·시뮬레이터)  │ ────────▶ │ "Physical AI 시뮬레이터.exe"   │ ───────▶ │ 수신기 desktop-go/cloud│
 │  · 로그인 (코드·번호·PIN)│  JSON    │   -class (교사용 학급 서버)    │ 가명 이벤트 │  · API 키(학교별)      │
 │  · 이벤트 큐(오프라인)  │ ◀──────── │  · 앱 화면 파일 제공(:47290)   │  (5분마다) │  · 추가만 하는 저장     │
 │    localStorage       │  로그인·   │  · 계정 · 학급 · 이벤트 (JSON)  │          │  · 삭제 요청 처리       │
 └──────────────────────┘  열린 차시  │  · 실시간 현황 · 내보내기      │          └──────────────────────┘
   또는 학생 PC 의 exe            │  · 클라우드 동기화 작업자       │
   (127.0.0.1:47280) 가          └──────────────────────────────┘
   교사 PC 주소로 접속             교사 브라우저: 대시보드 + 번호↔이름 표(이 PC 에만)
```

- **학급 서버** = 기존 Windows 프로그램(desktop-go)을 `-class` 로 켠 것. 같은 exe 하나로 시뮬레이터와 학급 서버를 모두 한다.
  배포 zip 에 `교사용 학급 서버.cmd`(옆의 exe 를 `-class` 로 실행)를 넣었다.
- 학생은 두 방법 중 하나로 들어온다. (가) 교사 PC 주소 `http://<교사 PC IP>:47290/console?from=class` 를 브라우저로 연다(설치 없음).
  (나) 학생 PC 의 시뮬레이터 exe 에서 학급 서버 주소를 넣는다(교차 출처 요청, 서버가 `http://127.0.0.1:47280` 만 허용).
- 저장: 교사 PC 의 `%AppData%\PhysicalAI\class-server\` — `db.json`(계정·학급·PIN 해시·세션 해시·동기화 설정, 통째로 원자적 저장),
  `secret.key`(해시 페퍼와 가명 키), `events/<학급>.jsonl`(이벤트, 추가만). 표준 라이브러리만 쓴다(빌드가 그대로).

## 3. 로그인 흐름

**처음 설정 (한 번)** — 학급 서버를 처음 켜면 교사 PC 에 열린 창에서 운영자 계정(아이디 + 8자 이상 비밀번호)을 만든다.
이 요청은 **그 PC 자신(127.0.0.1)에서만** 받는다. 회사 기사가 설치하면 회사가 운영자 계정을 갖고 교사 계정을 발급한다.
교사가 직접 설치했다면 그 교사가 운영자 겸 교사가 된다.

**교사** — 아이디 + 비밀번호 → 세션 토큰(12시간). 학급 만들기(이름은 "2학년 3반" 같은 이름표, 학생 이름 금지) →
학생 N명 일괄 발급 → 서버가 **번호와 4자리 PIN 을 한 번만** 돌려준다(서버에는 해시만) → 화면이 카드(학급 코드 · 번호 · PIN · QR)를 인쇄.
번호↔이름 표는 교사가 붙여 넣으면 **교사 PC 브라우저에만** 저장되고(`roster.ts`), 대시보드와 카드에 이름을 다시 붙인다.

**수강생** — 학급 코드(6자, 헷갈리는 글자 없음) + 번호 + PIN → 세션 토큰(12시간). 이메일 · 실명 없음.
틀리면 "다시 확인", 같은 번호로 5번 틀리면 1분 잠금(잠길 때마다 2배, 최대 1시간), 한 PC 에서 30번 틀리면 그 PC 를 5분 잠금.
잠긴 학생은 교사 현황판에 "잠김"으로 보이고, 교사가 PIN 을 다시 발급하면 풀린다. PIN 을 잊으면 찾지 않고 **다시 발급**한다.

**운영자** — 교사와 같은 로그인. 교사 계정 발급 · 끄기, 클라우드 주소와 API 키 설정(키는 다시 보여 주지 않음, 끝 4자만).

## 4. 끊겼을 때

| 상황 | 동작 |
| --- | --- |
| 학급 서버가 꺼짐 · LAN 끊김 | 학생 화면은 계속 쓸 수 있다. 이벤트는 학생 PC 큐(localStorage)에 쌓이고 2초 → 4초 → … 최대 5분 간격으로(흔들림 포함) 다시 보낸다. 서버가 돌아오면 순서대로 보내고, 같은 이벤트를 두 번 받아도 서버가 id 로 한 번만 저장한다. 큐는 학생마다 따로(같은 PC 의 다음 학생 로그인으로 보내지지 않음), 최대 5000개(넘으면 오래된 것부터 버리고 셈). |
| 새로 로그인할 수 없음 | 서버 없이는 로그인할 수 없다. 로그인하지 않은 앱은 지금처럼 기록 없이 쓸 수 있다. |
| 세션 만료 · 교사가 모두 로그아웃 | 큐가 멈추고(401) 화면이 다시 로그인을 요청. 로그인하면 이어서 보낸다. |
| 인터넷 끊김 (LAN 은 됨) | 수업에는 영향이 없다. 동기화 작업자가 실패를 기록하고 간격을 늘려(최대 1시간) 다시 보낸다. 커서는 성공해야만 넘어간다. |
| 학급 서버 PC 재시작 | 계정 · 학급 · 세션(해시) · 이벤트 · 동기화 커서가 파일에 있어 그대로 이어진다. "접속 중" 표시만 다음 신호까지 비어 있다. |
| `secret.key` 를 잃음 | 서버가 켜지지 않고 이유를 알린다(새 키로 켜지면 모든 PIN 이 틀려지므로). 폴더째 백업. |

## 5. 이벤트 모델 (xAPI 모양)

문장 하나 = 누가(actor) · 했다(verb) · 무엇을(object) + 결과(result) · 맥락(context). 나중에 학교 · 교육청이 LRS 를 요구하면 그대로 보낼 수 있게 모양만 맞췄다.

- **actor**: 클라이언트는 넣지 않는다. 서버가 로그인에서 `{"account":{"homePage":"urn:robocity:class-server:<서버 id>","name":"<학급코드>-<번호>"}}` 를 쓴다(이름 · 이메일 없음, 남의 이름으로 보낼 수 없음).
- **object**: `urn:robocity:lesson:<차시>[:page:<쪽>]` · `urn:robocity:site:<현장>:problem:<n>[:step:<k>]` · `urn:robocity:quiz:<평가>:item:<문항>` · `urn:robocity:robot:<모델>`.
- **context**: 서버가 학급 id 와 번호를 넣는다(`urn:robocity:ctx:class`, `…:no`). 시도 id(registration)는 선택.
- **result**: 성공 · 점수 · 답(500자까지) · 걸린 시간(ISO 8601) · 실습 값(`urn:robocity:val:<이름>`, 16개까지).
- 서버가 `stored`(받은 시각)와 `seq`(학급 안 순번)를 붙인다. 현황판은 학생 PC 시계 대신 `stored` 를 쓴다.

**동사와 공개 목적** (서버 `GET /class-api/v1/purposes` 로도 공개)

| 동사 | id | 언제 | 목적 | 클라우드 |
| --- | --- | --- | --- | --- |
| experienced | ADL | 수업 페이지를 열 때 | 진도, 교사 화면의 "지금 어디" | ○ |
| attempted | ADL | 차시 · 현장 문제를 시작할 때 | 진도, "지금 어디" | ○ |
| answered | ADL | 예상 · 질문 · 평가 문항에 답할 때 | 교사 피드백, 자주 틀리는 생각 찾기 | ○ (선택지 같은 짧은 값만) |
| completed | ADL | 단계 · 차시를 마칠 때 | 진도, 학급 결과 | ○ |
| passed / failed | ADL | 문제 실행 · 평가 결과 | 성취 확인, 같은 문제에서 막힌 학생 알림 | ○ |
| hinted | 자체 `urn:robocity:verb:hinted` | 힌트를 열 때 | 막힘 감지, 힌트 개선 | ○ |
| ran | 자체 | 시뮬레이터에서 실행할 때 | 활동량 | ○ |
| operated | 자체 | 실물 로봇에서 실행할 때 | 로봇 사용 현황, 안전 관리 | ○ |

서버는 목록에 없는 동사, 형식이 다른 대상 id, 너무 큰 문장(4 KB), 90일보다 오래되거나 하루 넘게 앞선 시각을 받지 않는다.

**실시간 현황 규칙** (서버 `/live` 와 엔진 `live.ts` 가 같음): 지금 어디 = 마지막 이벤트의 대상 ·
막힘 = 같은 대상을 마지막 통과 뒤 N번(기본 3) 실패 · 쉬는 중 = 접속 중이지만 M분(기본 5) 동안 이벤트 없음 ·
접속 끊김 = 2분 동안 아무 신호 없음 · 아직 안 들어옴 · PIN 잠김. 칸(학생 × 차시)은 없음 / 시작 / 완료 / 막힘.

## 6. 어디에 무엇이 남는가

| 자료 | 학생 PC | 교사 PC (학급 서버) | 클라우드 |
| --- | --- | --- | --- |
| 학생 이름 | — | **교사 브라우저의 번호↔이름 표만** (서버 파일에는 없음) | **절대 없음** |
| 번호 · 학급 코드 · 학급 이름 | 로그인 세션 | ○ | **없음** (HMAC 가명으로 바뀜) |
| PIN · 비밀번호 | — (입력만) | PBKDF2 해시 + 소금 + 페퍼 | 없음 |
| 이벤트 | 보내기 전 큐 | ○ 전부 | 가명 이벤트 (아래) |
| 서술형 답 | 큐 | ○ (교사만 봄) | **없음** (선택지 번호 · 숫자 같은 32자 이하 코드만) |
| IP 주소 | — | 요청 로그(화면)에만, 파일에 저장 안 함 | 없음 |

**클라우드로 가는 것**: actor = `HMAC(서버 비밀키, 학급id/번호)` 20자, 학급 = HMAC 16자, 동사 · 대상 · 성공 · 점수 · 시간 · 짧은 코드 값 · 시각.
가명 키는 교사 PC 의 `secret.key` 에만 있어서 **회사는 가명을 사람으로 되돌릴 수 없다**. 같은 학생은 같은 가명이라 통계와 연구는 된다.
학생 삭제 · 학급 삭제는 클라우드로 **삭제 요청**이 가고, 수신기가 해당 가명의 기록을 지우고 삭제 기록을 남긴다.
동기화는 운영자가 주소와 키를 넣어 켜기 전에는 꺼져 있다. 주소는 `https://` 만(시험용 127.0.0.1 제외).

## 7. 보안 메모

- 비밀은 저장하지 않는다: PIN(PBKDF2-SHA256 10만 회) · 비밀번호(60만 회), 16바이트 소금, `secret.key` 페퍼. 세션 토큰은 32바이트 난수, 파일에는 SHA-256 만.
  4자리 PIN 은 1만 가지라 해시만으로는 오프라인 대입을 못 막는다 → 페퍼를 db.json 과 나눠 두고, 온라인 대입은 잠금으로 막는다.
- 모르는 번호 · 아이디도 같은 시간이 걸리게 가짜 해시를 검사(계정 존재 여부가 시간으로 새지 않음).
- LAN 전용: 사설 · 링크로컬 · 자기 PC 주소의 요청만 받는다. Host 가 IP · localhost · `*.local` 이 아니면 거절(DNS 리바인딩 방지).
- CORS: 같은 출처와 학생 exe(`http://127.0.0.1:47280`)만. 쿠키 없이 Bearer 토큰만 써서 다른 웹페이지가 대신 요청할 수 없다.
- 요청 로그에는 방법 · 경로 · 상태만(본문 없음 → PIN · 비밀번호가 로그에 남지 않음). 요청 본문 1 MB, 이벤트 묶음 100개, 학생당 5분에 1500개 제한(넘으면 429 → 큐가 나중에 다시 보냄).
- 내보낸 CSV 는 `= + - @` 로 시작하는 칸 앞에 `'` 를 붙여 엑셀 수식 실행을 막는다. UTF-8 BOM 으로 한글이 깨지지 않는다.
- 남은 위험: 교실 LAN 은 평문 HTTP(같은 공유기 안 도청 가능) — 회사 공유기에서 학생 Wi-Fi 격리(AP isolation)는 끄되 손님망과 분리할 것.
  교사 PC 를 잃어버리면 db.json + secret.key 가 함께 나갈 수 있다 → Windows 계정 암호 · BitLocker 권장.

## 9. 클라우드 수신기 (참고 구현) — `desktop-go/cloud/`

- `POST /v1/sync` (Authorization: Bearer <학교별 키>) 로 가명 이벤트 묶음을 받아 `<data>/<학교>/<서버>/statements-YYYY-MM.jsonl` 에 **추가만** 한다.
  같은 묶음 id 가 다시 오면 무시. 가명이 아닌 actor, 번호가 든 문장은 거절, 서술형 답은 한 번 더 걸러 버린다.
- 삭제 요청은 해당 가명의 줄을 지우고 `deletions.jsonl` 에 기록. `GET /healthz`.
- 실행: `ROBOCITY_API_KEYS="school-a:<32자 이상 난수>,…" go run ./cloud -addr 127.0.0.1:8080 -data /var/lib/robocity` (desktop-go 폴더에서).
  앞에 HTTPS 리버스 프록시(Caddy 가 가장 간단: 도메인만 적으면 인증서 자동)를 둔다.
- 호스팅은 아직 정하지 않음. **국내 리전(NCP · KT Cloud · NHN Cloud)의 작은 VM 1대 + 디스크 백업**이 가장 마찰이 적다
  (교육청 단위 조달이면 CSAP 인증 IaaS 위가 사실상 요구됨). 나중에 LRS(예: SQL LRS)가 필요하면 jsonl 을 그대로 넣으면 된다.

## 10. 화면 쪽 연결 (교육 화면 개편과 함께)

엔진: `web-typescript/src/engine/account/` (React 없음). 학급 서버 API: `/class-api/v1/…` (`desktop-go/classroom/server.go` 머리 주석의 표).

- 서버 찾기: `resolveServer({ pageOrigin: location.origin, saved: savedServerAddress(localStorage) })` → 없으면 주소 입력(`normalizeServerAddress`) 또는 QR(`joinParams(location.search)`).
- 학생: `client.loginStudent(code, no, pin)` → `saveSession` → `new EventQueue({ key: queueKeyFor(s.student), store: browserStore(), send: client.sender() })` + `autoFlush(queue)`.
  화면 곳곳에서 `queue.push(events.pageOpened(…))` 등. `lessonOpen(session, id)` 로 닫힌 차시를 잠근다. 401 이면 `queue.state().authNeeded` → 다시 로그인 → `queue.resume()`.
- 교사 대시보드: `client.classes()` → 학급 선택 → 3~5초마다 `client.events(id, state.lastSeq)` → `applyStatements` → `liveRows(state, cls.students, Date.now())` + `withNames(rows, loadRoster(...))`.
  잠김 표시는 `client.live(id)` 의 `locked`. 칸 표시는 `cellStatus`. 이름표 `placeLabel`.
- 발급: `client.issueStudents(id, n)` → `loginCards(cls, issued, roster, joinLink(base, cls.code))` 를 바로 인쇄(PIN 은 다시 볼 수 없음).
- 교사용 내용 가리기: `can(session?.role, 'seeTeacherContent')`.

### 10-1. 붙인 화면 — `web-typescript/src/ui/account/`

| 모드 | 언제 | 화면 |
| --- | --- | --- |
| 자유 모드 (기본) | 학급 서버도 로그인도 없을 때 (시연 · 시뮬레이터 exe · 로봇 콘솔) | 지금과 똑같다. 로그인 벽 없음, 기록 안 함. 설정(톱니) 메뉴의 **학급 로그인**으로 언제든 들어갈 수 있다. |
| 학급 모드 | 학급 서버가 연 페이지(`?from=class`, 포트 47290), 참여 링크(`?server=…&class=…`), 저장된 로그인, 이 PC 에서 로그아웃하지 않은 로그인 | 콘솔이 교육 탭으로 열리고, 교육 탭이 로그인 화면이 된다(학생: 학급 코드 + 번호 + PIN · 선생님: 아이디 + 비밀번호). 시뮬레이터 · 라이브러리 탭은 로그인 없이 쓴다. |
| 처음 설정 | 새 학급 서버(`needsSetup`)를 그 PC(127.0.0.1)에서 열었을 때 | 같은 자리에 "관리자 계정 만들기" — 만들면 바로 학급 관리가 열린다. 다른 PC 에서는 "학급 서버 PC 에서 먼저 설정" 안내만. |

- **로그인** (`LoginPanel` — 교육 탭 화면과 대화상자가 같이 씀): 큰 입력칸, 번호 · PIN 은 숫자 키패드, PIN 보기/가리기. 참여 링크의 학급 코드를 미리 채운다.
  서버를 못 찾으면 주소 입력칸(`normalizeServerAddress`, 예: 192.168.0.10). 오류는 한 문장으로: 틀림("카드를 다시 확인") · 잠김("14:05 에 풀려요 (약 3분 뒤)") · 서버 연결 안 됨.
  PIN · 비밀번호는 입력칸에만 있고 시도마다 지운다.
- **계정 칩** (상단 바, 로봇 연결 왼쪽): 학생은 "3번 학생 · 기록 저장됨 / 보내는 중 · 3개 / 연결 끊김 · 12개 기다리는 중 / 다시 로그인 필요", 선생님은 아이디 · 역할.
  메뉴: 학급 관리(교사 · 운영자), 다시 로그인, 로그아웃(학생 로그아웃 때 남은 기록을 2초 동안 한 번 더 보내 본다).
- **역할별 가리기**: 학생은 수업 카드의 "교사용 보기" 단추와 교사 블록, 지도의 "모든 현장 열기", 설정의 "검수 시연"이 보이지 않는다. 자유 모드와 교사 · 운영자는 지금처럼.
- **닫힌 차시**: 학생이 선생님이 열지 않은 차시를 열면(지도 · 전체 차시 · 다음 차시 어디서든) "선생님이 아직 열지 않은 차시예요" 창이 뜨고 [열렸는지 다시 확인]이 있다.
  학생 화면은 15초마다(그리고 창으로 돌아올 때) 학급 정보를 다시 받아 열린 차시를 맞춘다. 이 요청이 교사 현황판의 "접속 중" 신호도 된다.
- **학습 이벤트** (학생만, `track()` → `EventQueue` + `autoFlush` 3초): 수업 페이지 열기(experienced), 차시 시작(attempted), 활동 결과 · 차시 마침(completed),
  확인 문제 답(answered: O/X · 보기 번호) · 한 회 점수(passed/failed), 현장 실습 가동 시작(attempted) · 힌트(hinted) · 실행 결과(passed/failed: 걸린 시간 · 고친 값 — `runLog.logRun` 의 이벤트를 받아서),
  실물 연동 시작 · 실제 로봇 결과 기록(operated). 401 이면 큐가 멈추고 "다시 로그인" 창을 한 번 띄운다(닫아도 실습은 계속). 다시 로그인하면 `queue.resume()`.
- **학급 관리** (교사 · 운영자, 상단 바 아래 전체 화면, Esc 또는 [← 수업 화면으로]):
  왼쪽 학급 목록(운영자는 모든 학급) · 새 학급 · 보관한 학급, 운영자는 **교사 계정**(만들기 · 끄기 · 비밀번호 바꾸기)과 **클라우드 동기화**(처음엔 꺼짐, https 주소 + 키 — 키는 끝 4자만 다시 보임, 간격, 지금 보내기, 마지막 성공 · 오류).
  학급마다 학급 코드 · 학생 접속 주소(서버 PC 에서 보면 `/status` 의 LAN 주소) · CSV 내보내기 · 학생 모두 로그아웃 · 보관(보관한 학급은 코드를 다시 적어야 삭제) 그리고 네 탭:
  - **실시간 현황**: 4초마다 이벤트 피드(`applyStatements`) + `/live`(PIN 잠김 · 접속 신호) → `liveRows` + 이 PC 의 이름표. 학생 카드에 지금 어디(차시 · 쪽, 현장 문제, 확인 문제) · 마지막 활동 · 마침 · 통과 · 힌트,
    막힘(같은 문제 3번 실패)은 빨간 줄로 어느 문제인지까지. 위의 개수 단추(수업 중 · 막힘 · 쉬는 중 · 오프라인 · 아직 안 들어옴 · 잠김)로 거른다. 잠긴 학생 카드에는 [PIN 다시 발급].
  - **학생 · PIN**: "학생 N명 새로 만들기" → 로그인 카드가 바로 뜬다(학급 코드 · 번호 · PIN · 이름(이 PC 의 이름표에 있으면) · 접속 주소). "PIN 은 지금만 볼 수 있어요" 안내, [인쇄하기](카드만 인쇄), 닫기는 두 번 눌러야 닫힌다. 번호별 PIN 다시 발급 · 삭제(기록도 지워짐을 알림).
  - **차시 열기**: 모든 차시 / 고른 차시만(단원별 묶음 체크). 학생 화면에는 15초 안에 반영.
  - **이름표**: "번호,이름"을 붙여 넣기(엑셀 두 칸 복사 가능) → 이 브라우저에만 저장(`roster.ts`). "이름은 이 PC 에만 저장돼요" 안내, CSV 로 받기, 이 PC 에서 지우기.
- **개발용 출처**: `desktop-go -class -dev-origin http://localhost:3000` 으로 켜면 그 PC 의 개발 서버 화면에서 API 를 부를 수 있다(루프백 http 출처만, 그 PC 에서 온 요청만, 기본은 꺼짐 — `TestDevOrigin`).
