# 보고 #41 — 다른 로봇팔 OMX-F · 말로 만들기 (AI)

2026-10-25. 의논에서 정한 순서대로 두 가지를 넣었다.

- **OMX-F**: ① 3D 모델과 ② 시뮬레이터 조작까지. 실물 연결(③)과 모방 학습(④)은 다음 단계로 미룬다.
- **말로 만들기 (AI)**: 학생이 말로 적으면 AI 가 블록 줄을 만든다. 학생이 확인해 넣고, 시뮬레이션을 통과한 뒤에만 로봇이 움직인다.
  AI 는 로봇을 직접 움직이지 않는다. API 키 발급과 실제 키로 하는 평가(⑤)는 나중에 한다.

## 2. 말로 만들기 (AI)

### 흐름

1. 학생이 코딩 › 블록 위의 **말로 만들기** 칸에 할 일을 적는다. 예: "빨간 블록 집어서 1번 자리에 놔".
2. 학생 PC 는 문장과 장면 정보를 **학급 서버(선생님 PC)** 로 보낸다. 장면 정보는 팔 · 관절 범위 · 도구 · 책상 위 자리 이름 · 저장한 자세 이름 · 지금 프로그램이다.
3. 학급 서버가 Claude API 를 부른다. 답은 `{ok, lines, explain}` JSON 으로만 받는다(구조화 출력).
4. 학생 PC 는 받은 줄을 **블록 편집기와 같은 파서 · 검사**로 확인한 뒤 미리 보기로 보여 준다.
5. 학생이 **[블록에 넣기]** 를 누르면 편집기의 블록만 바뀐다. 실행은 늘 하던 대로 [시뮬레이션] → 통과 → 로봇 순서다.

### 안전장치

| 위험 | 막는 곳 |
|---|---|
| AI 가 로봇을 직접 움직임 | 길이 없음. 답은 블록 줄일 뿐이고, 넣은 뒤에도 시뮬레이션 통과가 먼저 |
| 블록에 없는 명령 · Python 코드 | 서버가 여러 줄 · 빈 답을 거절(502). 학생 PC 의 블록 검사가 다시 거름. 걸린 줄은 주황으로 표시하고 [블록에 넣기] 를 막음 |
| 도구 · 자리와 맞지 않는 동작 | 같은 블록 검사(예: 도구 없이 집기). [다시 만들기] 는 검사 결과를 붙여 한 번 더 묻음 |
| 키 유출 | 키는 선생님 PC 의 학급 서버 기록에만 둔다. 화면에는 앞뒤 몇 글자만 보임. 운영자만 넣고 바꿈. 오류 기록에도 키를 남기지 않음 |
| 비용 · 남용 | 학생 한 명 하루 횟수(기본 30, 1~200), 같은 학생 3초 간격, 동시에 8개까지. 실패한 질문은 횟수에서 돌려줌 |
| 엉뚱한 부탁 | 시스템 지시로 블록 언어 밖 요청은 `ok: false` 와 다른 말 제안으로 답하게 함. 거절 응답(refusal)도 같은 모양으로 |
| 수업 뒤 확인 | 학급별 기록(`llm/<학급>.jsonl`): 누가 · 언제 · 무슨 말 · 만든 줄 · 넣었는지. 학급 관리 › 말로 만들기 (AI) 에서 봄 |

### 모델

| 모델 | 쓰임 | 가격 (입력 / 출력, 100만 토큰당) |
|---|---|---|
| Claude Haiku 5.5 | 기본값. 빠르고 저렴 | $0.10 / $0.50 |
| Claude Opus 5.5 | 헷갈리는 말을 더 잘 알아들음 | $4 / $20 |

운영자가 학급 관리에서 바꾼다. 시스템 지시(블록 언어 표 · 규칙 · 예 4개)는 프롬프트 캐시로 묶어 질문마다 다시 내지 않게 했다.
학급 관리 화면은 오늘 쓴 토큰과 대략의 비용을 보여 준다.

### 이 PC 의 Ollama (시연용, 10월 25일 추가)

API 키가 나오기 전 시연과, 인터넷이 없는 교실을 위해 AI 종류를 하나 더 두었다 (`desktop-go/classroom/llm_local.go`).

- 학급 관리의 **AI 종류**: Claude / 이 PC 의 Ollama. 운영자만 바꾼다. Ollama 는 주소(기본 `http://127.0.0.1:11434`)와 모델을 고른다.
  [모델 찾기] 는 Ollama 의 `/api/tags` 로 받아 둔 모델을 보여 준다.
- 질문은 Ollama 의 `/api/chat` 로 보낸다. 시스템 지시와 답 형식(JSON 스키마를 `format` 으로)은 Claude 와 같고, 생각하기(`think`)는 끈다.
  `think` 를 모르는 Ollama 는 한 번 더 그것 없이 묻는다. 기다리는 시간은 150초 (Claude 45초).
- 학생 화면은 같다. 기다리는 동안 "선생님 PC 의 AI 라 조금 걸릴 수 있어요" 를 붙인다. 기록에는 `ollama:<모델>` 로 남는다.
- 작은 로컬 모델은 애매한 말을 더 자주 틀릴 것으로 본다(측정 전). 틀린 줄은 블록 검사가 막으므로 안전은 같다.
- 확인: 가짜 Ollama 로 Go 시험(모델 찾기 · 설정 · 질문 모양 · think 재시도 · 잘못된 답) + 브라우저(선생님 설정 → 학생 질문 → 블록 넣기).
  실제 Ollama 는 이 작업 환경에서 받을 수 없어 사용자 PC 에서 처음 확인한다.

### AI 버튼 — 시뮬레이터에서 바로 (10월 25일 추가, 이 PC 의 Ollama 만)

학급 서버 · 로그인 · 선생님 설정 없이, 시뮬레이터 프로그램(exe)이 같은 PC 의 Ollama 에 바로 묻는다 (`desktop-go/localai.go`, `classroom.AskOllama`).

- **어디에 보이나**: PC 프로그램으로 열었을 때, 블록으로 다룰 수 있는 장면에서만 — 기본 작업대 · AI 키트, 블록(초급) 수준.
  공정 짜기 · 실습 셀 A~E · Python/ROS 2 수준 · 검수 시연 · 데모 재생 중에는 숨는다. 3D 화면 아래 가운데, 다시 보기 막대가 뜨면 그 위로.
- **흐름**: 말하기 → 블록 미리보기(블록 검사) → **[▶ 해 보기]** = 블록 편집기에 넣고 곧바로 시뮬레이션. [블록만 넣기] · [다시 만들기] · ↶ 되돌리기.
  빈 책상에서 블록을 집는 프로그램이면 공정 짜기처럼 실습 매트와 블록을 꺼낸다. 실물 로봇은 지금처럼 시뮬레이션 통과 뒤 [로봇 실행] 으로만.
- **모델**: Ollama 에 받아 둔 모델 중 고르고(이 PC 에 기억), 처음에는 Qwen 3 를 고른다. Ollama 가 꺼져 있거나 모델이 없으면 설치 · 받는 법과 [다시 찾기].
- 확인: Go 시험(가짜 Ollama) + 리눅스로 빌드한 같은 프로그램과 브라우저로 버튼 → 답 → [해 보기] → 블록 집기까지, 공정 짜기에서 버튼이 숨는 것.

### 확인

- Go: `desktop-go/classroom/llm_test.go` — 가짜 Messages API 로 실제 SDK 경로(요청 모양 · 캐시 표시 · 구조화 출력 · 키 · 횟수 · 간격 · 거절 · 오류 · 기록)를 시험.
- TS: `npm run check:speak` — 모든 팔 · 테마 · 도구에서 장면 정보가 서버 한도 안인지, 시스템 지시의 예가 블록 파서를 통과하는지, 표의 명령이 블록 언어에 다 있는지, 잘못된 답이 걸리는지.
- 브라우저: 가짜 Claude 서버 + 실제 학급 서버로 학생 흐름(넣기 · 못 만듦 · 검사에서 걸림)과 선생님 화면을 확인.
