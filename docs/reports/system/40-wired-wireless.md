# 보고 #40 — 로봇 연결 환경: 무선 / 유선 두 갈래

2026-10-24. 새 매뉴얼(교사용 · 학생용)을 쓰기 전에, 로봇을 PC 에 잇는 길을 **무선(USB 로 설정)** 과 **유선(LAN 포트)** 두 갈래로 정리했다.

> **2026-10-27 바뀜 — 로봇 핫스팟(②)을 없앴다.** 제조사 핫스팟(hostapd)이 한 번 켜지면 wpa_supplicant 를 막고 wlan0 을
> NetworkManager 에서 떼어 놓아, 교실 Wi-Fi 연결이 "No suitable device found" · "device not ready" 로 실패했다.
> 이제 USB 키트 설치(`install.py` 4단계)와 eduino-usb 서비스, 켤 때마다(`eduino-wifi.service`) `wifi.py retire_hotspot()` 이
> 핫스팟을 끄고(`hotspot_off.sh`), 로그인 자동 실행을 이름만 바꿔 두고, isc-dhcp-server 를 끄고, wlan0 을 NetworkManager 에 돌려준다.
> 교실 Wi-Fi 가 없으면 핫스팟으로 넘어가지 않고 계속 찾는다(랜선 직결은 늘 됨). `와이파이=핫스팟` · `wifi.py --hotspot` ·
> `/api/wifi/hotspot` · USB 만들기의 [로봇 핫스팟] · 로봇 Wi-Fi 탭의 [핫스팟으로 돌아가기] 는 없앴다. 아래 표의 ② 는 기록으로 둔다.

## 연결하는 길 넷

| 길 | 이렇게 이어요 | 설정 | 상태 |
|---|---|---|---|
| ① 교실 Wi-Fi | PC ~ 공유기 ~ 로봇 | USB 의 `wifi.txt` 에 `와이파이=이름` | 전과 같음 |
| ② 로봇 핫스팟 | PC ~ 로봇 (로봇이 Wi-Fi 를 냄) | `와이파이=핫스팟` (또는 Wi-Fi 설정 없음) | 전과 같음 |
| ③ 유선 · 공유기 경유 | PC — 공유기/허브 — 로봇 | 랜선만 꽂기. 로봇 LAN 포트가 주소를 받음 | 안내 · 결과 파일 추가 |
| ④ 유선 · PC 직결 | PC — 랜선 1개 — 로봇 | 설정 없음. 1분 뒤 연결 창 **[유선 직결]** | **새로 됨** |

## 바뀐 것

- **직결 주소** (`robot-python/server/lan.py`): 로봇 LAN 포트에 늘 `169.254.127.10/16` 을 함께 붙인다 (공유기에서 받는 주소는 그대로).
  공유기 없이 랜선 하나로 이으면 Windows 가 스스로 169.254.x.y 주소를 잡으므로 PC 설정이 필요 없다.
  link-local 주소라 학교망에 꽂아도 다른 기기에 영향이 없고, 로봇이 주소를 나눠 주지도 않는다.
  eduino-usb 서비스(root)가 켜질 때와 몇 초마다 확인해 빠졌으면 다시 붙인다.
- **`와이파이=끔`** (`wifi.py --off`): 유선만 쓰는 교실에서 로봇 핫스팟을 켜지 않고 무선을 끈다. 켤 때(eduino-wifi.service)도 꺼진 채로.
  다시 켜려면 `와이파이=` 에 Wi-Fi 이름이나 `핫스팟` 을 적어 꽂는다. 빈 `와이파이=` 는 이제 "그대로"(실패가 아님).
- **결과 파일 주소**: `주소: 무선 192.168.0.52 · 유선 192.168.0.61 · 직결 169.254.127.10`. 로봇 ID 는 직결 주소에서 따오지 않는다.
- **PC 프로그램**: 연결 창에 **[유선 직결]** 탭(3단계 안내 + 연결 버튼 + 직결 전용 오류 안내). [로봇 찾기] 는 공유기 범위와 함께 직결 주소도 묻는다.
  로봇 USB 만들기에 **연결 방법** 고르기: 교실 Wi-Fi · 로봇 핫스팟 · 유선만(Wi-Fi 끔). 로봇 결과 보기에 주소를 종류와 함께 보여 준다.
