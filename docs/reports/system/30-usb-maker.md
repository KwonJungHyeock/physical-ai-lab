# 보고 #30 — 로봇 USB 만들기: 시뮬레이터 프로그램 하나로

작성: 2026-10-14

"시뮬레이션과 USB 준비를 프로그램으로 만드는 게 더 편할까?" 에 대한 답과, 그대로 만든 결과입니다.
결론은 **따로 프로그램을 하나 더 만들지 않고, 이미 나눠 주는 시뮬레이터 프로그램(exe) 안에 넣는 것**입니다.
선생님이 받는 파일은 하나가 되고, USB 는 칸 세 개를 채우고 버튼 하나로 만듭니다.

## 1. 전과 후

| 할 일 | 전 (zip + 메모장) | 후 (프로그램) |
| --- | --- | --- |
| 받을 파일 | 시뮬레이터 zip, USB 키트 zip 두 개 (버전이 어긋날 수 있음) | 시뮬레이터 zip 하나. 로봇 키트가 프로그램 안에 들어 있음 |
| USB 에 넣기 | 압축을 풀어 `eduino` 폴더를 USB 맨 위에 복사 (폴더 층을 틀리기 쉬움) | ⚙ → [로봇 USB 만들기] → 꽂은 USB 가 저절로 골라짐 → [USB 만들기] |
| Wi-Fi 적기 | `wifi.txt` 를 메모장으로 고침 (양식 · 띄어쓰기 실수) | 칸에 적기. **이 PC 의 Wi-Fi 이름이 미리 들어 있음.** 틀린 값은 이유가 바로 보임 |
| 꺼내기 | Windows 작업 표시줄에서 | [USB 꺼내기] |
| 결과 보기 | USB 의 `result-….txt` 를 하나씩 열기 | USB 를 다시 꽂으면 로봇마다 한 줄: 사용자 · 로봇 ID · 주소 · 실패 이유, 성공한 로봇은 [연결] |
| 로봇을 못 찾을 때 | 매뉴얼을 찾아보기 | 로봇 찾기 창에 "로봇이 아직 이 Wi-Fi 에 없나요?" → 바로 USB 만들기 |

그대로인 것: 새 로봇은 **처음 한 번** 로봇에서 `설치하기` 더블클릭(또는 명령 한 줄)과 로봇 비밀번호가 필요합니다.
리눅스는 USB 를 꽂는 것만으로 프로그램이 실행되지 않게 막아 두었기 때문입니다(보안). 그 뒤로는 꽂기만 하면 됩니다.

## 2. 화면

⚙ 설정 → **[로봇 USB 만들기]** (시뮬레이터 프로그램에서만 보이고, 학생 계정에는 보이지 않습니다)

1. **USB 고르기**: 꽂힌 USB 가 이름 · 빈 곳 · 상태(키트 있음 날짜 / 키트 없음 / 공간 모자람 / 로봇 결과 N)와 함께 나옵니다. 하나면 저절로 골라집니다. 2초마다 다시 보므로 꽂으면 바로 나타납니다.
2. **로봇이 붙을 Wi-Fi**: Wi-Fi 이름(이 PC 의 Wi-Fi, 또는 이 USB 에 적혀 있던 것) · 비밀번호(보기/숨기기) · 사용자(선택, 24자).
   비밀번호 7자, 앞뒤 빈칸, `#` 로 시작하는 이름 같은 것은 버튼이 잠기고 이유가 나옵니다(로봇이 읽는 규칙 그대로).
3. **[USB 만들기]**: 진행 막대(1~3분). 끝나면 다음 할 일 4가지 — [USB 꺼내기], 로봇에 꽂기, 새 로봇이면 처음 한 번(명령 한 줄 [복사]), 결과 보기.
4. **[로봇 결과 보기]**: 로봇에 꽂았던 USB 를 다시 꽂으면 이 탭으로 열립니다. "로봇 3대 · 연결 2대 · 실패 1대" 와 로봇마다 한 줄.

그림: 「시뮬레이터 사용 매뉴얼」 10장 (그림 41~44).

## 3. 만든 것

| 부분 | 파일 | 하는 일 |
| --- | --- | --- |
| 프로그램 (Go) | `desktop-go/usbkit.go` | 키트를 프로그램 안에 넣고, USB 에 `eduino/` 를 쓰고 `wifi.txt` 를 채움 (주석 · 메모장용 BOM · CRLF 그대로). 파일마다 옆에 쓴 뒤 옮겨, 중간에 빼도 반쪽 파일이 남지 않음. 예전 결과는 `지난 결과/` 로, PC 프로그램(Physical AI Tool.html)에 적힌 로봇 목록은 그대로 |
| | `desktop-go/usbdrives_windows.go` | Windows: 이동식 드라이브 목록(Windows 드라이브는 빼고), 빈 곳, 이 PC 의 Wi-Fi 이름 · 저장된 비밀번호(netsh, 한글 Windows 코드페이지 변환), 꺼내기 |
| 빌드 | `desktop-go/build.sh` | `EDUINO_SIGNING_KEY` 가 있으면 서명된 키트를 만들어 넣음 (`KIT=…` 로 만든 것을 넣을 수도) |
| 화면 | `web-typescript/src/ui/simulator/connect/UsbMaker.tsx`, `src/engine/simulator/usbKit.ts` | 위 2장. 결과 파일 읽기 · 입력 검사는 엔진에 |
| 로봇 쪽 | (바꾸지 않음) | `usb_setup.py` 가 읽는 `wifi.txt`, `kit_update.py` 가 확인하는 서명 그대로 |

**안전**: USB 를 쓰는 요청은 이 PC(127.0.0.1) 에서, 이 프로그램 주소로, 이 프로그램 화면이 붙이는 머리글이 있을 때만 받습니다.
학급 서버 모드(같은 공유기의 학생 PC 가 접속)에는 이 기능이 없습니다. 고를 수 있는 USB 도 프로그램이 찾은 것만입니다(화면이 경로를 보낼 수 없음).

## 4. 확인한 것

| 점검 | 결과 |
| --- | --- |
| `go test` (desktop-go) | 통과. `wifi.txt` 채우기 ↔ 읽기, 입력 검사 11가지, USB 쓰기 · 예전 결과 옮기기 · 로봇 목록 지키기 · 키트 밖 경로 거부, 공간 모자람, API (머리글 없음 · 다른 주소 거부), **로봇의 `usb_setup.read_fields` 로 읽어 같은 값인지** |
| `npm run check:usb` | 결과 파일 읽기(성공 · 실패 · 그대로 · 깨진 파일), 입력 검사, 날짜 · 크기 표시 |
| 실제 화면 (`tools/check/usb-maker.mjs`, 프로그램을 리눅스용으로 빌드해 폴더를 USB 로) | 22가지 모두 통과: Wi-Fi 미리 채움, USB 저절로 고름, 비밀번호 7자 잠김 · 이유, 만들기 → 다 됐어요, 창 밖으로 넘침 없음, 로봇이 읽는 `wifi.txt`, **키트 서명 확인 (`kit_update.verify`)**, USB 의 파일들, 로봇 결과 2개(성공 · 실패) 표시, [연결] → 그 로봇 확인, 다시 만들면 예전 결과 2개 옮김, 로봇을 못 찾으면 안내 → USB 만들기 열림, 페이지 오류 0 |
| Windows 부분 | `GOOS=windows go vet` 통과. 실제 Windows PC · 실제 USB 에서 한 번 해 보는 일은 남았습니다 (아래) |

## 5. 남은 것

- **실제 Windows PC + USB 메모리로 한 번** 해 보기: 드라이브 목록, 꺼내기, 이 PC 의 Wi-Fi 비밀번호 미리 채우기(Windows 설정에 따라 비밀번호는 비어 나올 수 있음 — 그때는 적으면 됨).
- 프로그램이 약 100 MB 커졌습니다(zip 약 95 MB → 약 190 MB). 로봇 프로그램이 함께 들어가기 때문입니다.
- 이 밖의 남은 일(실제 교실 Wi-Fi 부하, 흡착 펌프 배선 확인, ROS 2 실행 위치 결정)은 보고 #29 와 같습니다.
