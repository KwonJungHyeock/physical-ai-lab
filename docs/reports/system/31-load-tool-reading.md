# 보고 #31 — 학급 서버 부하 시험 · 그리퍼 불일치 안내 · 쉬운 글 마무리

작성: 2026-10-14

보고 #30(로봇 USB 만들기) 다음으로 추천한 순서대로 세 가지를 마쳤습니다.

1. 학급 서버에 학생 30명(그리고 60명)을 가짜로 붙여 버티는지 재 봤습니다.
2. 실제 로봇에 끼운 도구와 화면의 도구가 다르면 알려 주고, 맞지 않는 명령은 막습니다.
3. 쉬운 글 기준(한 문장 한 줄, 쉬운 말)을 매뉴얼 PDF 세 권 · 마무리 평가 · 관제센터 · 지도 카드까지 넓혔습니다.

## 1. 학급 서버 부하 시험

"선생님과 함께 수업" 한 시간을 그대로 흉내 냈습니다. 도구: `web-typescript/tools/check/class-load.mts`.

| 누가 | 하는 일 (실제 화면과 같은 간격) |
| --- | --- |
| 학생마다 | 1.5초마다 선생님 진행 읽기, 단계가 바뀌면 내 상태 보내기, 3초마다 학습 기록 1~3개 보내기 |
| 조 | 4명쯤 한 조(최대 12조), 조마다 로봇 담당 1명 |
| 선생님 | 1.5초마다 진행 · 학급 관리 화면(기록 · 실시간 현황) 읽기, 15초마다 다음 단계 |

결과 (2분씩, 같은 PC 에서):

| | 학생 30명 | 학생 60명 |
| --- | --- | --- |
| 초당 요청 | 34 | 65 |
| 실패 | 0 | 0 |
| 요청 하나 걸린 시간 | 95 % 가 5 ms 이하 · 가장 늦은 것 49 ms | 95 % 가 5 ms 이하 · 가장 늦은 것 38 ms |
| 선생님이 단계를 넘긴 뒤 모든 학생 화면에 보이기까지 | 중앙값 0.87초 · 최대 1.5초 | 중앙값 0.73초 · 최대 1.5초 |
| 서버 CPU (한 코어 기준) | 평균 2.4 % · 최대 4 % | 평균 4.7 % · 최대 8 % |
| 서버 메모리 | 20 MB | 27 MB |
| 학급 관리 화면이 한 번에 받는 기록 | 약 17 KB | 약 34 KB |

뜻: 교사 PC 한 대로 한 반(30명)은 충분하고, 두 반을 합쳐도 여유가 큽니다.
학생 화면에 단계가 늦게 보이는 것은 서버가 아니라 화면이 1.5초마다 묻기 때문입니다(최대 1.5초).

남은 것: **실제 교실 Wi-Fi** 에서 같은 시험을 한 번 해야 합니다.
교실 공유기는 PC 30대가 한꺼번에 붙으면 느려질 수 있기 때문입니다.
방법: 교실의 PC 한 대에서 `CLASS=http://<선생님 PC>:47290 N=30 npx tsx tools/check/class-load.mts`.

## 2. 그리퍼 불일치 안내

문제: 화면은 흡착 펌프인데 실제 팔에는 그리퍼가 끼워져 있으면, 손끝 길이가 달라 블록에 닿지 않거나 부딪힙니다.
그 반대도 같습니다.

| 경우 | 화면 |
| --- | --- |
| 화면 = 그리퍼, 실제 팔은 그리퍼가 대답하지 않음 | 위쪽 안내 "화면의 도구는 어댑티브 그리퍼인데, 로봇의 그리퍼가 대답하지 않아요." [다시 확인] [닫기] |
| 화면 = 다른 도구, 실제 팔에 그리퍼가 끼워져 있음 | "로봇에 그리퍼가 끼워져 있어요. 화면의 도구는 흡착 펌프예요." [어댑티브 그리퍼로 바꾸기] [다시 확인] [닫기] |
| 맞지 않는 도구로 로봇 실행 · 그리퍼 · 펌프 명령 | 실행하지 않고 이유를 알려 줌 (예: "로봇에 그리퍼가 끼워져 있어요. 흡착 펌프로 바꿔 끼운 뒤 다시 해 주세요.") |

- 로봇 서버에 `GET /api/tool` 을 더했습니다(그리퍼 응답 값, 펌프 배선 여부). 실행 중이면 묻지 않습니다.
- 화면은 연결할 때와, 쉬는 동안 20초마다 한 번 묻습니다.
- 연습용 가짜 팔은 `--no-gripper` 로 그리퍼 없는 팔이 됩니다(시험용).
- 매뉴얼 두 권(시뮬레이터 · 기초교육)의 「문제가 생기면」 표에 두 안내를 더했습니다.

확인: `npm run check:tool`(판정 · 거절 문장), 가짜 팔 두 가지(그리퍼 있음 · 없음)로 실제 화면에서 안내가 뜨고 [어댑티브 그리퍼로 바꾸기] 로 사라지는 것.
함께 고친 것: 안내가 3D 보기 도구(보기 큐브) 밑에 깔리던 것, 첫 방문의 "PC 프로그램 받기" 창과 겹치던 것.

남은 것: **실제 로봇에서 한 번** — 그리퍼를 뺀 팔이 정말 "대답 없음"(값 −1)을 주는지 확인해야 합니다.

## 3. 쉬운 글 마무리 (보고 #26 의 남은 것)

기준은 보고 #26 과 같습니다: 한 문장은 한 줄에, 문장이 끝나면 줄을 바꿈, 쉬운 말.

| 어디 | 전 | 후 |
| --- | --- | --- |
| 마무리 평가 7문항 (상황 · 계산 · 힌트 · 원리 · 답) | 한 줄에 들어가는 문장 68~76 %, 세 줄 2개 | 100 % |
| 마무리 평가 · 지도 카드 · 관제센터 화면 (실제로 그려진 줄) | 두 줄로 넘어가는 글 31곳 | 0 / 160 |
| 시뮬레이터 사용 매뉴얼 PDF | 두 줄 넘는 문장 80 | 0 / 460 |
| 교사용 교육 가이드라인 PDF | 41 | 0 / 222 |
| 로봇 기초교육 자료 PDF | 13 | 0 / 268 |

- 마무리 평가의 원인 고르기 보기도 짧게 했습니다. 전에는 정답 보기만 길어서 길이로 답이 보였습니다.
- 매뉴얼의 그림 번호 설명은 이름 한 줄, 그 아래 문장마다 한 줄로 바꿨습니다.
- 기초교육 자료에서 앞에 '>' 가 찍혀 나오던 안내 4개를 팁 · 참고 상자로 고쳤습니다.
- 교육 화면 아래의 "실물 연동" 막대가 지도 · 마무리 평가 · 관제센터에서 점수와 카드를 가리던 것을, 따라 움직일 수 있는 화면(수업 · 현장 실습)에서만 보이게 했습니다.

측정 도구:

- `npx tsx tools/check/text-fit.mts` — 원고에서 계산(마무리 평가 · 지도 카드를 더함).
- `node tools/check/text-lines.mjs more` — 앱을 띄워 지도 카드 9곳 · 마무리 평가 목록과 7문항 · 관제센터 5화면의 실제 줄 수.
- `SENTENCES=1 node tools/build/guides.mjs` — PDF 를 만들며 인쇄 폭에서 문장마다 줄 수를 재고, 넘는 문장을 보여 줌.
