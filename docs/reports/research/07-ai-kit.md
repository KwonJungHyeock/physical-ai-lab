■ 요약
 - 시뮬레이터의 작업 환경을 제안서 구성품 "AI 로봇 확장 키트"와 같은 구조로 교체

 - 영상 처리도 공식 키트 프로그램과 같은 순서·같은 숫자로 바꿈 (마커 보정 → HSV → 좌표)

 - 실물에서 재야 확정되는 값 6가지는 매뉴얼에 측정표로 정리 (manuals/robot-arm/robot-check.md 5절)

■ 공식 자료끼리 어긋난 곳과 선택
 1) 카메라 위치
    - 3D 모델(2021)은 렌즈가 보정판 중심보다 74mm 앞 (233.8, −3.5), 높이 287.5
    - 공식 사진은 가로 640→600 으로 줄인 것. 되돌리면 보정판이 정사각형(2.0 px/mm),
      사다리꼴 왜곡 1.4% (기울기 약 1.5°) → 카메라는 수직 아래를 봄,
      보정판 중심이 화면 중심보다 54px 아래 → 카메라 바로 아래는 (133.5, −1.2)
    → 현재 키트의 사진을 택함. 이 위치여야 공식 "마커 2개 비율" 공식의 오차가 몇 mm 안에 듦
      (모델 위치면 블록 윗면 높이 때문에 약 10mm 틀어져 흡착 허용 범위를 넘음)
 2) 카메라 높이 — 추정
    - 공식 잡기 자세에서 손목이 보정판 위 약 300~320mm 까지 올라감 → 카메라는 그보다 높아야 함
    - 360mm 로 두고, 시야각은 사진의 배율(2.0 px/mm)에서 계산 → 48°
 3) 분류함 C
    - C 통의 중심은 로봇에서 296mm → 이 로봇이 닿지 않음
    - 공식 투하점 (238.8, −124.1) 은 통 안쪽 가장자리 3mm 안이라 25mm 블록이 벽에 걸림
    → 공식 점에서 통 안쪽으로 10mm 옮긴 (238.8, −134.1) 사용. 이때 도구를 10~20° 기울임
      (공식 C 자세도 약 10° 기울어져 있음)
 4) RDK X5 와 M5 차이
    - 공식 키트 코드·모델은 280 M5/PI 기준. RDK X5 는 몸체 URDF 에서 J2 가 8.3mm 높고,
      받침(베이스)이 뒤로 88mm 길어 받침판 뒤 가장자리를 33mm 넘음
    - 공식 표준 DH(기둥 131.22)와 RDK X5 URDF(139.56)가 z 로 7mm 다름.
      RDK X5 펌웨어가 어느 쪽인지는 실기 get_coords 로만 확인 가능 → robot_check.py 8단계 추가
    → 실측 확정 (보고 #8): 로봇 좌표가 RDK X5 URDF 와 0.2mm 차이로 일치, 공식 DH 와는 8.2mm 차이.
      시뮬레이터 좌표 = 실제 로봇 좌표 (보정 불필요)

■ 시뮬레이터와 공식 자료 비교 (자동 검사)
 - 공식 AI 키트의 분류함 관절 각도 → 우리 순기구학 → 공식 좌표와 x·y 4.1mm, 자세 3° 이내
 - 공식 투하점 A·B·D 가 공식 모델의 통 안에 들어감
 - 두 마커 사이 |dx|+|dy| = 220mm = 공식 코드의 상수
 - 공식 관찰 자세에서 도구가 아래를 향함
 - 우리가 푼 자세가 공식 자세와 같은 형태:
     분류함 B  시뮬 [113, −3, −91, −1, …]   공식 [112.9, 3.2, −96.3, 0.9, …]
     분류함 C  시뮬 [−14, −48, −16, −17, …]  공식 [−13.7, −52.1, −25.4, −4.6, …]
 - 역기구학 시작값을 공식 자세들로 바꿈 → 팔이 뒤로 꺾이는 엉뚱한 해가 사라짐
   (고치기 전: 블록 위에서 내려갈 때 J1 135°·J2 112° 로 한 바퀴 돌아가는 해가 나왔음)
 - 키트 작업점 1,022곳 × 모든 도구 도달, 최대 오차 0.5mm
 - 색 분류 미션 (어댑티브·플렉서블·흡착, 카메라 플랜지 유무): 4/4
 - 무작위 배치 6가지: 4/4
 - 충돌: 블록, 받침판, 분류함 벽, 카메라 거치대 (기둥·팔·카메라)
 - 브라우저(실제 렌더링된 카메라 화면을 영상 처리): 흡착 펌프 무작위 배치 4/4, 어댑티브 그리퍼 4/4
 - 블록을 찾기 전에 관찰 자세로 가지 않으면 팔이 카메라를 가려 "블록이 보이지 않아요" 로 멈춤
   → 실물과 같은 현상. 공식 프로그램처럼 찾기 전에 robot.home() 하라는 안내를 띄움

■ 영상 처리 — 공식 키트 프로그램과 같게
 순서: ① ArUco 마커 2개(6×6, id 1·2) 찾기 → 중심 = 두 마커의 가운데, 비율 = 220 ÷ (|du|+|dv|)
       ② 마커로 보정판 영역만 자르기 ③ BGR→HSV, 공식 범위로 색 거르기
       ④ 크기 조건 통과한 것 중 색마다 가장 큰 덩어리 ⑤ 좌표 = (픽셀 − 중심) × 비율 + 보정판 중심
 - HSV 값은 공식 코드 그대로 (OpenCV 단위 H 0~180) → 파이썬으로 그대로 옮길 수 있음
     노랑 [11,85,70]~[59,255,245]  빨강 [0,43,46]~[8,255,255]  초록 [35,43,35]~[90,255,255]
     파랑 [100,43,46]~[124,255,255]  청록 [78,43,46]~[99,255,255] (파랑과 같은 분류함)
 - 공식 빨강 범위는 0~8 만 봄 (180 근처로 넘어가지 않음) → 블록 빨강을 약간 주황 쪽 빨강으로 설정
 - 보정판에 실제 ArUco 무늬를 그림 → 화면 속 마커를 OpenCV 로도 인식할 수 있는 진짜 마커
 - 결과: 시뮬 카메라 화면에서 마커 id 1·2, 1px = 0.500mm, 블록 4개 인식.
   찾은 위치 오차 2~4mm (블록 윗면이 25mm 높아 카메라에서 바깥쪽으로 밀려 보임 —
   실제 키트에서도 같은 원리로 생기는 오차. 흡착 허용 범위 안)
 - 화면 표시: 마커 상자와 id, 자른 영역, 두 마커 중심(+), 비율, 블록별 (픽셀) → (mm)

■ 액세서리 — 공식 사양표 반영
 - 평행 그리퍼: 잡는 폭 20mm 미만(실효 15mm), 길이 66mm → 25mm 키트 블록은 못 잡음.
   시뮬레이터가 "최대 20mm 까지만 벌어져서 25mm 블록을 잡을 수 없어요" 라고 알려 줌
 - 어댑티브 그리퍼: 112 × 94 × 50mm, 잡는 폭 20~45mm (공식 3D 모델과 일치)
 - 카메라 플랜지 카메라: 시야각 약 60°
 - 흡착 펌프: 공식 3D 모델(끝까지 89.3mm) — 공식 키트 흡착 높이와 블록 25mm 가 이 값으로 맞아떨어짐
 - 흡착 펌프 핀: 공식 키트 코드는 M5 set_basic_output(2·5, 0=켜기), 라즈베리파이 GPIO 20·21.
   RDK X5 는 공식 자료 없음 → 로봇 코드에서 확인 안내

■ 화면에서 바뀐 것
 - 도구 기본값: 흡착 펌프 (키트 포함품)
 - 명령: robot.move_above("분류함 D") 처럼 분류함 이름으로 (옛 "빨강 칸" 대신)
 - 블록을 들고 이동할 때는 분류함 벽(98mm)보다 높이 들어 올림 (공식 프로그램과 같은 방식)
 - 펜·실린더·폰 홀더를 달면 블록은 보관함에 들어가 보정판이 비워짐
 - 카메라 이름: 키트 카메라 / 손 카메라
