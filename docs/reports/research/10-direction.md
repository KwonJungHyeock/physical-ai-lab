[보고 #10] 사양 전수조사와 방향 재정리 — PC 시뮬레이터 + 로봇 연결, 수준별 3단계

■ 요약
 - 사양 전수조사: 공식 GitHub 원본(문서·코드·URDF·메시)으로 로봇·키트·카메라·도구를 다시 대조.
   시뮬레이터에 틀린 곳 4가지, 공식 자료로도 확정 안 되는 곳 5가지를 찾음
 - 흡착 펌프 제어 방법 확인: RDK X5 공식 비전 키트 코드 — 40핀 헤더 31·37번 (Hobot.GPIO)
 - 연결 구조: "PC 가 계산, 로봇은 실행만" 을 유지하고, 연결선은 USB-C 케이블 → 랜선 → 로봇 핫스팟 순으로 권장
 - 수준별 3단계 제안: 초급 블록 / 중급 파이썬(실제 pymycobot 문법) / 고급 ROS 2
 - 조사 원본: 연결 방식 조사, 사양 점검표 (작업 폴더 research/ — 필요 시 docs 로 옮김)

■ 조사 방법
 - Elephant Robotics·에듀이노·판매처 사이트는 작업 환경에서 막혀 있어, 같은 내용의 GitHub 원본을 읽음
   (mycobot_docs = 공식 GitBook 원본, pymycobot, mycobot_ros·mycobot_ros2, aikit_V2, AiKit_UI,
    mycobot280RDKX5_vision_kit, D-Robotics rdk_doc·x5-hobot-configs·x5-hobot-utils)
 - 막힌 사이트의 값은 검색 요약으로만 확인 → 표에 "검색 요약" 으로 표시, 신뢰도 낮음

■ 1. 시뮬레이터에서 틀린 곳 (고칠 것)
 1) 실린더: 우리는 "막대가 튀어나와 누르는" 모듈로 만듦
    → 실물은 버튼·키보드를 누르는 고정 막대 (공압·전동 아님). 누르기 = 팔이 내려갔다 올라옴
    → 고치면 실린더 실습도 실제 로봇에서 그대로 실행 가능 (팔 동작뿐이므로)
 2) 펜 홀더: 우리는 "펜이 올라가고 내려가는" 장치로 만듦
    → 실물은 펜을 고정하는 홀더, 끝에 ±1mm 스프링 여유 (47.5×25×45.5mm, 35g). 올리기·내리기 = 팔 높이
    → 블록의 [펜 내리기]/[펜 올리기] 는 "종이에 닿게 내려가기 / 10mm 들기" 팔 동작으로 바꿈 → 실제 로봇 실행 가능
 3) 손 카메라(카메라 플랜지) 시야각: 우리는 수평 60°
    → 공식 문서 "약 60°"(수평·대각 미기재). RDK X5 공식 비전 키트의 보정값(fx 639.5, 640×480)으로는
      수평 53.2°. RDK X5 용 공식 값을 택해 53.2° 로, 카메라 위치도 같은 보정값의 손-눈 행렬로 맞춤
 4) 흡착 펌프: "RDK X5 핀 미확인" 으로 로봇 실행을 막아 두었음
    → RDK X5 공식 비전 키트 코드: Hobot.GPIO, BOARD 번호 31·37.
      켜기 = 31 HIGH, 37 LOW / 끄기 = 31 LOW, 37 HIGH (color_demo.py, aruco_demo.py 의 pump_on/off)
    → 로봇 서버에 넣고, 처음 한 번 "펌프 켜기/끄기 시험" 으로 배선을 확인한 뒤 실행 허용

■ 2. 공식 자료로도 확정되지 않는 곳 (실물 사진·측정으로 정함)
 1) 키트 카메라 — 출처끼리 다름
    - 제안서·보도자료: 1920×1080, 110°, 2.8mm (110° 가 대각인지 수평인지 원문에 없음)
    - 공식 키트 프로그램(AiKit_UI)은 640×480 으로 받아 씀 → 시뮬레이터 640×480 은 맞음
    - 시야각: 구형 키트 보정값으로는 수평 63°, 우리 값 48° 는 공식 사진의 배율에서 계산한 것.
      셋이 서로 맞지 않음 (사진이 어느 카메라로 찍혔는지 모름)
    - 위치·높이: 공식 3D 모델 2022년판으로는 렌즈 (165.5, 0.4), 판 위 368mm. 우리 값 (133.5, −1.2), 360mm
    → 영상처리는 마커 2개로 스스로 보정하므로 좌표 계산은 카메라가 달라도 맞음.
      화면이 실물과 똑같이 "보이게" 하려면 실제 카메라 사진 1장이 필요.
      → 콘솔에 "실제 카메라 사진으로 시뮬레이터 카메라 맞추기" 를 넣을 예정 (마커 크기·위치로 배율·위치 자동 계산)
 2) 키트 배치: 시뮬레이터는 공식 3D 모델 2021년판(suit_env) 기준. 2022년 12월판(suit_env_v2)이 따로 있음
    (mycobot_ros: mycobot_description/urdf/mycobot_280_pi/suit_env_v2.dae, 로봇 기준으로 변환해 비교)

    - 2022년판이 2023 키트(제안서 구성품) 출시 직전 모델이라 더 가까울 가능성이 큼

 3) 블록 한 변 (우리 25mm: 공식 흡착 높이에서 계산), 보정판 150mm, 마커 id 1·2 (공식 사진에서 판독)
    → 공식 치수표 없음. 실물 자로 확인
 4) 로봇 무게: GitBook 860g, 공식 RDK X5 사양 페이지(검색 요약) 1090g → 제안서 수치 확인 필요 (시뮬레이터와 무관)
 5) J5 범위: 문서 ±165°, SDK −155~160° → 시뮬레이터는 SDK 값(로봇이 실제로 막는 값) 유지

■ 3. 확인된 값 (그대로 유지)
 - 관절 범위 = pymycobot MyCobot280RDK-X5 표 그대로, 작업반경 280mm, 가반 250g, 반복정밀도 ±0.5mm
 - J2 높이 139.56mm (RDK X5 URDF, 실측 0.2mm 일치 — 보고 #8)
 - 어댑티브 그리퍼 20~45mm·112×94×50mm, 평행 그리퍼 <20mm(유효 15mm)·66×78×46mm·84g
 - 흡착 펌프 끝까지 89.3mm (URDF·메시 계산 89.2mm)
 - ArUco DICT_6X6_250, 상수 220 = 두 마커 중심의 |Δx|+|Δy| (mm)

■ 4. 제안서 문구 점검
 - "통신: Type-C 시리얼" → PC 가 USB 로 팔 제어기에 직접 붙는 공식 경로 없음.
   "USB-C (가상 네트워크)·마이크로 USB 디버그 콘솔" 로 고치는 것을 권장
 - 평행 그리퍼 "150g" → 최대 파지력. 무게는 84g
 - 카메라 플랜지 "720P" → 판매 페이지와 일치. 공식 보정·예제는 640×480 사용
 - AI 키트 공식 프로그램(aikit_V2, AiKit_UI)에는 RDK X5 판이 없음. RDK X5 전용 공식 예제는
   "Vision Kit"(손 카메라 방식, 블록에 ArUco 5×5 30mm). → 우리 콘솔이 AI 키트 2023 을 RDK X5 에 맞춰 쓰는 역할

■ 5. 연결 구조
 결론: 로봇 OS 화면(모니터·VNC)은 수업에 쓰지 않는다. 로봇은 제어 에이전트(server.py)만 돌리고,
       3D·시뮬레이션·영상처리·코드 실행은 학생 PC 브라우저가 한다. (지금 구조)
 - 검증된 프로그램을 통째로 로봇에 보내 로봇이 스스로 실행 → 실행 중 연결이 흔들려도 동작은 끊기지 않음.
   명령을 하나씩 보내는 방식(공식 소켓 30002 등)보다 연결에 강함
 - 화면과 3초 끊기면 로봇이 스스로 정지 (적용 완료)
 - 브라우저 보안상 로봇이 화면을 주는 방식이 가장 제약이 없음 (배포 사이트→로봇 호출은 크롬 142+ 허용 필요)

 연결선 우선순위
  1) USB-C 케이블 (로봇 192.168.128.10): RDK X5 공식 설정에 USB 가상 네트워크가 있음. 와이파이 불필요,
     PC 의 학교 인터넷 그대로. 단 로봇이 주소를 나눠 주지 않아, 로봇 쪽에 한 번 설정이 필요
     → 먼저 robot-python/checks/network_check.py 로 공장 이미지에 켜져 있는지 확인
  2) 랜선 직결 (로봇 192.168.127.10): 가장 안정적. PC 에 남는 랜 포트가 있어야 함. 같은 설정 필요
  3) 로봇 핫스팟 (10.42.0.1): 노트북용. 접속하는 동안 PC 인터넷이 끊김
  - 교실 와이파이 공유는 권장하지 않음. 배포 사이트(Vercel)는 로봇 없는 시뮬레이터 연습용
 - 로봇 쪽 추가 권장: 부팅하면 server.py 가 자동으로 켜지게(systemd), 필요하면 데스크톱 끄기(메모리·CPU 확보)

■ 6. 수준별 3단계 (제안)
 환경(AI 키트 / 로봇팔 단독)과 별개로, 단계마다 편집기·명령·실습이 다르다.

 초급 — 블록 코딩 (코딩 경험 없는 교원·학생)
  - 제어판(관절 ±, 도구 끝 ±, 기본·0° 자세), 드래그 티칭(손으로 움직여 기록·재생), 엔트리식 블록
  - 실습: 전 축 구동(검수 1), 반복 위치제어(검수 2), 엔드이펙터 교체(검수 5), 블록 옮기기, 펜, 실린더

 중급 — 파이썬 (공식 pymycobot 문법 그대로)
  - 브라우저 안에서 진짜 파이썬 실행 (Pyodide). 학생이 쓰는 코드:
      from pymycobot import MyCobot280RDKX5
      mc = MyCobot280RDKX5("/dev/ttyS1", 1000000)
      mc.send_angles([0, 0, 0, 0, 0, 0], 50); time.sleep(2); print(mc.get_coords())
    → 시뮬레이터의 가짜 로봇이 받아 움직임. 변수·반복·함수·조건 모두 됨
  - 통과한 코드 = 로봇에서 그대로 돌아가는 코드 (학생이 로봇에서 python3 로 실행해도 같음)
  - 영상처리: 카메라 사진 받기, HSV 색 인식, 마커 보정, 좌표 변환 (공식 키트 알고리즘을 코드로)
  - 실습: 각도·좌표 제어, 영상 취득(검수 3), 비전-로봇 연계(검수 4), AI 샘플 로컬 실행(검수 6), API(검수 7 일부)
  - 시험 완료: 브라우저 파이썬으로 pymycobot 식 코드를 돌려 시뮬레이터 명령으로 바꾸는 것 확인 (약 13MB, 한 번 받으면 캐시)

 고급 — ROS 2
  - rclpy 노드 작성: 토픽 발행·구독(/joint_states), 타이머, 메시지. 브라우저에서 노드·토픽 그래프,
    ros2 topic echo 흉내, RViz 처럼 3D 확인
  - 실제 로봇: 공식 패키지 mycobot_280_rdkx5 (slider_control 이 /joint_states 를 받아 팔을 움직임) 로 실행
  - 실습: 노드·토픽, joint_states 로 팔 움직이기, MoveIt/RViz 개념, 검수 7 (ROS 2 실행)

 공통: 시뮬레이션 통과 → [로봇에서 실행], 정지 Esc, 실제 카메라, 실제 로봇 자세 따라가기

■ 적용한 것 (이 보고서 이후)
 - 실린더·펜: 팔 동작으로 바꿈 → 실제 로봇에서 그대로 실행됨
 - 손 카메라: 수평 53.2°, 위치는 공식 손-눈 보정값
 - 흡착 펌프: 로봇 서버가 공식 순서(Hobot.GPIO 31·37)로 켜고 끔. 제어판 [켜기]/[끄기] 가 실제 펌프도 움직임
 - 키트: 2022년판(2023 키트) 모델로 교체 — 같은 통 4개(앞 벽이 낮은 부품통: 뒤·옆 52mm, 앞 34.7mm,
   안쪽 85×66mm), 자재 상자, 기둥 (305.5, 0.4), 카메라 (165.5, 0.4) 판 위 368mm.
   공식 투하점 A~D 모두 통 안 (자동 검사). 분류함 C 는 투하점을 10mm 안쪽으로(앞 벽 여유)
 - 키트 카메라: 제품 사양 110° 를 16:9 대각으로 보고 640×480(가운데 4:3) → 가로 86.1°·세로 70°
   → 판이 화면에서 작게 보임(0.93 px/mm). 공식 프로그램이 인식 전에 화면을 1.5배 키우는 것과 맞음
 - 영상처리: 작은 마커(약 20px)도 읽도록 마커 판독을 고침. 같은 렌더 화면에서
   로봇 쪽 OpenCV 와 브라우저 결과가 같음 (블록 위치 x 133/186, y ±26)

■ 단계 구조 적용 결과
 - 콘솔 맨 위에서 [초급 · 블록 코딩 | 중급 · 파이썬 | 고급 · ROS 2] × [AI 키트 | 로봇팔 단독] 을 고른다.
   단계마다 편집기·실습 목록이 따로 있고, [직접 움직이기] 제어판은 모든 단계에 있다.
 - 중급: 브라우저 안 진짜 파이썬(Pyodide 314, 로봇이 파일을 직접 줌 — 인터넷 불필요).
   가짜 pymycobot 은 실제 라이브러리와 같게 동작: send_angles 는 기다리지 않음, 움직이는 중 get_angles 는
   중간 값, sync_send_* 는 도착까지 기다림, 범위 검사·오류 문장도 pymycobot 과 같음. send_coords 는 IK 로 풀고
   get_coords 와 1.5mm 안에서 일치. 펌프는 Hobot.GPIO 31·37 (공식 비전 키트 순서).
 - 고급: rclpy·sensor_msgs·std_msgs 흉내. 공식 드라이버 노드 control_slider(/joint_states → send_angles)가
   시뮬레이터에 켜져 있음. 노드·토픽 그래프와 메시지를 편집기 아래에 보여 줌.
   로봇에서는 ros2 run mycobot_280_rdkx5 slider_control + python3 my_node.py (launch 파일은
   joint_state_publisher_gui 가 같은 토픽을 내보내 학생 노드와 겹치므로 쓰지 않음).
 - 실행 경로: 파이썬 실행 → 시각이 붙은 명령 목록 → 3D 재생하며 충돌 검사 → 통과하면 같은 목록을 같은 시각에
   로봇 서버가 실행. 시뮬레이션은 실제 로봇의 지금 자세에서 시작하고, 그 사이 자세가 3° 넘게 바뀌면 다시 시뮬레이션하게 함.
 - 자동 검사: 중급·고급의 모든 예제가 두 환경에서 오류·충돌 없이 돌고 실습 목표를 채우는지 확인 (npm run check).
 - 아직 없는 것: 중급의 카메라(영상 취득·비전 연계·AI 샘플, 검수 3·4·6)는 초급 목록에만 있음. 다음 작업.

■ PC 설치형 시뮬레이터 (로봇 없이 연습)
 - 방식: 설치형 웹앱(PWA). 크롬·엣지에서 배포 주소를 열고 [PC에 설치] → 바탕화면 아이콘, 별도 창.
   관리자 권한·파이썬·설치 프로그램이 필요 없음. exe 설치 파일(약 100MB 이상, 보안 프로그램에 막힐 수 있음)은 만들지 않음.
 - 오프라인: 처음 한 번 약 15MB(3D 모델, 파이썬 실행기)를 PC 에 저장. 그 뒤 인터넷 없이 세 단계 모두 실행.
   시험: 한 번 연 뒤 네트워크를 끊고 새로고침 → 3D, 블록 시뮬레이션, 파이썬 시뮬레이션 모두 동작.
   크롬 설치 가능 검사 통과 (시험 브라우저의 시크릿 모드 표시만 나옴).
 - 새 버전: 인터넷이 있을 때 켜면 저절로 바뀜 (화면·스크립트는 배포마다 새로, 큰 파일은 바뀐 경우만 다시 받음).
 - 화면: PC 창 크기에 맞춰 한 화면(스크롤 없음). 윗줄 1개에 단계·환경·실습, 왼쪽 3D·실행·기록/카메라,
   오른쪽 편집기. 1366×768 노트북은 아래 칸을 [기록 | 카메라 | 숨기기] 로 전환, 1680px 이상은 나란히.
   가로 1100px 미만 창은 예전처럼 세로 스크롤 화면.
 - 로봇 연결은 따로: 실제 로봇은 로봇 주소(http://로봇IP:8080/console)로. 설치한 앱(https)에서 로봇(http)을
   직접 부르는 것은 브라우저 보안 규칙에 막힐 수 있어 나눔. 시뮬레이터에서 통과한 코드를 로봇 콘솔에 붙여 넣어 실행.
 - 안내서: manuals/setup/pc-simulator.md

■ 화면 재구성 (검수 모듈 · 영역 구분 · 3D 품질)
 - 영역 4개로 나눔: 모드(맨 위: 단계·작업 환경·연결) / 실습 모듈·구성품(왼쪽) / 시뮬레이션(가운데) / 편집기(오른쪽).
 - 검수 7종 = 모듈: 누르면 환경·도구·예제·목표가 한 번에 준비. 지금 단계에 없는 검수는 가능한 단계로 열림
   (검수 3·4·6 은 초급, 1·2·5 는 초·중, 7 은 초·중·고). 로봇팔 단독 환경의 엔드이펙터 교체에도 검수 5 표시.
   진행 표시: 연한 초록 = 시뮬레이션에서 목표 달성, 진한 초록 = 실제 로봇 실행. PC(브라우저)에 저장.
 - 미션 카드: 목표 문장, 진행 막대, 세 단계 [시뮬레이션 → 목표 달성 → 실제 로봇], 실습 버튼, [예제 다시].
 - 3D 품질: 스튜디오 조명(인터넷 없이 만드는 반사광), 중립 톤 곡선(블록 색 그대로), 부드러운 그림자,
   고화질에서 주변 음영(AO)·SMAA 계단 제거, 바닥 격자, 시점 버튼(기본·위·앞·옆, 부드럽게 이동),
   도구 끝 궤적 선, 실제 로봇 자세를 따라갈 때 보간(0.15초 간격 읽기를 끊김 없이). 느린 PC 는 [고화질] 끄기
   (코어 4개 이하 PC 는 처음부터 보통 화질).
 - 가상 카메라는 새 조명·격자·궤적 선을 보지 않음: 영상 처리가 쓰는 화면은 이전과 같은 조명으로 그림
   (새 조명 그대로면 파랑 블록을 놓치는 것을 시험에서 확인하고 고침). 검수 4 가 블록 4개를 모두 분류.

■ 영점 맞추기와 화면 개편 (실제 로봇 시험 후)
 - 실제 로봇 시험: PC(윈도우 크롬)에서 로봇 서버로 접속해 실행 성공. 문제는 영점 — 로봇이 읽는 각도와 실제 자세가
   달라 시뮬레이션과 실제 동작이 어긋나고, "목표 자세에 도착하지 않았어요" 가 남.
 - 영점 맞추기를 관절 하나씩 하는 방식으로 바꿈 (공식 명령 release_servo → 손으로 표시선 맞춤 →
   set_servo_calibration → focus_servo). 0° 자세로 보내 어긋난 관절 확인 → 그 관절만 풀고 맞춰 저장 →
   0° 자세·기본 자세로 화면과 비교. 나머지 관절은 고정된 채라 팔을 받치기 쉬움. 3D 에 그 관절을 고리로 표시.
   맞춘 날짜·관절은 로봇에 저장(~/.robot_console_calibration.json, zip 을 새로 풀어도 유지).
 - 도착 실패 오류에 관절별 차이를 표시 (예: "J3 목표 -92.4° / 지금 -86.1° (6.3° 차이)").
 - [연결 확인] 은 몸통(J1) 10° 로 바꿈 (끝 원판 J6 15° 는 도구가 없으면 안 보임). 연결 확인은 실습 완료로 치지 않음.
 - 화면: 모든 조작을 왼쪽 제어 패널 하나로(실행 · 로봇 상태 · 직접 조작 · 구성품, 칸마다 접기), 가운데 3D 를 크게,
   기록은 한 줄(누르면 펼침), 카메라는 3D 위에 띄우는 창, 검수 1~7 은 맨 위 번호, 편집기는 오른쪽(접기 가능).
   색·그림자·글꼴을 정리해 한 가지 강조색(파랑)과 실행 색(초록·주황·빨강)만 씀.
 - 고화질에서 쓰던 PCSS 부드러운 그림자는 일부 NVIDIA 노트북에서 셰이더가 안 만들어져 로봇이 안 보였음 → 뺌.
   셰이더 오류가 나면 자동으로 보통 화질로 바꾸고 기록에 남김.

■ 영점 두 가지 방법 · 티칭 펜던트 제어 패널 · 확대/축소
 - 영점 ① 한 번에(일자 자세): 서보를 모두 풀고 팔을 곧게 세워 표시선 6쌍을 맞춘 뒤 고정 → 6축 한 번에 저장.
   저장 전 읽은 값(틀어진 정도)을 보여 주고 20° 넘으면 경고. 로봇 전원을 끈 채 펴 두고 켜는 방법도 같음.
 - 영점 ② 관절별 정밀: 0° 자세에서 로봇이 그 관절을 0.5°·2° 씩 돌려 표시선을 맞춘 뒤 저장 (손으로 맞추는 것보다 정밀).
   저장은 공식 set_servo_calibration, 관절을 잠깐 풀었다가 저장 후 고정.
 - 로봇을 놓는 위치는 영점과 별개. AI 키트는 로봇 자리가 받침판에 정해져 있고 카메라는 마커로 보정.
   로봇팔 단독 매트는 사람마다 놓는 위치가 다를 수 있어, 도구 끝으로 매트의 두 점을 찍어 맞추는 기능을 다음 후보로 둠.
 - 제어 패널을 티칭 펜던트 방식으로: 표시등(모드·서보·동작·오류), 검은 표시창(J1~J6, X·Y·Z, RX·RY·RZ),
   JOINT/BASE 좌표계, 이동 단위, 속도 10~100%, 누르고 있으면 계속 움직이는 조그 키(떼면 멈춤), 한계 눈금이 있는 관절 막대.
 - 3D 확대·축소: 휠은 가리키는 곳으로, [+][−] 버튼, 키보드 +/−, [맞춤]. 더 가까이 들어갈 수 있게.

■ 편집기·블록·패널 정리
 - 고화질에서 로봇이 안 보이던 문제: 원인(일부 NVIDIA 그래픽에서 PCSS 그림자 셰이더 실패)은 이미 제거. 한 겹 더,
   고화질로 켠 직후 화면을 읽어 로봇 받침(어두운 부분)이 그려졌는지 확인하고, 안 그려졌으면 보통 화질로 자동 전환.
 - 초급 블록: 숫자를 칩으로 모두 보이게 하고, 누르면 막대·±버튼·직접 입력·지금 로봇 각도 창. 블록을 골라 그 다음에
   추가, 블록마다 위/아래/복사/지우기, 6축 블록에 [지금 자세]. 끌어다 놓기 없이도 모두 가능.
 - 중급·고급 편집기: 파일 탭, 파이썬 문법 색, 실행·오류 줄 표시, 상태 줄, 출력·노드·메시지 탭, Ctrl+Enter 시뮬레이션,
   편집기 머리줄에서 예제 고르기.
 - 실행 구조: 코드는 PC 에서 실행, 로봇에는 동작 명령만 전송 (업로드·예제마다 따로 실행 불필요).
 - 화면: 세 열(제어 패널·시뮬레이션·편집기)을 같은 높이의 머리줄을 가진 패널로 통일, 안쪽은 얇은 선으로만 나눔.
