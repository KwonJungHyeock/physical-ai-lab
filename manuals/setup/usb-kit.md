# USB 키트로 로봇 준비하기 — Wi-Fi 이름·비밀번호만 적어 꽂기

수업 장소마다 랜선을 꽂고, 터미널을 열고, Wi-Fi 를 입력하던 일을 줄이는 방법입니다.

- **로봇마다 처음 한 번**: USB 를 꽂고 `설치하기` 더블클릭(또는 명령 한 줄) → 콘솔 설치 · 자동 시작 · Wi-Fi 연결이 한 번에 끝납니다.
- **그 뒤로는**: PC 에서 `wifi.txt` 두 줄을 고쳐 저장 → 로봇에 USB 를 꽂기 → 로봇이 살짝 움직이면 끝. 터미널이 필요 없습니다.

로봇팔(myCobot 280 RDK X5)과 이동 로봇(myAGV 2023 Pi) 모두 같은 USB 를 씁니다.
만드는 쪽: `robot-python/usb-kit/` (설치 파일·양식), `robot-python/server/usb_setup.py` (로봇 쪽), `robot-python/tools/make_usb_kit.py` (묶기).

## 1. USB 만들기 (PC, 한 번)

**시뮬레이터 프로그램으로 (Windows, 권장)**: USB 를 꽂고 `Physical AI 시뮬레이터.exe` → 윗줄 **⚙ 설정 → [로봇 USB 만들기]**.
꽂은 USB 가 저절로 골라지고 Wi-Fi 이름에는 이 PC 의 Wi-Fi 가 들어 있습니다. 비밀번호 · 사용자를 적고 **[USB 만들기]** →
**[USB 꺼내기]**. 아래 1~2 를 프로그램이 대신합니다(프로그램에 든 서명된 키트를 쓰고, `wifi.txt` 를 로봇이 읽는 양식으로 씁니다).
로봇에 꽂았던 USB 를 다시 꽂으면 **[로봇 결과 보기]** 에 `result-*.txt` 를 로봇마다 한 줄로 보여 줍니다(성공 로봇은 [연결]).
다시 만들면 예전 결과는 `eduino/지난 결과/` 로 옮깁니다. 만드는 쪽: `desktop-go/usbkit.go`, 화면 `web-typescript/src/ui/simulator/connect/UsbMaker.tsx`.

**직접 (프로그램 없이)**:
1. 받은 `eduino_usb.zip` 을 풀어 나온 **`eduino` 폴더를 USB 맨 위에** 복사합니다.
   ```
   USB
   └─ eduino
      ├─ wifi.txt            ← 이것만 고쳐요
      ├─ 설치하기.desktop    ← 로봇 화면에서 더블클릭 (로봇마다 처음 한 번)
      ├─ install.py          ← 설치 파일 (더블클릭이 이걸 실행)
      ├─ robot_console.zip   ← 로봇 콘솔 프로그램 (검수 6 의 AI 모델 yolov5s.onnx 포함)
      ├─ 읽어보세요.txt
      ├─ Physical AI Tool.html ← PC 프로그램: PC 바탕화면에 복사 (4절)
      └─ checks/            ← 점검 파일 (흡착 펌프·로봇·네트워크)
   ```
   USB 는 보통 쓰는 **FAT32 / exFAT** 그대로 둡니다. (`eduino_usb` 폴더째 복사해 `eduino_usb/eduino` 가 되어도 USB 꽂기는 됩니다.)
2. `wifi.txt` 를 메모장으로 열어 `=` 뒤를 채우고 저장합니다.
   ```
   와이파이=EDUINO-LAB
   비밀번호=12345678
   사용자=3조 김민수
   ```
   - 와이파이 이름은 대소문자·띄어쓰기까지 똑같이. 비밀번호가 없는 Wi-Fi 면 `비밀번호=` 뒤를 비워 둡니다.
   - **사용자**: PC 시뮬레이터의 [로봇 찾기] 목록에 IP 와 함께 크게 보이는 이름(24자까지). 여러 명이 같은 교실에서 써도
     자기 로봇을 바로 고릅니다. 비워 두면 전에 정한 이름 그대로. USB 하나로 여러 대를 맞출 때는 로봇마다 이름을 바꿔 저장하고 꽂습니다.
   - `와이파이=핫스팟` 으로 저장하면 로봇이 **자기 핫스팟으로 돌아갑니다**. (예전 양식의 `이름=` 도 와이파이 이름으로 읽습니다.)
   - `와이파이=끔` 으로 저장하면 로봇의 **Wi-Fi 를 끕니다**. 랜선으로만 씁니다(공유기 · 허브에 꽂거나, PC 와 랜선 하나로 직결).
     직결 주소는 늘 `169.254.127.10` 입니다 (PC 프로그램의 로봇 연결 → [유선 직결]). Wi-Fi 를 다시 켜려면 교실 Wi-Fi 이름이나 `핫스팟` 으로 만들어 꽂습니다.
   - 결과 파일의 주소는 종류를 붙여 적습니다: `주소: 무선 192.168.0.52 · 유선 192.168.0.61 · 직결 169.254.127.10`.

직접 만들 때 (저장소에서):
```bash
cd web-typescript && npm run build:robot && cd ..      # 콘솔 화면 파일
python3 robot-python/tools/make_usb_kit.py -o dist # dist/eduino_usb.zip, dist/robot_console.zip
```

## 2. 로봇마다 처음 한 번 (약 5분)
1. 로봇 전원을 켜고 1분 기다린 뒤 USB 를 꽂습니다.

**방법 A — 더블클릭 (로봇에 모니터·마우스·키보드를 붙였을 때, 권장)**
1. USB 를 꽂으면 로봇 화면에 USB 창이 열립니다 (안 열리면 바탕화면·파일 관리자에서 USB 를 엽니다).
2. `eduino` 폴더의 **`설치하기`** 를 더블클릭합니다.
   - "신뢰할 수 없는 실행 파일 / Untrusted application launcher" 창이 뜨면 **[그래도 실행 / Launch Anyway]**.
     (USB 는 FAT32·exFAT 라 '실행 허용' 표시를 붙일 수 없어서 매번 묻습니다. 정상입니다.)
3. 검은 창(터미널)이 열리고 비밀번호를 물으면 **로봇 계정 비밀번호** + Enter (입력해도 글자가 안 보이는 게 정상).
4. 아래 4단계가 차례로 지나가고 맨 아래에 `주소: http://…:8080/console` 가 나오면 끝. Enter 로 창을 닫습니다.
   서버는 이 창과 상관없이 **로봇 안에서 계속 켜져 있고**, 다음부터는 전원만 켜면 저절로 켜집니다.

**방법 B — 명령 한 줄 (모니터 없이 SSH 로 접속할 때)**
2. 로봇 터미널을 엽니다 — 로봇 핫스팟 / 랜선으로 SSH 접속.
3. 한 줄 입력 (비밀번호를 물으면 로봇 계정 비밀번호):
   ```bash
   sudo python3 /media/*/eduino/install.py
   ```
   - RDK X5 는 USB 를 `/media/<USB 이름>/` 에 엽니다 (예: `/media/C052-0E64/eduino/install.py`).
   - `No such file` 이 나오면 USB 가 다른 곳에 열린 것입니다. 이 줄은 어디에 열렸든 찾아 실행합니다:
     ```bash
     sudo python3 "$(find /media /mnt -maxdepth 4 -path '*eduino/install.py' 2>/dev/null | head -1)"
     ```
   - 그래도 못 찾으면 USB 가 아직 열리지 않은 것입니다:
     `sudo mount /dev/sda1 /mnt` 후 `sudo python3 /mnt/eduino/install.py`
4. 설치 파일이 차례로 합니다 (방법 A·B 같음).
   | 단계 | 하는 일 |
   | --- | --- |
   | 1/4 | `robot_console.zip` 을 `~/robot_console` 에 풂 (이전 판은 지우고 새로), pymycobot 확인 |
   | 2/4 | 전원을 켜면 콘솔 서버가 저절로 켜지게 (`autostart.py`, 로봇팔이면 `server.py`, myAGV 면 `agv_server.py`) |
   | 3/4 | `eduino-usb` 서비스 설치: 앞으로 USB 를 꽂으면 `wifi.txt` 를 읽어 연결 |
   | 4/4 | 이 USB 의 `wifi.txt` 로 지금 바로 연결 |
   - 로봇 종류: RDK X5 는 저절로 **로봇팔**로 알아봅니다. 라즈베리 파이 보드면 물어봅니다 (Enter = myAGV).
     바로 정하려면 `… install.py agv` 또는 `… install.py arm`.
   - Wi-Fi 는 그대로 두고 설치만: `… install.py --no-wifi`
5. 연결되면 **로봇이 살짝 움직입니다** (로봇팔은 밑동이 5° 돌았다 돌아오고, myAGV 는 불빛을 깜빡이며 제자리에서 살짝 돌기 — 주변을 비워 두세요).
   USB 의 `eduino/result-<로봇이름>.txt` 에 결과·로봇 ID·주소가 적힙니다.
   (팔 전원이 꺼져 있거나 서보를 풀어 둔 로봇팔은 움직이지 않습니다 — 결과 파일이 `성공` 이면 연결된 것입니다.)
   - **로봇 핫스팟으로 SSH 접속 중이었다면 여기서 창이 끊깁니다. 정상입니다** — 설치는 끝까지 진행되고, 결과는 USB 의 파일로 봅니다.

## 3. 그 뒤로 — Wi-Fi 가 다른 곳에 수업 갈 때 (터미널 없이)
1. PC 에서 `wifi.txt` 의 이름·비밀번호를 고쳐 저장합니다.
2. 로봇 전원을 켜고 **1분 뒤** USB 를 꽂습니다.
3. 20~60초 안에 로봇이 살짝 움직이면 연결 끝. 10초쯤 더 기다렸다 USB 를 빼서 PC 에서 `result-<로봇이름>.txt` 를 봅니다.
   ```
   2026-10-02 09:12
   로봇: ubuntu-3a7f
   결과: 성공 — 'EDUINO-LAB' 에 연결했어요.
   로봇 ID: 107   주소: 192.168.0.107
   PC 브라우저: http://192.168.0.107:8080/console
   확인값: 3f9c0a1b22e4
   ```
- **USB 하나로 여러 대**를 차례로 꽂아도 됩니다. 로봇마다 결과 파일이 따로 생깁니다
  (로봇 이름이 모두 `ubuntu` 여도 파일 이름 끝에 로봇마다 다른 Wi-Fi 칩 주소 네 자리가 붙어요: `result-ubuntu-3a7f.txt`).
- 이미 이 `wifi.txt` 로 연결에 성공한 로봇은 다시 꽂아도, 꽂은 채로 켜도 그대로 둡니다 (`확인값` 으로 구분).
- 실패하면 로봇은 **원래 연결(로봇 핫스팟)로 돌아갑니다**. 결과 파일의 이유(비밀번호·이름 등)를 보고
  `wifi.txt` 를 고쳐 다시 꽂으면 다시 합니다. 고치지 않고 다시 꽂아도 한 번 더 시도합니다.
- 한 번 붙은 Wi-Fi 는 로봇이 기억합니다. 그 교실에서는 전원만 켜면 저절로 붙고, 그 Wi-Fi 가 없는 곳에서는 로봇 핫스팟이 켜집니다.
- 로봇 화면(데스크톱)에 아무도 로그인하지 않았어도 됩니다 — 이때는 서비스가 USB 를 직접 열었다 닫습니다.

## 4. PC 에서 접속 — 시뮬레이터 프로그램 (권장)
1. PC 를 로봇과 같은 Wi-Fi 에 연결하고 `Physical AI 시뮬레이터.exe` 를 더블클릭합니다.
2. 시작 화면이 끝나면 **[연결하기]** 를 누릅니다. **로봇 연결** 창이 이 PC 의 네트워크를 저절로 찾아 **로봇 목록**이 나옵니다
   (사용자 이름 · IP · 로봇 ID · 상태). 사람이 많으면 위 칸에 이름이나 번호를 넣어 거릅니다.
3. 내 로봇의 **[연결]** → 그 로봇의 콘솔이 열리고 바로 실습합니다. 헷갈리면 [움직여 확인].
   로봇 없이 하려면 [시뮬레이션만].
- 로봇은 전원을 켜고 1~2분 뒤에 목록에 나옵니다 (Wi-Fi 연결 + 서버 자동 시작). 안 나오면 [다시 찾기].

## 4-1. PC 에서 접속 — Physical AI Tool (exe 를 못 쓸 때)
1. USB 의 `eduino/Physical AI Tool.html` 을 교실 PC **바탕화면에 복사**합니다 (PC 마다 한 번. 설치 없음).
   로봇이 이 USB 로 Wi-Fi 에 붙을 때마다 그 로봇을 이 파일에 적어 두므로, 연결한 뒤 복사하면 **내 로봇** 목록에 바로 나옵니다.
   (설치 명령이 끝날 때 로봇 터미널 맨 아래에도 `주소: http://…:8080/console` 가 크게 나옵니다.)
   로봇 콘솔 윗줄 **[··· 설정] → [PC 프로그램 받기]** 로 받아도 같은 파일입니다.
2. PC 를 교실 Wi-Fi 에 연결하고 그 파일을 **더블클릭** → **[같은 Wi-Fi 에서 찾기]** → 결과 파일의 **로봇 ID** 인 로봇의
   **[열기]** (모르겠으면 [움직여 확인]). 한 번 연 로봇은 다음부터 **내 로봇** 에 바로 나옵니다.
   - 로봇 ID 를 알면 아래 칸에 ID 만 넣고 [열기] 해도 됩니다.
   - 처음 열 때 크롬이 "로컬 네트워크의 기기에 접근" 을 물으면 **허용**.
(결과 파일의 `PC 브라우저` 주소를 바로 열거나, 콘솔 오른쪽 위 **[로봇 연결] → [로봇 찾기]** 로 옮겨 가도 됩니다.)
자세한 것은 [`robot-console.md`](../robot-arm/robot-console.md) 5절, myAGV 는 [`agv-console.md`](../myagv/agv-console.md) 5절.

## 5. 공유기
- 교실 전용 공유기 한 대를 권장합니다 (학교망은 기기끼리 막혀 있는 경우가 많아요).
- 2.4GHz 를 켜 두면 가장 확실합니다 (5GHz 도 대부분 됨). 접속할 때 웹 로그인 화면이 뜨는 Wi-Fi 는 안 됩니다.
- "AP 격리 / 게스트 격리" 는 끄기. 가능하면 로봇마다 고정 IP(DHCP 예약)를 주면 로봇 ID 가 늘 같습니다.

## 6. 안전과 문제 해결
- 로봇은 USB 에서 **Wi-Fi 이름과 비밀번호만 읽습니다**. USB 의 프로그램을 저절로 실행하지 않습니다
  (`install.py` 는 사람이 `설치하기` 를 더블클릭하고 비밀번호를 넣거나 `sudo` 로 실행할 때만). 다른 USB 를 꽂아도 로봇이 다른 Wi-Fi 로 옮겨 가는 것 말고는 일어나지 않습니다.
- 로봇이 안 움직이고 결과 파일도 안 생기면:
  - 꽂은 뒤 1분 넘게 기다렸는지 (켠 직후 1분은 교실 Wi-Fi 를 먼저 기다리느라 USB 를 보지 않습니다)
  - `eduino` 폴더가 USB **맨 위**에 있는지, 파일 이름이 `wifi.txt` 인지 (메모장이 `wifi.txt.txt` 로 저장하지 않았는지)
  - 로봇 터미널에서: `systemctl status eduino-usb`, 기록 `sudo tail /var/log/eduino-wifi.log`
- 설치 되돌리기: `sudo systemctl disable --now eduino-usb && sudo rm /etc/systemd/system/eduino-usb.service`
  (Wi-Fi 는 `wifi.txt` 에 `와이파이=핫스팟`, 자동 시작은 `sudo python3 ~/robot_console/autostart.py --off`)
