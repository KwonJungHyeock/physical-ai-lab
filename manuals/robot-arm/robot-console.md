# 로봇에서 실습 콘솔 켜기 (에듀이노 로봇팔 실습)

대상 폴더: `robot-python/server/` — 서버는 myCobot 280 RDK X5 **로봇 안에서** 켜고,
화면은 **PC 브라우저**에서 엽니다.

> 로봇 화면(RDK OS)의 브라우저로 콘솔을 열면 3D 화면과 시뮬레이션이 매우 느립니다.
> 로봇은 서버(로봇 제어·카메라)만 맡고, 3D·시뮬레이션·영상 처리는 PC 가 계산하도록
> **같은 공유기에 붙은 PC 에서 접속**하세요.

할 수 있는 것
- 화면의 3D 팔이 **실제 로봇 자세를 실시간으로 따라감** (위쪽 주황 줄에 실제 관절 각도)
- 시뮬레이션을 통과한 프로그램을 **[▶ 로봇에서 실행]** 으로 실제 로봇에서 실행
- **[■ 정지]** 버튼이나 **Esc** 키로 즉시 정지
- 단계 3개(**초급 블록 코딩 / 중급 파이썬 / 고급 ROS 2**) × 작업 환경 2개(**AI 키트 / 로봇팔 단독**)
- 맨 위 **[실습 | 검수 시연]**: 수업은 [실습](주제별 실습 목록), 납품 검수 7종은 [검수 시연]에 따로 모여 있음
- 제어 패널(상태·조그·자세·도구·작업대): **누르고 있는 동안 실시간으로 움직이는 조그**, 자세 기록과 다시 가기, 손으로 움직이기, 영점 맞추기
- **실제 카메라** 화면과 영상 처리, 실제 블록 위치를 시뮬레이터로 가져오기

> **`robot_console.zip` 은 로봇(RDK X5)에 푸는 파일입니다.** PC 에서 풀어 열면 로봇 서버가 없어 시뮬레이션만 됩니다.
> PC 에서는 설치한 앱(또는 사이트)의 오른쪽 위 **[로봇 연결]** 로 로봇에 들어갑니다 (5절).

> **가장 쉬운 방법: USB 키트** — [`usb-kit.md`](../setup/usb-kit.md). USB 를 꽂고 명령 한 줄이면 아래 1·2·4-1·4-2절이 한 번에 끝나고,
> 그 뒤로는 시뮬레이터 프로그램의 ⚙ → [로봇 USB 만들기] 로 Wi-Fi 를 바꿔 만든 USB 를 꽂으면 로봇이 그 Wi-Fi 로 옮겨 갑니다. 아래는 하나씩 직접 할 때의 방법입니다.

## 1. 파일 준비 (PC)
받은 `robot_console.zip` 을 USB 메모리에 복사합니다. (점검 때와 같은 방법)

직접 만들 때는 저장소에서:
```bash
cd web-typescript
npm install
npm run build:robot      # 화면 파일을 robot-python/server/static 에 만듦
```
그 뒤 저장소 맨 위에서 `python3 robot-python/tools/make_usb_kit.py -o dist` 로 `dist/robot_console.zip` 을 만듭니다.
`robot-python/server` 폴더(`server.py`, `camera.py`, `static/` …)가 로봇에서 쓰는 이름 `robot_console/` 로 묶입니다.

## 2. 로봇에 풀기 (로봇의 터미널)
USB 를 꽂고, 압축 파일이 있는 경로에 맞게 두 번째 줄을 고쳐서 실행합니다.
이전 판이 있으면 먼저 지웁니다.
```bash
cd ~
rm -rf ~/robot_console
python3 -m zipfile -e /media/C052-0E64/rdk_280/robot_console.zip ~/
cd ~/robot_console
```
(`unzip` 이 없어도 되도록 파이썬으로 풉니다.)

## 3. 실행 전 확인
- 팔 주변 30cm 안에 물건과 손이 없게 합니다.
- `robot_check.py` 나 공식 앱, ROS 2 예제처럼 로봇 포트를 쓰는 프로그램은 끕니다.
- 전원을 켠 직후 팔은 접힌 "쉬는 자세" 입니다. 처음 실행하면 **먼저 기본 자세(관찰 자세)로
  천천히 펴진 뒤** 프로그램을 시작합니다.
- 키트 카메라(USB)는 서버를 켜기 전에 꽂아 둡니다.

## 4. 서버 켜기
```bash
python3 server.py
```
다음처럼 나오면 켜진 것입니다.
```
로봇팔 실습 콘솔 서버가 켜졌어요.
  브라우저 주소: http://192.168.0.252:8080/console
  끄기: Ctrl+C  (로봇도 함께 멈춰요)
  로봇 화면의 브라우저는 느려요. 같은 공유기에 붙은 PC 에서 위 주소를 여세요.
10:02:11 로봇 각도 읽기 OK: 4.0 134.5 -57.8 -129.5 104.4 -1.8
```
- **"로봇 각도 읽기 OK"** 가 나오면 로봇과 연결된 것입니다. 못 읽었다고 나오면 전원·케이블과
  다른 로봇 프로그램이 켜져 있지 않은지 확인합니다.
- 화면에서 누르는 명령은 이 터미널에 한 줄씩 기록됩니다 (`[실행 1] 동작 17개 시작`, `send_angles … → 응답` 등).
  로봇이 안 움직이면 이 기록을 보내 주세요.
- 포트 8080 을 이미 쓰고 있다고 나오면 `python3 server.py --port 8081`
- 카메라: 기본은 자동으로 찾습니다. 못 찾으면 `python3 server.py --camera 0` 처럼 번호를 정하고,
  카메라 없이 쓰려면 `--camera none`
- 로봇 없이 화면만 보려면 `python3 server.py --demo` (가짜 팔)

## 4-1. 전원만 켜면 서버가 저절로 켜지게 (한 번만, 권장)
수업 때마다 로봇 터미널에서 `python3 server.py` 를 켤 필요가 없게 합니다. 2절까지 한 뒤 **한 번만**:
```bash
cd ~/robot_console
sudo python3 autostart.py
```
- 이제 서버가 바로 켜지고, **다음부터는 로봇 전원만 켜면** 약 10~20초 뒤 저절로 켜집니다.
- 상태 보기 `python3 autostart.py --status`, 기록 보기 `journalctl -u robot-console -f`
- 새 `robot_console.zip` 을 같은 자리(`~/robot_console`)에 풀었다면 `sudo systemctl restart robot-console`
- 카메라 번호 같은 옵션도 그대로 줄 수 있습니다: `sudo python3 autostart.py --camera 0`
- 되돌리기(직접 켜는 방식으로): `sudo python3 autostart.py --off`
- 자동 시작 중에 `python3 server.py` 를 또 켜면 "포트를 이미 쓰고 있다" 고 나옵니다. 둘 중 하나만 씁니다.

## 4-2. 교실 Wi-Fi 에 로봇 붙이기 (선생님, 로봇마다 한 번)
**USB 키트를 쓰면 이 절은 필요 없습니다** — [`usb-kit.md`](../setup/usb-kit.md): `wifi.txt` 에 이름·비밀번호를 적어 꽂기만.

랜선 대신 Wi-Fi 로 수업할 때입니다. **교실 전용 공유기** 한 대를 두는 것을 권장합니다 (학교망은 기기끼리 막혀 있는 경우가 많아요).

**공유기 준비 (한 번)**
- 이름(SSID) 예: `EDUINO-LAB`, 비밀번호 8자 이상, **2.4GHz 켜기** (로봇 Wi-Fi 가 2.4GHz 만 잡는 경우가 있어요).
- "AP 격리 / 게스트 격리" 는 **끄기** (켜져 있으면 PC 가 로봇을 못 찾아요).
- 가능하면 로봇마다 **고정 IP(DHCP 예약)**: 192.168.0.101 ~ 130 처럼 주면 로봇 ID(101~130)가 늘 같아서 스티커를 붙여 두기 좋아요.

**로봇을 교실 Wi-Fi 로 옮기기 — 화면에서**
1. PC 를 로봇 핫스팟(`ElephantRobotics_AP…`)에 연결하고 `http://10.42.0.1:8080/console` 을 엽니다 (로봇 ID 는 1).
2. 오른쪽 위 **[로봇 … 연결됨]** → **[로봇 Wi-Fi]** 탭.
3. **Wi-Fi 이름**(예: `EDUINO-LAB`)과 **비밀번호**를 넣고 **[이 Wi-Fi 로 옮기기]**.
   목록에 있으면 눌러서 이름을 채워도 되지만, **목록에 없어도 됩니다** — 로봇이 핫스팟으로 켜져 있는 동안에는
   주변 Wi-Fi 가 보이지 않는 게 정상이고, 이름과 비밀번호만으로 연결합니다 (대소문자·띄어쓰기까지 똑같이).
4. 몇 초 뒤 화면이 끊기면 정상입니다. PC 도 `EDUINO-LAB` 에 연결하고 **[로봇 찾기]** 로 로봇을 다시 찾습니다.
   새 네트워크에서는 **로봇 ID 가 바뀝니다** (주소 끝 숫자).
- 이제 로봇은 켜질 때마다 교실 Wi-Fi 에 먼저 붙고, 교실 Wi-Fi 가 없는 곳에서는 핫스팟으로 돌아갑니다.
- 비밀번호가 틀리는 등 실패하면 로봇은 **원래 연결로 스스로 돌아옵니다** (약 1분 안). PC 도 원래 Wi-Fi 로 돌아와 다시 합니다.
- 다시 핫스팟으로: 같은 탭의 **[핫스팟으로 돌아가기]**.

**myCobot 280 RDK X5 (제조사 핫스팟 `ElephantRobotics_RDKX5_AP_…`) 는 이 방법으로 합니다 — 로봇마다 한 번**
이 로봇의 핫스팟은 제조사 스크립트(`/usr/local/bin/hotspot-function/hotspot_on.sh`)가 로그인 때 켜서,
끄고 켜는 데 관리자 권한이 필요합니다. 로봇 터미널(모니터·키보드, 또는 랜선으로 SSH)에서:
```bash
cd ~/robot_console
sudo python3 wifi.py EDUINO-LAB 비밀번호
```
- 제조사 핫스팟을 끄고(`hotspot_off.sh`) 교실 Wi-Fi 에 연결합니다. 핫스팟으로 SSH 접속 중이면 그 접속은 끊기지만
  연결 작업은 끝까지 진행됩니다 (기록: `/var/log/eduino-wifi.log`). 되도록 **랜선을 꽂은 채로** 하세요.
- 성공하면: 켤 때마다 교실 Wi-Fi 를 먼저 기다리고(약 45초), **없으면 제조사 핫스팟을 켭니다**
  (`eduino-wifi.service`). 로그인 때 핫스팟을 켜던 자동 실행 파일은 지우지 않고 이름만 바꿔 둡니다.
- 실패하면(비밀번호·이름 틀림): 이유를 알려 주고 제조사 핫스팟을 다시 켭니다. 아무것도 남기지 않습니다.
- 제조사 방식으로 완전히 되돌리기: `sudo python3 wifi.py --hotspot`

**로봇 터미널에서 (화면에 "권한이 없어요" 가 나올 때, 또는 모니터를 붙여 설정할 때)**
```bash
cd ~/robot_console
sudo python3 wifi.py                      # 지금 연결과 주변 Wi-Fi 목록
sudo python3 wifi.py EDUINO-LAB 비밀번호   # 교실 Wi-Fi 로 옮기기
sudo python3 wifi.py --hotspot            # 로봇 핫스팟으로 돌아가기
```
자동 시작(4-1)으로 켜진 서버는 일반 사용자 권한이라, 로봇 OS 설정에 따라 화면에서 Wi-Fi 를 바꾸지 못할 수 있습니다.
그때는 위 명령으로 한 번 옮겨 두면 됩니다.

## 5. PC 에서 접속 — [로봇 찾기] / [로봇 연결]
**로봇 ID** 는 로봇 주소(IP)의 마지막 숫자입니다. 서버가 켜지면 터미널에 `★ 로봇 ID: 252` 처럼 나옵니다.
여러 대를 쓰는 교실에서는 로봇마다 ID 스티커를 붙여 두면 학생이 자기 로봇을 바로 찾습니다.

1. PC 를 로봇과 **같은 Wi-Fi**(예: `EDUINO-LAB`)에 연결하고, 에듀이노 로봇팔 실습 앱(또는 사이트)을 엽니다.
   처음이면 모델을 고른 뒤 **로봇 연결** 창이 뜹니다. (언제든 오른쪽 위 파란 **[로봇 연결]** 버튼)
2. **[로봇 찾기]** 탭에서 **[로봇 찾기]** 를 누르면 같은 Wi-Fi 의 로봇이 몇 초 안에 목록으로 나옵니다
   (ID · 모델 · 상태). 앞부분(`192.168.0.`)은 교실 공유기에 맞게 한 번만 고치면 기억합니다. 로봇 핫스팟이면 `10.42.0.`.
3. 내 로봇인지 모르겠으면 **[움직여 확인]** — 그 로봇의 몸통이 5° 돌았다가 돌아옵니다. 맞으면 **[연결]**.
   - 웹 사이트(https)에서 찾으면 크롬이 처음 한 번 **"로컬 네트워크의 기기에 접근"** 을 물어봅니다 → **허용**.
4. ID 를 알면 **[ID 로 연결]** 탭에서 ID(예: `252`)를 넣고 **[연결]** 해도 됩니다. 전체 주소(`192.168.0.252`)나
   이름(`robot.local`)도 되고, 최근에 연결한 로봇은 목록에서 누릅니다.
5. 그 로봇의 콘솔이 열리고, 오른쪽 위에 **"로봇 252 연결됨"**, 창 제목에 **"로봇 252"** 가 나옵니다.
   다른 로봇으로 바꿀 때도 그 버튼을 누릅니다. 로봇 없이 연습하려면 [시뮬레이션만].
- 로봇이 안 보이면: PC 와 로봇이 같은 Wi-Fi 인지, 주소 앞부분이 PC 주소(`ipconfig`)와 같은지, 로봇을 켜고 1분 기다렸는지 확인합니다.

직접 주소로 열어도 됩니다: 같은 공유기에 붙은 PC 의 브라우저(크롬·엣지·웨일)에서 `http://로봇IP:8080/console`.
- 오른쪽 위에 **"로봇 ○ 연결됨"**, 오른쪽 패널 [직접 제어] 의 조그 목록에 J1~J6 각도가 보이면 성공입니다.
  "로봇 연결 끊김" 이면 서버 터미널을 확인합니다.
- [직접 제어] 탭 맨 아래 **로봇 상태** 를 펼쳐 **[연결 확인]** 을 누르면 로봇 몸통(1번 관절)이 10° 돌았다가 빠르게 돌아옵니다 (약 5초).
  실제 로봇이 움직이면 연결이 확실한 것입니다.
- 로봇 핫스팟에 붙었다면 주소는 `http://10.42.0.1:8080/console`
- **처음 한 번 — 주소로 들어가기**: USB 설치가 끝나면 로봇 터미널 맨 아래에 **`주소: http://192.168.x.x:8080/console`** 과 로봇 ID 가
  크게 나옵니다 (USB 의 `result-….txt` 에도 `PC 브라우저:` 줄로 적힘). PC 크롬에서 그 주소를 엽니다.
  그 PC 에서 처음 열면 3D 위에 **"다음부터 주소 없이 열기 — PC 프로그램 받기"** 카드가 한 번 뜹니다 → **[PC 프로그램 받기]**.
- **PC 프로그램 (Physical AI Tool)** — 주소를 외우지 않고 더블클릭으로 로봇 열기:
  콘솔 윗줄 **[··· 설정] → [PC 프로그램 받기]** 를 누르면 `Physical AI Tool.html` 파일 하나가 받아집니다
  (USB 키트의 `eduino` 폴더에도 같은 파일이 있습니다 — 그 파일을 바탕화면에 복사해도 됩니다. USB 의 파일에는
  그 USB 로 Wi-Fi 를 맞춘 로봇들이 저절로 적혀 있어, 복사해 열면 **내 로봇** 에 바로 나옵니다. 주소를 몰라도 됩니다).
  바탕화면에 옮겨 두고 **더블클릭**하면 브라우저에 **Physical AI Tool** 이 열려
  - **내 로봇**: 받은 로봇과 전에 연 로봇이 **"연결 가능 / 응답 없음"** 과 함께 나오고, **[열기]** 한 번이면 그 로봇 콘솔이 열립니다.
  - **로봇 찾기**: 같은 Wi-Fi 의 로봇을 모두 찾아 줍니다 (ID · 모델). **[움직여 확인]** 으로 내 로봇인지 보고 [열기].
  - **로봇 ID 로 열기**: USB 결과 파일의 로봇 ID(예: 107)만 넣고 [열기].
  설치가 필요 없고, 로봇의 주소가 바뀌어도(다른 교실) [로봇 찾기] 로 다시 찾습니다. 교실 PC 마다 한 번 받아 둡니다.
  - 크롬이 받을 때 "안전하지 않은 다운로드" 라고 물으면 **[유지]** 를 누릅니다 (로봇이 https 가 아닌 http 로 보내기 때문).
    묻는 것이 번거로우면 USB 키트의 파일을 바탕화면에 복사해 씁니다.
  - 처음 열 때 크롬이 "로컬 네트워크의 기기에 접근" 을 물으면 **허용** 을 누릅니다.
- 서버 터미널에 `이름으로: http://<로봇이름>.local:8080/console` 이 나오면 IP 대신 그 이름으로도 열립니다.
- **처음 쓰는 로봇이거나 화면과 실제 팔의 자세가 다르면 먼저 9절(영점 맞추기)을 합니다.**
- **연결이 끊기면**: 3D 화면 위에 빨간 테두리 안내가 뜹니다.
  - "로봇 서버와 연결이 끊겼어요" — 로봇 전원, 같은 공유기(와이파이), 로봇의 서버가 켜져 있는지 확인합니다.
    화면은 스스로 계속 다시 시도하고, 서버가 돌아오면 안내가 저절로 사라집니다. **[다시 연결]** 로 바로 확인할 수도 있습니다.
  - "로봇 팔이 대답하지 않아요" — 서버는 켜져 있지만 팔과 통신이 안 되는 경우입니다 (팔 전원을 껐다 켰거나 케이블 문제).
    전원·케이블을 확인하고 **[다시 연결]** 을 누르면 서버가 로봇 포트를 새로 엽니다 (`/api/reconnect`).

## 6. 화면 구성과 실습 고르기
윗줄 왼쪽 **[교육 | 시뮬레이터]** 탭으로 두 화면을 오갑니다. 이 절은 **[시뮬레이터]** 화면 설명이고,
**[교육]**(로봇공학 · 피지컬 AI 주제 23개, 자료실 PDF)은 [`robotics-course.md`](../course/robotics-course.md) 에 있습니다.

PC 화면은 **3D 화면(왼쪽, 넓게)** 과 **작업 패널(오른쪽, 한 개)** 두 부분입니다. 조작과 코딩을 모두 오른쪽 패널 하나에서 하고,
패널 맨 위 **탭 4개**로 바꿉니다. 처음 화면은 **[직접 제어]** 입니다.

| 영역 | 위치 | 하는 일 |
| --- | --- | --- |
| **윗줄** | 위 (늘 보임) | 로고·**Physical AI 학습 프로그램** · **[교육 \| 시뮬레이터]** · **[모델]**(노트북 화면에서는 [··· 설정] 안) · **지금 과제**(누르면 과제 고르기 창, 목표 진행 막대, 검수 시연이면 번호 1~7) · **[AI 키트 ▾]** 작업대 · **[··· 설정]** · 연결 상태 · **[■ 정지]** |
| **3D 화면** | 왼쪽 | 로봇·작업대. 왼쪽 위 도구 끝 위치, 오른쪽 위 시점 버튼·[표시 ▾]·[고화질]·[카메라], 왼쪽 아래 카메라, 맨 아래 한 줄 기록 |
| **작업 패널** | 오른쪽 | 탭 **[직접 제어] [블록 코딩] [Python] [ROS 2]** |

- **[직접 제어]**(기본): 위에서부터 **움직이기(조그) → 도구 → 자세 → 로봇 상태**(한 줄로 접혀 있음, 누르면 연결 확인·손으로 움직이기·영점 맞추기).
- **[블록 코딩] 초급 · [Python] 중급 · [ROS 2] 고급**: 위에 **과제 카드**(제목·할 일, 그 과제의 버튼, [예제 코드 처음으로]),
  가운데 **편집기**, 맨 아래 **실행 막대**.
- **탭마다 자기 프로그램을 기억합니다.** 블록 코딩 ↔ Python 을 오가도 고친 프로그램이 지워지지 않고, 묻는 창도 뜨지 않습니다.
  코딩하다가 [직접 제어] 로 가서 로봇을 움직이고 돌아와도 그대로입니다.
- **실행 막대**(코딩 탭 맨 아래, 아이콘 한 줄): **[▶ 시뮬레이션]**(Ctrl+Enter) · **[▷▷] 빠르기 버튼** 하나 — 한 번 누르면 세모 하나가
  채워지고 2배, 두 번이면 세모 둘 · 4배, 세 번이면 다시 보통 속도 (실제 로봇은 늘 제 속도) · **[로봇 모양 ▶ 로봇 실행]**(시뮬레이션 통과 후 열림. 로봇 없이 열었으면 [코드 받기]) · **[■]** 정지.
  통과한 단계에는 ✓ 가 붙고, 잠긴 버튼에는 이유("시뮬레이션 통과 후" / "로봇 연결 필요")가 적혀 있습니다.
- **[■ 정지]** 는 윗줄에 늘 있고, **Esc**(실행 중이면 스페이스도)로도 멈춥니다. 패널을 접어도, 어느 탭이어도 같습니다.
- **과제 고르기**: 윗줄의 지금 과제를 누르면 **과제 카드 창**이 열립니다.
  - 카드마다 그 과제를 나타내는 **큰 아이콘**(관절 돌리기·과녁·손·카메라·눈·AI 칩·코드 …)이 주제 색 띠 위에 있습니다.
  - 위쪽 **[실습] / [검수 시연]** 으로 바꿉니다. 실습은 주제별(기본 조작 · 집기·옮기기 · 카메라·비전 · 도구 활용 · API·ROS 2 · 자유 실습),
    검수 시연은 제안서 **검수 7종** 카드입니다. 카드의 동그라미는 연한 초록 = 시뮬레이션 완료, 진한 초록 = 실제 로봇 완료.
  - **언어**(블록 코딩·Python·ROS 2)와 **작업대**(AI 키트·로봇팔 단독)를 골라 보고, 카드를 누르면 그 과제가 **그 언어 탭에서** 열립니다.
  - 검수 시연 중에는 윗줄에 번호 **1~7** 이 있어 한 번에 다음 검수로 갑니다. 지금 언어에 없는 검수(예: 검수 3 은 블록 코딩만)는 그 언어로 열립니다.
  - 목표 진행은 윗줄에 늘 보입니다 (직접 제어로 하는 과제 — 전 축 구동 등 — 도 채워집니다).
- **작업대 [AI 키트 ▾]**: AI 키트 ↔ 로봇팔 단독(매트) 바꾸기, **블록 섞기**, **처음 상태로**. 블록을 집지 못하는 도구(도구 없음·펜 등)면
  블록을 치워 두므로 [블록 섞기]가 꺼지고 이유가 나옵니다.
- **[··· 설정]**: **PC 프로그램 받기**(5절), (웹 사이트에서) 이 PC 에 앱으로 설치, 로봇 연결 · 로봇 Wi-Fi, **패널 위치 왼쪽/오른쪽**
  (왼손잡이나 교실 모니터에 맞게. 이 PC 에 기억).
- **패널 접기**: 탭 줄 오른쪽 **[›]** 로 접으면 3D 가 창 전체가 되고, 가장자리에 탭 버튼 세로 줄만 남습니다. 그 줄의 탭을 누르면
  그 탭으로 다시 펼쳐집니다. [표시 ▾] → [실행할 때 패널 접기] 를 켜 두면 실행하는 동안만 저절로 접힙니다.
- 창이 좁으면(가로 1100px 미만) 3D 아래에 패널이 오는 한 줄 화면이 됩니다.
- **처음 화면 — 모델 고르기**: 에듀이노 로고가 나온 뒤 로봇 모델을 고릅니다. 지금은 **myCobot 280 RDK X5**
  를 쓸 수 있고, 280 Pi · 280 Arduino · myAGV · 다른 로봇팔은 "다음 순서 / 준비 중" 으로 보입니다.
  한 번 고르면 기억하고, 윗줄 **[모델]** 로 바꿉니다. 로봇 주소로 열면 그 로봇의 모델로 바로 시작합니다.
- **3D 화면**: 처음 열 때와 창 크기가 바뀔 때 **로봇과 작업 공간이 패널에 가리지 않는 곳에 꽉 차게** 저절로 맞춥니다.
  오른쪽 위 [맞춤 · 위 · 앞 · 옆] 도 그 방향에서 꽉 차게 맞춥니다. **[표시 ▾]** 에서 체크로 켜고 끕니다:
  **베이스 좌표축**(X 빨강 앞 · Y 초록 왼쪽 · Z 파랑 위), **도구 좌표축**(도구 끝), **관절 선택 점**, **관절 회전축**(J1~J6 주황 화살표),

  (키트 · 손 · 실제, 원본 · 처리, 사진 찍기, 실제 블록 위치 가져오기), [×] 로 접습니다.

### 편집기 쓰기
- **다른 예제**: 윗줄 과제를 눌러 과제 카드 창에서 고릅니다 (같은 언어의 다른 실습이 그 탭에 열립니다).
- **초급 블록**:
  - 왼쪽 꾸러미의 블록을 **누르면 추가**됩니다. 오른쪽에서 블록을 하나 눌러 고르면(파란 테두리), 새 블록은
    **고른 블록 바로 다음에** 들어갑니다. 끌어다 놓아도 됩니다.
  - 블록에 마우스를 올리거나 고르면 위에 **[↑] [↓] [⧉ 복사] [× 지우기]** 가 나옵니다.
  - 흰 숫자(각도·초·횟수)를 누르면 작은 창이 열립니다: 막대로 끌기, −10·−1·+1·+10, 직접 입력,
    관절 각도는 **[지금 로봇 ○°]** 로 로봇의 지금 각도를 그대로 넣기. 범위를 넘는 값은 들어가지 않습니다.
  - [6개 관절 한번에] 블록의 **[지금 자세]** 는 조그로 맞춘 로봇 자세를 한 번에 넣습니다 (드래그 티칭).
  - **동작 시간**: [**2초 동안** 1번 관절을 30°로] 블록은 정한 시간에 맞춰 천천히/빠르게 움직입니다
    (0.3~20초. 너무 짧아 속도 제한을 넘으면 가장 빠른 속도로 하고 알려 줍니다). 코드로는 `robot.move_joint(1, 30, time=2)`.
  - **멈추기**: [⏸ **1초 동안 멈추기**] 블록으로 동작 사이에 쉬는 시간을 넣습니다 (0~10초).
- **중급·고급 코드**: 파일 탭(my_robot.py / my_node.py, 바꾼 곳이 있으면 점 표시), 줄 번호, 색 입힌 코드,
  실행 중인 줄(초록)·오류 줄(빨강) 표시, 아래 상태 줄. **Ctrl+Enter** 로 바로 시뮬레이션합니다.

- **실행 구조 — 업로드 없음**: 파이썬·ROS 코드는 **PC 브라우저 안에서** 실행되고, 로봇 서버에는 "몇 초에 어떤
  자세로" 같은 **동작 명령만** 보내집니다. 로봇에서는 `server.py` 하나만 켜 두면 되고, 예제를 바꿀 때마다 로봇에서
  따로 실행하거나 파일을 옮길 필요가 없습니다. 편집기의 코드 → 실행 막대 **[▶ 시뮬레이션] → [로봇 실행]** 이 전부입니다.
  (로봇 터미널에서 `python3` 로 직접 돌려 보는 [로봇용 파일로 받기] 는 검수 7 확인용 선택 사항입니다.)

### 중급 · 파이썬

(키트: 분류함 A / 단독: 자리 4), 엔드이펙터 교체(검수 5, 그리퍼 → 펌프), API 로 로봇에서 실행(검수 7), 자유 실습.
- 파이썬은 **PC 브라우저 안에서** 돌아갑니다 (처음 한 번 약 13MB 를 로봇에서 받아 옴, 인터넷 불필요).
- `time.sleep` 은 시뮬레이션 시간만 흐르게 하므로 결과가 바로 나오고, 3D 화면이 실제 속도로 재생합니다.
- 편집기 아래 **출력** 칸에 `print` 한 내용이 시각과 함께 나옵니다.
- 오류는 **몇 번째 줄인지** 와 쉬운 설명으로 나옵니다 (범위를 벗어난 각도는 pymycobot 과 같은 오류 문장).
- 통과한 코드는 **로봇에서 그대로 돌아가는 코드**입니다. [로봇에서 실행] 은 그 명령들을 같은 시각에 로봇으로 보내고,
  [로봇용 파일로 받기] 로 받아 로봇 터미널에서 `python3 my_robot.py` 로 실행해도 됩니다.

### 고급 · ROS 2
실습: 토픽으로 팔 움직이기, 타이머로 반복 동작, ROS 2 노드 로봇에서 실행(검수 7), 자유 실습.
- 편집기 아래에 **노드와 토픽 그래프**(`ros2 node list` 처럼), 토픽 메시지(`ros2 topic echo` 처럼), 로그가 나옵니다.
- 시뮬레이터에는 공식 드라이버 노드 `control_slider` 가 켜져 있어, `/joint_states` 로 보낸 각도대로 팔이 움직입니다.
- 로봇에서 진짜 ROS 2 로 실행: [ROS 2 로 실행하는 법] — 터미널 1 `ros2 run mycobot_280_rdkx5 slider_control`,
  터미널 2 `python3 my_node.py`.

**중급·고급 [로봇에서 실행] 은 지금 자세에서 시작합니다** (로봇에서 파이썬을 직접 실행할 때와 같게).
시뮬레이션도 실제 로봇의 지금 자세에서 시작하므로, 시뮬레이션한 뒤 팔을 움직였다면 한 번 더 시뮬레이션합니다.

2. **검수 1 · 전 축 구동**: 윗줄 과제 → [검수 시연] → 1 → [▶ 시뮬레이션] → 통과하면 [로봇 실행]

## 8. 제어 패널 — 상태와 조그 (티칭 펜던트 방식)
오른쪽 패널의 **[직접 제어]** 탭은 자주 쓰는 순서로 **움직이기(조그) → 도구 → 자세 → 로봇 상태** 입니다
(영점 맞추기 중에는 영점 칸이 맨 위. 작업대는 윗줄 [AI 키트 ▾] 에 있습니다).
- **로봇 상태**: 처음에는 한 줄로 접혀 **"서보 켜짐 · 대기"** 처럼 요약만 보입니다. 누르면 표시등 4개(모드, 서보, 동작, 오류)와
  **[연결 확인] [손으로 움직이기 / 서보 고정] [영점 맞추기]**, 마지막 영점 기록이 나옵니다.
  관절 각도는 조그 목록에, 도구 끝 위치(mm)는 3D 왼쪽 위에 있어 따로 표를 두지 않습니다.
  로봇에 연결되어 있으면 실제 로봇에서 0.1초마다 읽은 값입니다.
- **조그(JOG)**:
  - **관절 / 좌표**: 관절(J1~J6) 하나씩 돌리기, 또는 도구 끝을 로봇 베이스 기준 X(앞뒤)·Y(좌우)·Z(위아래)로 옮기기
    (도구는 지금 향한 방향 그대로 곧게 움직입니다. 기본 자세처럼 도구가 비스듬해도 됩니다).
  - **이동 단위**: 관절 0.5·1·5·10°, 직교 1·5·10·20mm. **속도**: 10~100%.
  - **◀ ▶ 키를 짧게 누르면 한 칸**(이동 단위만큼), **누르고 있으면 그동안 계속 부드럽게** 움직이고, 손을 떼는 순간 멈춥니다.
    속도 막대로 빠르기를 정합니다. 시작할 때 0.25초 동안 부드럽게 빨라집니다.
  - 실제 로봇의 **관절** 조그는 로봇 자체의 **연속 조그**(`jog_angle`)로 움직여 끊김 없이 부드럽습니다. 화면은 누르고 있는 동안
    0.2초마다 "계속" 신호를 보내고, 신호가 0.8초 끊기거나 손을 떼면 로봇이 멈춥니다. 관절 한계 3° 앞에서도 스스로 멈춥니다.
    화면은 움직이는 방향으로 8° 앞을 미리 충돌 검사해 닿기 전에 멈춥니다. **좌표**(X·Y·Z) 조그도 로봇 자체의 연속 조그
    (`jog_coord`)로 움직이고, 화면이 25mm 앞을 미리 검사합니다. 누르는 동안 속도 막대를 바꾸면 바로 반영됩니다.
    관절 막대 끌기만 조금 앞의 목표를 계속 보내는 방식입니다.
  - **슬라이드 조그(좌표)**: X·Y·Z 값 아래 보라색 손잡이를 좌우로 끌면, 끄는 만큼 빠르게 그 방향으로 움직입니다.
    손을 떼면 손잡이가 가운데로 돌아오고 팔이 멈춥니다. 실제 로봇에서도 같은 방식(로봇 자체 연속 조그, 속도만 바뀜)입니다.
  - 버튼은 누르면 눌려 들어가는 입체 버튼이고, 관절 막대와 속도 막대는 둥근 손잡이로 끕니다.
  - 관절 막대: 가운데 검은 눈금이 0°, 양 끝 숫자가 그 관절의 한계입니다. 한계 10° 안이면 값이 주황색이 됩니다.
    막대를 끌면 실제 로봇도 끄는 대로 따라옵니다.
  - **관절 고르기 (산업용 펜던트와 같은 이름)**: 베이스(J1) · 숄더(J2) · 엘보(J3) · 손목 1(J4) · 손목 2(J5) · 손목 3(J6).
    각 줄 왼쪽의 작은 그림에서 그 관절이 움직이는 부분만 파란색입니다. 고른 관절 한 줄만 펼쳐져
    **↺ ↻ 버튼**(도는 방향 그대로, 짧게 한 칸·누르고 있으면 계속)과 막대가 나오고, 나머지 줄은 각도만 보여 줍니다.
  - **3D 에서 고르고 돌리기**: 관절을 조절할 때만(조그 패널에 마우스를 올리거나 누를 때, 점·링 위에 있을 때,
    그 뒤 5초 동안) 3D 로봇의 관절마다 번호 점 **①~⑥** 이 나타납니다. 시뮬레이션을 볼 때는 가리지 않도록 숨어 있습니다. 점을 누르면 그 관절이 골라지고,
    고른 관절 둘레에 **각도 눈금 링**이 뜹니다. 링을 잡고 **빙 돌려 끌면** 그 방향으로 관절이 돕니다
    (화면에서 도는 방향 = 관절이 도는 방향. 축이 옆으로 누워 보이는 관절은 링을 **좌우로** 끌어요). 놓으면 그 각도로 갑니다.
    손목 3개(④⑤⑥)는 가까이 붙어 있어 3D 오른쪽 위 **[옆]** 보기에서 가장 잘 보입니다. 점을 끄려면 [표시] → [관절 선택 점].
  - 실제 로봇에서 링이나 막대를 끌면 로봇이 **교실 최고 속도(50)로 바로 따라옵니다** (끄는 곳보다 최대 12° 뒤에서 따라오고,
    놓으면 0.2~0.5초 안에 도착). 버튼·키보드 조그는 속도 막대의 속도를 씁니다.
  - **키보드**: 조그 패널을 한 번 누른 뒤 **↑ ↓** 관절 고르기, **← →** 돌리기(짧게 한 칸, 누르고 있으면 계속).
- **자세**: **[기본 자세]**(관찰 자세) / **[일자로 펴기]**(모든 관절 0°, 팔이 위로 곧게)로 틀어진 자세를 한 번에 바로잡습니다.
  - **내 자세**: 조그나 손으로 팔을 원하는 자세에 둔 뒤 **[지금 자세 저장하기]** → "내 자세 1, 2 …" 가 목록에 생깁니다.
    **[이 자세로]** 를 누르면 그 자세로 돌아가고(실제 로봇도, 충돌 검사 후), **[지우기]** 로 지웁니다.
  - 저장한 자세는 **이 PC 에 남아** 다음 수업에도 있습니다. 초급 블록 [자세로 가기] 에서도 같은 이름으로 쓰고,
    중급·고급은 마우스를 올리면 나오는 각도를 `send_angles([...])` 에 씁니다. (드래그 티칭 실습에 씁니다)
- **도구**: 끼운 도구의 버튼(흡착 켜기·끄기, 그리퍼 열기·닫기 …)과 도구 바꾸기, 카메라 플랜지.
  로봇에 연결되어 있으면 **흡착 켜기·끄기와 그리퍼 열기·닫기는 실제 로봇도 바로 움직입니다**
  (조그로 물건 위에 가서 [열기] → 내려가서 [닫기] → 들어 올리기, 처럼 손으로 집어 옮기기 연습).
  - 먼저 도구 칸의 **[장착할 도구]** 에서 실제로 단 그리퍼(어댑티브·평행·플렉서블)를 고릅니다. 고른 종류대로 명령이 갑니다.
  - **받침대 (G 베이스)**: 로봇을 받침대 위에 올려 고정했다면 도구 칸 아래 **[로봇 아래 → 받침대 (G 베이스)]** 를 켜고
    **받침대 높이**(책상에서 로봇 바닥까지, mm)를 넣습니다. 3D 에 받침대가 그려지고, 시뮬레이터의 책상 높이가 그만큼 내려가
    도구가 로봇 바닥보다 아래(책상 쪽)까지 내려갈 수 있습니다. 켜지 않으면 화면은 책상이 로봇 바닥 높이에 있다고 보고
    "책상에 닿아요" 로 막습니다. 이 설정은 로봇 주소마다(이 PC 의 브라우저에) 기억됩니다.
    - 도구 끝 위치(3D 왼쪽 위·좌표 조그의 z)는 pymycobot `get_coords` 처럼 **로봇 바닥 기준**이라, 받침대 위에서 책상에
      닿는 높이는 z 가 마이너스(예: 50mm 받침대면 약 −50)입니다. 파이썬 예제의 좌표도 받침대 높이만큼 낮춰 써야 같은 곳에 닿습니다.
  - **흡착 펌프가 안 될 때**: 로봇이 펌프 핀을 못 쓰면 [흡착 켜기] 아래에 빨간 안내와 이유가 나옵니다.
    배선은 펌프 상자 → 로봇 베이스 40핀(보드 인쇄 번호): **5V → 5V(2·4번), GND → GND(6번), G5 → 37번, G2 → 31번**,
    펌프 상자 전원선도 꽂습니다. (공식 RDK X5 비전 키트와 같은 핀·순서)
    점검: 로봇 터미널에서 서버를 잠깐 끄고 점검 파일을 일반 사용자로, 안 되면 관리자로 실행합니다.
    ```bash
    sudo systemctl stop robot-console
    python3 /media/*/eduino/checks/pump_check.py        # 1) 일반 사용자로
    sudo python3 /media/*/eduino/checks/pump_check.py   # 2) 1 이 '권한' 오류이면
    sudo systemctl start robot-console
    ```
    켜기 3초 동안 모터 소리가 나면 소프트웨어는 정상이고, 안 나면 배선을 봅니다. **2) 에서만 소리가 나면** 핀을 쓰는 데
    관리자 권한이 필요한 것이라, 콘솔 서버를 관리자 권한으로 켜야 합니다 (결정이 필요한 부분 — 담당자에게 문의).
  - 프로그램이 로봇에서 실행되는 중에는 따로 열고 닫을 수 없습니다.
  - **그리퍼가 '지지직' 하지 않게**: 그리퍼는 위치로 움직이는 모터라, [닫기] 후 블록이나 반대쪽 손가락에 막히면
    계속 밀면서 소리가 나고 모터가 뜨거워집니다. 서버는 손가락이 멈추면(약 1초) **멈춘 자리보다 조금(5) 더 조인 자리에서
    버티게** 바꿔, 블록은 잡은 채 모터가 계속 밀지 않게 합니다 (프로그램 속 열기·닫기도 같음. 터미널에
    `[그리퍼] 닫힘: 멈춘 자리 31 → 26 …` 이 나옴). 블록이 미끄러지면 더 세게: `python3 server.py --grip-squeeze 10`,
    예전처럼 계속 밀게 하려면 `--grip-squeeze -1`.
  도구는 모양 그림으로 보이고, 아무 도구도 달지 않았으면 맨 앞의 **[도구 없음]** 을 고릅니다
  (끝 플랜지만. 도구 명령이 든 프로그램은 알려 줍니다).
- **작업대**(윗줄 **[AI 키트 ▾]**): 블록 섞기, 처음 상태로, AI 키트 ↔ 매트. 블록을 집지 못하는 도구(도구 없음·펜 등)일 때는 블록을 치워 두므로 [블록 섞기]가 꺼지고 이유가 나옵니다.
- 모든 이동은 먼저 시뮬레이터로 책상·키트·블록에 닿는지 검사하고, 닿으면 움직이지 않고 알려 줍니다.
- **손으로**(로봇 상태 칸): 서보가 풀리면 팔이 떨어질 수 있습니다. **반드시 한 손으로 팔을 받친 뒤** 누릅니다.
  원하는 자세에서 **[지금 자세 기록]**, 끝나면 **[서보 고정]**.
- **3D 화면 확대·축소**: 마우스 휠(가리키는 곳으로 확대), 오른쪽 위 **[+][−]**, 키보드 **+ / −**,
  **[맞춤]** 은 로봇과 작업 공간이 꽉 차게.

## 9. 영점 맞추기 — 화면과 실제 팔의 자세가 다를 때
영점은 관절마다 "여기가 0°" 라는 기준입니다. 틀어지면 같은 명령에도 실제 팔이 시뮬레이션과 다른 자세로 가고,
"목표 자세에 도착하지 않았어요" 오류가 날 수 있습니다 (오류 문구에 **어느 관절이 몇 도 차이 나는지** 나옵니다).
상태 칸의 **[영점]** 을 누르면 제어 패널이 영점 도구로 바뀝니다. 방법은 두 가지입니다.

**① 차례로 맞추기 (일자 자세) — 교육 · 처음 설치에 쓰는 한 가지 방법**
1. **도구(그리퍼 등)를 빼고** 팔 주변(약 30 cm)을 비운 뒤 [도구를 빼고 주변을 비웠어요] 에 표시합니다.
2. **[0° 자세로 보내기]** — 로봇이 표시선이 거의 맞는 자리(위로 곧게)까지 알아서 갑니다.
3. **J1 → J6 한 관절씩**: 표시선이 맞으면 **[맞아요, 다음]**. 어긋났으면 팔을 한 손으로 받치고
   **[J○ 풀기]** → 그 관절만 손으로 돌려 두 표시선을 일직선으로 → **[고정하고 다음]**.
   나머지 관절은 고정돼 있어 팔이 쓰러지지 않고, 한 사람이 한 손으로 할 수 있습니다. 3D 에 지금 관절이 파란 고리로 나옵니다.
4. 여섯 관절이 끝나면 표시창의 값이 "틀어진 만큼" 입니다. **[6축 모두 0° 로 저장]**
   (20° 넘게 차이 나는 관절이 있으면 경고가 나옵니다).
5. 확인: **[기본 자세로]** 갔다가 **[0° 자세로]** 돌아와 표시선 6쌍이 다시 맞으면 끝입니다.

영점은 서보 자체에 저장됩니다(공식 방법). 기본 자세나 다른 각도를 기준으로 프로그램이 따로 보정값을 들고 있지 않으므로,
다른 프로그램(공식 myBlockly · pymycobot)으로 써도 같은 0° 입니다.

**② 한 관절 다듬기 — 나중에 한 관절만 조금 다를 때**
1. **[0° 자세로 보내기]** — 3D 화면도 팔 전체가 보이는 시점으로 바뀝니다.
2. 표시선이 어긋난 관절(J1~J6)을 고르면 3D 에 그 관절이 **파란 고리**로 표시됩니다.
3. **[−2°] [−0.5°] [+0.5°] [+2°]** 로 로봇이 그 관절을 조금씩 돌립니다. 두 표시선이 딱 맞으면
   **[J○ 여기를 0° 로 저장]**. 손으로 맞추는 것보다 정밀하고, 팔을 받칠 필요가 없습니다.
4. 많이 틀어져 있으면 [J○ 만 풀어 손으로 돌리기] 로 크게 맞춘 뒤 저장합니다.

- 저장은 공식 명령(`set_servo_calibration`)으로, 관절을 잠깐 풀었다가 저장하고 다시 고정합니다.
- 상태 칸 아래에 **마지막으로 영점을 맞춘 날짜와 관절**이 나옵니다 (로봇의 `~/.robot_console_calibration.json`,
  새 zip 을 풀어도 남음). 표시선을 맞추지 않고 저장하면 그 관절의 모든 동작이 틀어지니 주의합니다.
- 영점은 **관절의 기준**이고, 로봇을 책상 어디에 놓았는지와는 상관없습니다. AI 키트는 로봇이 받침판의 정해진
  자리에 고정되고 카메라는 마커로 위치를 맞추므로 영점만 맞으면 됩니다.

## 10. 실제 카메라
카메라 칸의 **[실제 카메라]** 를 누르면 로봇에 꽂힌 카메라 영상과 영상 처리 결과가 나옵니다.
카메라가 2대(키트 카메라 + 손 카메라)면 **[실제 1] [실제 2]** 로 나오고, 옆의 **[키트 | 손]** 으로 그 카메라가 무엇인지
정합니다 (처음에는 1 = 키트, 2 = 손. 한 번 정하면 이 PC 가 기억합니다).
- **[실제 블록 위치 가져오기]**: 실제 카메라가 찾은 블록 위치로 시뮬레이터의 블록을 옮깁니다.
  이 배치로 시뮬레이션을 통과시킨 뒤 [로봇에서 실행] 하면 실제 블록을 집으러 갑니다.
  - **키트 카메라**: 브라우저가 마커 2개로 보정해 계산합니다. 마커 id 1·2 가 모두 보여야 좌표가 나옵니다. 블록을 마커에 붙여 놓지 마세요.
  - **손 카메라**: 로봇이 직접 계산합니다 — 공식 RDK X5 비전 키트의 카메라 보정값과 그 순간 로봇이 알려 주는 팔 자세로.
    먼저 색 따라가기 줄의 **[카메라 자세]** 로 책상을 내려다보게 하고, **팔이 멈춘 상태에서** 누릅니다.
    받침대(G 베이스) 높이를 넣어 두었다면 그 높이도 반영됩니다.
- 실제 카메라 영상은 받는 대로 바로 다음 장을 요청해(최대 초당 12장 정도) 로봇 움직임을 따라갑니다. 색 인식(처리 화면)은
  초당 2번 합니다. 로봇 쪽은 카메라 버퍼를 1장으로 줄이고 640×480 MJPG 로 받아 지연을 줄였습니다.
  그래도 늦으면 Wi-Fi 신호(공유기와의 거리)를 확인하세요 — 영상 한 장이 약 30~60KB 입니다.

### 10-1. 색 따라가기 (손 카메라)
카메라 플랜지(손 카메라)를 달았을 때, 고른 색의 물체를 **손 카메라 화면 가운데에 두도록 팔이 따라 움직이는** 기능입니다.
시뮬레이션에서는 3D 손 카메라로, 로봇에 연결되어 있으면 실제 카메라로 똑같이 동작합니다.
1. [직접 제어] → 도구 칸에서 **카메라 플랜지**를 켭니다(실제로 단 것과 같게).
2. 도구 칸의 **[색 따라가기]** 를 누르면 카메라 창이 열리고, 위쪽에 **색 따라가기** 줄이 나옵니다.
3. **[카메라 자세]** 를 눌러 손 카메라가 로봇 앞 책상을 내려다보게 합니다 (공식 RDK X5 비전 키트의 촬영 자세).
4. 빨강·초록·파랑·노랑 중 하나를 고르고, 그 색 물체를 화면 안에 둔 뒤 **[▶ 따라가기]**.
   - 처음 몇 초는 **방향 맞추기**: 팔이 앞뒤·좌우로 2cm 씩 움직였다 돌아오며, 화면에서 물체가 어느 쪽으로 움직이는지 잽니다.
     이때는 **물체를 움직이지 마세요.** (카메라를 어느 방향으로 끼웠든 이 단계가 맞춰 줍니다)
   - 그다음부터는 물체를 천천히 옮기면 팔이 따라와 화면 가운데(노란 원)에 맞춥니다. 높이와 도구 방향은 그대로입니다.
5. **[■ 멈추기]**, 위쪽 **[정지]**, 또는 **Esc** 로 멈춥니다.
- 매 걸음은 조그와 같은 충돌 검사를 거치고, 팔이 닿지 않는 쪽으로는 가지 않습니다 (화면에 이유가 나옵니다).
- "카메라 화면이 팔의 움직임을 따라 움직이지 않아요" 가 나오면: 카메라가 물체가 아니라 허공이나 도구를 보고 있거나,
  방향 맞추는 동안 물체가 움직인 것입니다. [카메라 자세] 후 물체를 가만히 두고 다시 시작하세요.
- 색 인식은 키트 색 인식과 같은 공식 HSV 범위를 씁니다. 배경에 같은 색이 많으면 가장 큰 덩어리를 따라갑니다.

### 10-2. 검수 시연 준비 — 준비 점검 · AI 샘플 · 결과표
- **[··· 설정] → [검수 준비 점검]**: 로봇이 검수 1~7 에 필요한 것을 한 번에 확인합니다 — 팔 연결, 좌표 기준(화면 = 로봇),
  손 카메라 기준, 카메라 대수(2대 필요), OpenCV·ArUco, AI 모델, 흡착 펌프, 그리퍼, ROS 2. ✗ 가 있으면 시연 전에 해결합니다.
  - "손 카메라 기준" 이 ✗ 이면 3D 손 카메라 화면만 실물과 어긋납니다. 실제 블록 위치(로봇 계산)는 영향이 없습니다. 그 값을 알려 주세요.
- **검수 6 (AI 샘플 로컬 실행)**: 로봇에 연결된 상태에서 검수 6 을 열면 **[AI 샘플 실행 (로봇에서 · YOLO)]** 버튼이 나옵니다.
  로봇 안(CPU)에서 YOLOv5s 물체 인식(공식 RDK X5 비전 키트의 yolo_demo 와 같은 방식)을 돌려, 찾은 물체 이름·확률·처리 시간과
  표시한 사진을 보여 줍니다. 컵·병·휴대폰·사람처럼 흔한 물체를 카메라 앞에 두고 합니다. 처음 한 번은 모델을 읽느라 조금 더 걸립니다.
  카메라 창이 열려 있으면 그 카메라로, 아니면 키트 카메라로 합니다.
- **검수 3 (영상 취득)**: 카메라 창에서 실제 키트 카메라와 실제 손 카메라로 각각 **[사진 찍기]** 를 하면 2/2 가 됩니다.
- **[··· 설정] → [검수 결과표 저장]**: 검수별로 언제 무엇을 했는지(로봇/시뮬레이션), 잰 값(반복 정밀도 mm, AI 처리 시간,
  블록 위치 등)과 준비 점검 결과를 한 장의 HTML 로 저장합니다. 브라우저로 열어 인쇄하면 PDF 로 남길 수 있습니다.
  기록은 이 PC 의 브라우저에 쌓이고, 준비 점검 창의 **[검수 기록 새로 시작]** 으로 비웁니다.

## 11. 지금 막아 둔 것 (안전)
서버와 화면이 둘 다 검사합니다.
- **흡착 펌프**: 공식 비전 키트와 같은 핀(BOARD 31·37, Hobot.GPIO)으로 켜고 끕니다. 로봇에서 GPIO 를 쓸 수 없으면
  (서버 터미널에 이유가 나옴) 펌프 동작은 빼고 움직임만 실행할지 묻습니다. 펜·실린더는 팔 동작이라 그대로 실행됩니다.
- 중급·고급 프로그램에서 서보를 푸는 명령(`release_all_servos`)은 팔이 떨어지므로 로봇으로 보내지 않습니다.
- 속도는 최대 50, 모든 관절 각도는 로봇 한계 안, 한 번에 한 프로그램만.
- 목표 자세에 제시간에 도착하지 못하면(막힘 등) 멈추고 알려 줍니다.
